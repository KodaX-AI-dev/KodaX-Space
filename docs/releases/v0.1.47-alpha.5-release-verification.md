## Superseded first candidate

Candidate `64610a9a` was tagged first and never published: its [source E2E](https://github.com/KodaX-AI-dev/KodaX-Space/actions/runs/42567041467), [source build](https://github.com/KodaX-AI-dev/KodaX-Space/actions/runs/42567041486) and [release](https://github.com/KodaX-AI-dev/KodaX-Space/actions/runs/42567123153) failed, the release qualifier refused it, and no GitHub Release was created before the tag moved to the corrected source. Its failures were attributed rather than rerun to green:

- `workflow-slash.spec.ts` (both cases, Linux and Windows): since `c4ad8913` the durable Space receipt is the single owner of a slash-command echo and renders as a local notice. The specs still expected a user query bubble. They now assert one local-notice receipt and no user-query copy of the command (`b1d95226`).
- `userBubble.test.tsx` (all four platforms, failing since `d5b7c0e7` landed): the label assertion expected Chinese copy while `I18nProvider` follows the host system languages, so it passed only on zh-CN machines. The test now pins `navigator.languages` (`d9535955`).
- `artifact-export.test.ts` (Linux): a real product defect. `resolveInsideProject` stripped the leading `/` of a POSIX absolute path and rerooted it under the project, so workspace file artifacts registered with absolute paths could not be previewed or saved on Linux and macOS; Windows drive-letter paths were unaffected. Absolute paths inside the project now resolve in place (including root aliases such as macOS `/var` → `/private/var`) with unchanged containment checks, plus cross-platform contract tests (`0bce0574`).
- Runner network failures, not code: Electron binary download 504 (Windows E2E and smoke), Feishu CLI archive download failure (Mac ARM installer) and DNS `ENOTFOUND github.com` / `nodejs.org` (Mac Intel smoke). The asset that failed to download was reachable again afterwards.

Earlier, the work-mode specs had failed on main since `38ead1fa`: composer-created drafts now stay on the welcome dashboard until the first send, so reading the draft from the conversation stream timed out. The specs read the single draft through the real Main `session.list` channel instead and keep the draft-reuse assertion (`a484c8ce`); that correction was already part of `64610a9a`.
