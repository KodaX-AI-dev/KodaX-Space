# F149 — 左侧栏置顶区、稳定排序与先归档后删除 测试指南

设计：[F149](../features/v0.1.47.md#feature_149-sidebar-pinned-area-stable-ordering-and-archive-first-lifecycle)。

## 前置条件

- 用测试数据目录（设置 → 常规 → 数据位置，或 `KODAX_HOME=<临时目录>`），不要在真实数据上做删除场景。
- 至少准备三个项目（A、B、C），每个项目两三个任务；其中一个任务是 fork 出来的。
- 项目顺序与置顶项目保存在 `~/.kodax/space/projects.json`（`order`、`pinned`）；任务的置顶 / 归档标记保存在 `~/.kodax/space/session-flags.json`。
- 升级场景需要一份 beta.3 留下的 `projects.json`（有 `order` 或没有都可）。

## 人工场景

### A. 项目主列表

1. 打开一个新项目 D：D 出现在主列表最上面。
2. 依次点开 A、B、C 的任务并发送消息：项目顺序不变。
3. 把 C 拖到最上面，重启 Space：顺序保持。
4. 升级：用 beta.3 的 `projects.json` 启动，首次显示的顺序与 beta.3 中一致。

### B. 项目内任务

1. 在同一项目里让两个任务同时运行并持续输出：两行位置不变，运行中的排在项目最前，后启动的在上。
2. 运行结束后，任务按最近活动时间归位。
3. fork 出的任务与其他任务平铺，没有缩进；重启后一样；“+N more” 弹窗中的顺序与侧栏一致。

### C. 置顶区

1. 悬停任务行，点置顶按钮：任务移到左侧栏顶部置顶区，并从所属项目中消失；当前任务不切换。
2. 再置顶另一个任务：它排在置顶区最上面。取消置顶：任务回到项目中按时间应在的位置。
3. 右键项目 → 置顶项目：项目连同任务列表出现在置顶任务下方，从主列表消失。再置顶第二个项目：它排在置顶项目最上面。
4. 在置顶区内拖动置顶项目：只改变置顶区顺序，主列表不变。
5. 右键置顶项目 → 取消置顶项目：项目回到主列表原来的位置。
6. 重启 Space：置顶任务、置顶项目及其顺序都保持。
7. 置顶一个很旧的任务（在项目中需要“+N more”才能看到），重启后它仍出现在置顶区；点击它会切换到所属项目并打开该任务。
8. 切换到 Partner：置顶区只显示 Partner 的置顶任务；置顶项目两边都显示。

### D. 先归档、再删除

1. 右键未归档任务：有“归档”，没有“删除”；面包屑会话菜单同样。悬停按钮的归档同样生效。
2. 打开“显示已归档会话”，右键已归档任务：只有“取消归档”与“删除”。删除后该任务的标记一并清除。
3. 右键未归档项目：有“归档项目”，没有“移除”。归档后它进入底部“已归档”分组。
4. 在“已归档”分组中右键：只有“取消归档”与“移除”。取消归档后项目回到主列表原位置。
5. 归档一个置顶中的任务或项目：它离开置顶区；取消归档后不会自动恢复置顶。
6. 重启 Space：归档状态保持。

## 失败处理

- 断开 Host 或让写入失败（例如把 `session-flags.json` 设为只读）后点置顶 / 归档：界面回滚到原状态，并提示保存失败。
