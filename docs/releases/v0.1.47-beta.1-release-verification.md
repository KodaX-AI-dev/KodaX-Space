## Pre-tag repair history

Two intermediate SHAs were pushed to main while converging and were superseded by `45b5f9ce` before tagging; their failures were attributed and fixed rather than rerun to green:

- `31f40c38` (release prep): the ci Windows shard 2 failure was `shared-host-history-recovery.spec.ts` "shared default Host protects active work then self-heals" failing its body at the 35-second first render. A local instrumented run on Windows showed the published alpha.6 daemon keeps `active_runs`/`connected_clients` busy flags for roughly 110–120 s after the protected Run settles (ubuntu clears within seconds), while the spec waited out a single retry slot. The first recovery render now waits up to 180 s (`5fe25965`); the variant passes locally in ~3.5 min and first-try in CI. The same commit fixed three stale tests found before pushing: the `project.list` schema test now asserts the required F148 `order` array, the ActivitySpinner locale assertion pins zh-CN, and the shared Host fixture closes the Space client before `daemon stop` with a typed retry for the beta.9 `connected_clients` refusal (KodaX Issue 410).
- `5fe25965`: the build macOS failures were `ComposerEditor.test.ts` using `ControlOrMeta+End`, which macOS Chromium does not bind (native key is Cmd+Down) — now darwin-conditional — and `conversationHistoryNavigation.browser.test.ts` failing the loaded Intel runner's frame-paced scroll settle at the 3.5 s page default. That F144 scroll test then exceeded a 12 s budget on `macos-15-intel` at `5fe25965`; both bottom checks now carry a 45 s ceiling (`45b5f9ce`), under which the Intel smoke build and the whole build workflow pass.
