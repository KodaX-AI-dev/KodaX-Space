# 办公专家调研与复用（2026-09-08）

本轮以 WorkBuddy 本机官方目录缓存、豆包工作实际伙伴目录和原作者源码为依据，比较“能做什么”和“怎样交付”，不把市场里的每个名称都转成 Space 新卡片。前八个专家已覆盖通用产品、项目、研究、数据、营销、邮件和会议；本轮增加四个独立办公场景，全部复用现成方法。

## 证据与范围

- WorkBuddy：`~/.workbuddy/app/cache/experts/manifest.json`，缓存更新时间 **2026-09-03**，2026-09-08读取。该缓存混有公开、外部及内部可见项，本报告不将 `internal_only` 条目列为可用市场能力。缓存总量不是办公专家数量，也不代表今日线上完整目录。结构与角色包方式参考[官方专家文档](https://open.workbuddy.cn/docs/expert)。本地检索摘录见审计目录 `workbuddy-office-catalog.json`。
- 豆包工作：2026-09-08 原生应用的“工作伙伴·小队”全部列表与“办公提效”分类；实际页面嵌入 `aily.doubao.com/doubao/market/buddies`。以下伙伴名称来自界面。办公提效分类有七项：PPT 制作专家、工作台搭建师、Office 效率全能王、会议准备与复盘专家、效率流程改造师、群聊摘要与待办助手、一图总结大师；部分办公角色位于其他分类。目录介绍不能证明本机真实业务执行已经验收。本轮没有取得可迁移的豆包伙伴完整源码与许可。
- 复用源：[Anthropic knowledge-work-plugins](https://github.com/anthropics/knowledge-work-plugins)，直接读取官方 Git 仓库源码和各作用域 LICENSE。锁定 `1f517b9de47e827c80cd933ed364e16838072239`，不是依赖会变化的 main。未执行下载仓库里的脚本。

## 伙伴不只是目录上的一句介绍

豆包“效率流程改造师”详情（[实际详情页](https://aily.doubao.com/doubao/market/buddies/3455b12c-07dc-46bc-8295-806ccf17a62e)）显示六个内置技能：流程图绘制、doubao-data-analysis、轻量化任务管理、任务管理专家、多步任务执行规划、飞书画板大师。它覆盖数据诊断、任务执行和可视化，不是只写SOP。Space 本轮只承诺已接入和验证的SOP整理范围，不能将六个名称视为已经复制了六种能力。新增专家继续遵循用户选择的 WorkBuddy 式持续会话配置，而不复刻独立伙伴/小队。

## 为什么只新增四个

工作汇报对“本期/上期、开发/验收、预算/进展”有明确判断标准；客户支持在情绪、处理状态、服务承诺和内外沟通分离上不同于普通邮件润色；知识综合处理多源证据和冲突；SOP 处理步骤、责任和条件分支。这四种方法都能使用现有文件/会话资料完成任务，有可测的输入和交付，不依赖新增 CRM、自动群聊索引或独立小队。

原有八个专家维持原定义，新建四个独立 ID，均使用同一个 Partner Agent 的持续会话绑定。目录扩展后为 **十二个专家：五个岗位、七个任务**。

## Space 适配重点

1. 删除失效的 `../../CONNECTORS.md` 引用，移除对未安装 risk-assessment 的强制依赖；平台资料类别不代表工具授权。
2. 取消“连接后自动发布、创建任务、扫描全部讨论”的暗示；资料读取与写入沿用会话范围和宿主实际操作。QQ/网易邮箱仍只读，不自动发送。
3. SOP 保留金额比较边界与缺失资料退回路径，未知审批时限不补造；优化方案与现行制度分开。
4. 客户回复模板中的“已升级/确认/退款/记录”等不能作为事实。没有日期、授权或处理结果时不擅自承诺，内部备注与客户正文分开。
5. 知识综合保留审批/生效状态；最新聊天建议不能覆盖现行制度；转发不能变成独立佐证，缺失URL不伪造。
6. 周报分清开发、验收与上线；没有基期不算趋势，预算消耗不代表工作完成。按用户篇幅裁剪，不强制完整模板。
7. knowledge-synthesis 上游 `user-invocable: false` 是其插件内策略，本轮移除以适配 Space 可选择/挂载的方法；`$ARGUMENTS` 使用普通任务描述占位，避免改变注入正文。

## 后续创建方法

先确认场景与现有专家差异，再找已随包方法、竞品原始来源或可信公开仓库。逐项核对许可、固定版本、支持文件、工具依赖、事实约束和交付格式，然后做实际 SDK 与真实任务验证。没有适用来源时，才按 space-expert-builder 和 skill-creator 建立范围明确的自有方法。本轮四项均有适用开源方法，**没有从零重写 Skill**。
