成品回归额外复现了 Partner blocked queue 重载遗漏：失败前“取回”已可见，重载后消失；同一输入在 Main live snapshot、独立 SDK view.queue 和 runs.getInput 中都仍为 queued / execution_binding_rejected，Provider 只收到 HOLD_QUEUE。证据为 `final-e2e.json/log`、trace 内的两份 queue-reload 附件及提取后的 `queue-layer-summary.json`。这证明此例属于 Renderer 恢复遗漏，不归因于 SDK。根因是 App 的首次恢复、激活和定时协调仍跳过 Partner，而且 activity 只认 Run、不认尚未准入的 product input。修复复用现有 coordinator：选中的 Partner 在历史允许后补一次首次 live snapshot；已有 idle live 不重复轮询，queued/delivering input 计入活动，继续沿用后台数量上限与 generation fencing。Coder idle 首读门禁及 Partner canonical history 策略不变，不自动重提已拒绝输入。两项纯函数 RED 后 23/23 GREEN；该模块行/分支/函数覆盖率 91.76% / 80.30% / 83.72%。新成品回归见下文。

新增 [Repo-intelligence Host 交接段落](kodax-beta1-repointel-host-handoff.md)。之前验收的 SDK 外部问题和平台限制继续有效，见 [完整验收边界](kodax-beta1-full-acceptance.md)。本轮不会把 Windows 本地 Provider 测试表述成 Linux/真实账号/模型质量验证。

随后成品又验证出 `/work-mode agent` 的显示遗漏：Host 已成功改为 Agent，命令输出正确，但 idle observation 退役后选择器保持 Coding。Main 在同一 Host 的 SDK CAS 成功并读回后，使用现有 `session.liveInvalidated` 发出明确的 `settings_changed` 原因，Renderer 沿原有协调器读取 Host 快照；失败和版本冲突不通知、不重试，不在命令写入中打开历史观察。公共入口 RED/GREEN 覆盖成功唯一通知、冲突保持原模式和无额外观察；同时清除退役观察的 Main 旧 live 缓存，保留独立 revision 水位，并通过再次公开读取验证 Agent。新 reason 属于 Space IPC，不修改 SDK 契约。文件回滚专项还修正了夹具对瞬态 ENOENT 的立即失败：仅将文件暂缺返回为 poll 的 null，其他 I/O 错误继续抛出，最终完整内容仍严格相等；修正后文件审批/回滚和队列恢复各连续 3 次成品通过。中间 `shipped-e2e` 的 26 通过/2 失败和后续新包结果分别保留。
