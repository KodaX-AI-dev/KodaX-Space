## Composer tokens — 2026-11-06

F031/F035/F147 source refinement, authorized from the [completion research and visual/interaction proposal](../research/composer-completion-comparison-2026-11-06.md). Lexical hosts a plain-text composer with typed command/skill/file nodes; completion catalogs, SDK execution and the session send payload remain existing contracts. Labels and full identities are local presentation metadata. Simple paths and commands retain their exact wire text; special paths use the existing file-link representation. ## FEATURE_144: Windowed Continuous Transcript Virtualization

> Status: Completed (2026-11-11; phase 1 complete 2026-11-10, phase 2 tickets 3–8 complete 2026-11-11) → `v0.1.47`, two phases (rescheduled 2026-11-09 from `post-v0.2.x`)

**排期（2026-11-09）**：第一段 = 票 1–2，立即开工，不引入窗口化。第二段 = 票 3–8，同在 v0.1.47 内完成，开工须同时满足：(a) 票 1 决策门结论为“DOM/布局为主”；(b) 历史滚动/翻页基础可验证地稳定（2026-11-10 起替代原“一个 alpha 周期内无新回归”的观察期，后者无法在开发期执行）：b1 票 1 基线发现的 Issue 242/243 已修复并有回归测试；b2 历史相关 E2E 与浏览器测试全绿；b3 重跑 10k/30k 基线，首次较早页无 stale 失败、后接锚点漂移 ≤2 px。第二段在 env gate 后推进，gate 关闭时与现状一致；v0.1.47 正式版须完成票 8（默认开启并移除整列挂载路径），否则第二段整体不随正式版发布。

**决策门（票 1 结束）**：按[历史浏览设计](../design/session-history-browsing-and-actions.md)的规模优化依据，开销拆到 IPC、解析、挂载、布局。DOM/布局为主 → 进入第二段；IPC/正文解析为主 → 先收窄预取或解析成本，第二段顺延并在本节记录理由。

### 1. 需求概述

After a user repeatedly loads older pages, tens of thousands of canonical messages must remain reachable through one continuous transcript without keeping every row mounted. The visible result must behave like the current natural scroll surface rather than page switching: older content grows upward, the live tail remains at the bottom, and the user's current reading position does not jump. Windowing must be visually invisible: no blank gaps, no scrollbar-thumb jitter, no reset of what the user expanded, and no replayed entry animation.

### 2. 影响范围

- `ConversationStreamV2` render rows shared by Coder (SDK `productItems`, accumulated saved collection, `around` locate window) and Partner (same SDK `productItems` path on the runtime host — the history backend ignores surface; the legacy `items` path remains only for the legacy/embedded host); viewport anchoring and long-Session cache eviction.
- Row-local UI state that resets on unmount: long-question collapse (`CollapsibleUserMessageContent`), tool-card manual expand (`ToolCallCard`), `ToolDiffView` expand/editor mount, "show all edits", error-notice details, and restored-tail entry animation (`RESTORED_REVEAL_TAIL_ITEMS`).
- Loaded-content Ctrl+F (`usePageFindMatches` walks mounted DOM rows), query rail, jump-to-bottom, keyboard/touch/wheel/held-scrollbar navigation, focus, selection/copy, and screen-reader reading order.
- Fork/rewind actions on SDK turn targets whose rows may be unmounted.
- Live view source, queued inputs, observation recovery, `resync_required`/`data_changed`, and the explicit bottom action that selects the live source.
- History-loading diagnostics marks and packaged Windows/macOS/Linux acceptance corpora.

The feature does not change KodaX transcript storage, canonical ordering, cursor semantics, raw audit retention, or Space's strong-identity-only reconciliation policy.

### 3. 技术方案

**现状基线（beta.4，2026-11-09）**：保存历史与推进中的 view 是两个来源；Coder 保存来源在同一 revision/sourceRevision 内按 SDK item ID 去重累积，较早页前插、较新页后接，两端只保留未读游标；`around` 打开独立定位窗口并可返回原集合；边缘翻页只响应用户手势方向；锚点以 DOM 行 + top 偏移捕获；屏外行由 `content-visibility: auto` 跳过绘制，但 DOM 与 React 树全量保留。

**结构**

- Window over CSV2 render rows (after turn/receipt grouping), so Coder and Partner share one mechanism. The live view source stays outside the window.
- Edge-true window: when the window reaches either end of the loaded collection, the spacer on that side is zero, so the DOM edge equals the collection edge. The existing gesture-intent edge paging and prepend anchor restore then work unchanged; the paging code stabilized during the last alpha cycle is not rewritten.
- One owner of scroll corrections: the existing anchor restoration, generalized to SDK item ID + intra-row offset. The virtualizer must not apply its own scrollTop adjustments; the ticket 4 library choice follows this constraint, and a small in-house window is acceptable.
- Row-local disclosure state lives in a session-scoped store keyed by row identity, so unmount/remount and Session switches keep what the user expanded and keep heights stable.

**视觉与交互保真**

- Overscan by pixel distance (about one viewport on each side, more in the scroll direction), not by row count, so fast wheel scrolling and held-scrollbar drags do not expose gaps.
- Unmeasured space renders as quiet, theme-aware placeholder blocks that follow the transcript rhythm (no shimmer); a bare blank area is never shown.
- Height estimates come from per-row-kind running averages of real measurements. Corrections above the viewport compensate scrollTop, and corrections are deferred while the native scrollbar is held so the thumb does not jitter under the pointer. Images reserve their aspect ratio when dimensions are known.
- Pinned rows never unmount: rows holding the active selection, keyboard focus, an open menu/popover, inline editing, or streaming output.
- Entry animation plays once per row identity; remounts never replay it.
- Query rail markers use logical offsets and update throttled, so markers do not drift while estimates converge.
- Ctrl+F searches the loaded row model (including loaded-but-collapsed bodies; unfilled bodies are never fetched for search), counts across the whole loaded collection, and on jump expands and materializes the target before highlighting.
- Rows expose `aria-setsize`/`aria-posinset` inside a feed so assistive tech reads the full length.

**上线**

- One temporary env var gate (`KODAX_SPACE_TRANSCRIPT_WINDOWING`) during tickets 4–7; ticket 8 made windowing the default and deleted the gate and the full-mount path. Per-row `content-visibility` was also removed in ticket 8: windowing needs real heights of the mounted rows, and the gate-on path had already overridden it to `visible`. No lasting setting is added.

### 4. 接口契约

- KodaX remains authoritative for newest/older/newer saved pages, `around` locate pages, opaque item IDs, revision/sourceRevision fences, `data_changed`/`resync_required`, conversation status/issues, and fork/rewind turn targets. No SDK change is required.
- Space owns the accumulated saved collection, render-row projection, row UI state, measurements, mounted window, overscan, anchor restoration, navigation, and diagnostics. The advancing SDK view remains a separately selected source; virtualization must not combine its body with saved history.
- Every row is addressed by SDK item identity (legacy-host rows: their existing strong row identity) scoped to its source/revision; historyBoundary is an action anchor, not row identity. Timestamp, equal content, visual position, or page-local index must never be used to reconcile records.
- A Session switch, collection replacement, revision change, resync, or user-owned navigation invalidates stale measurement/restoration work before it can move the viewport.
- Search, query navigation, fork, and rewind resolve against the full loaded collection (or an SDK `around` page when the target is unread), never merely the mounted DOM.

### 6. 验收标准

- Loading at least 10,000 mixed-height conversation rows keeps mounted `conversation-render-row` nodes at or below 500; the bound is independent of accumulated history length in either direction.
- Repeated older- and newer-page loads preserve one continuous scrollbar and the active row within 2 px after dynamic layout settles; there is no page swap or forced return to the newest page.
- Fast wheel scrolling, held-scrollbar dragging, jumping to newest, returning from an `around` locate window, and returning to an earlier reading position never show a blank area, duplicate row, reordered row, stale-page flash, replayed entry animation, or a scrollbar thumb that jitters under the pointer.
- Expand/collapse state of user questions, tools, diffs, and error details survives scrolling away and back, and Session switches.
- Expanding/collapsing, delayed Markdown/image/font layout, viewport resize, and live streaming preserve the intended anchor and remain immediately cancelable by real user input.
- Text selection and copy, keyboard focus, open menus, and screen-reader reading order survive window movement.
- Loaded-content Ctrl+F, search, and query navigation locate targets outside the mounted window, requesting SDK pages only for unread targets. Fork and rewind use the exact SDK turn target even when its row was initially unmounted.
- Active and queued Runs retain spinner, Stop, interactions, live tail, and observation recovery semantics while historical DOM remains bounded; Partner behaves identically.
- Packaged Windows, macOS, and Linux acceptance records DOM bound, heap trend, first paint, page-prepend latency, anchor drift, and long-scroll frame responsiveness; regressions fail the feature gate rather than silently falling back to full mounting.

## FEATURE_148: Settings-Based Data Location

状态：Completed（2026-11-13，当前源码，未发布）。决策见 [ADR-011](../ADR/ADR-011-settings-data-root.md)，验收见 [测试指南](../test-guides/FEATURE_148_v0.1.47_TEST_GUIDE.md)。

### 1. 需求概述

用户要在 Space 设置里更换数据位置（会话、设置、凭据），而不是改环境变量。旧实现有两个变量（`KODAX_HOME` 与 `KODAX_PROFILE_DIR`），两者不一致时 Space 与 SDK 会落到不同目录。目标：单一 `KODAX_HOME`；设置项优先；保存后经已验证的 Host 停止重启；可选把当前数据复制到新位置，且从不修改旧位置。

### 2. 影响范围

- Main：`electron/kodax/data-root*.ts`（解析、指针、校验、启动提示、切换）、`electron/ipc/data-root.ts`、`electron/window/data-root-progress-window.ts`、`main.ts`（首个 import 为 bootstrap；退出路径复用更新安装的 Host 停止）。
- IPC：`dataRoot.get` / `dataRoot.choose` / `dataRoot.apply`（`packages/space-ipc-schema/src/channels/data-root.ts`）。
- Renderer：设置 → 常规 → 数据位置；中英文案。
- SDK：`copyKodaXDataRoot` 与 `KODAX_DATA_ROOT_COPY_MARKER`（`@kodax-ai/kodax/runtime`，Registry beta.9 起发布）。

### 3. 技术方案

- 优先级：测试模式 > 设置指针 `<appData>/KodaX Space/data-root.json` > `KODAX_HOME` > `~/.kodax`。`KODAX_PROFILE_DIR` 仅在未设 `KODAX_HOME` 时作为弃用别名生效并记录告警。
- SDK 在 import 时固定 `<KODAX_HOME>/sessions`，所以 `data-root-bootstrap` 必须是 `main.ts` 的第一个 import，并在任何 store 或 SDK 加载前写好 `process.env.KODAX_HOME`。
- 指针位于它描述的根之外；启动时只校验、不创建目录。指针不可用或损坏时，本次退回下一优先级并弹窗（继续 / 恢复默认 / 退出）。
- Space 覆盖 `KODAX_HOME` 时写入 `KODAX_SPACE_HOME_OVERRIDE` 标记，下一个 Space 进程据此还原用户自己的值，避免“恢复默认”后重启仍沿用旧设置位置。
- 候选校验（顺序）：非绝对路径 → 网络路径（UNC，含 `\?\UNC\`）→ 规范化后与当前相同或互相嵌套（win32/darwin 忽略大小写）→ 可写探测 → 去掉系统杂项（`desktop.ini`、`.DS_Store`、`$RECYCLE.BIN` 等）后的内容：存在复制标记 → `incomplete_copy`；有其他非 KodaX 文件 → `unrecognized`；否则可用，并报告是否已有 KodaX 数据。
- 保存并重启：`requestUpdateInstallation(install)` → 已验证 Host 停止 → 复制（可选）→ 写指针 → relaunch → `app.exit(0)`。Host 无法验证停止（其他客户端仍连接、仍有运行中的工作、用户取消）时什么都不改。
- 复制：调用 SDK `copyKodaXDataRoot`，只接受空目标。SDK 先写 `.kodax-copy-incomplete` 标记，完成并复查无存活 Host 后删除标记；失败时只删除本次写入的内容，崩溃遗留的带标记目标被拒绝（`target_incomplete`）而不是清空；Host 锁不可读按 Host 运行处理。`.json`/`.jsonl` 中指向旧根的绝对路径（原生、正斜杠、JSON 转义三种形式）改写到新根。Space 排除 `space/runtime-client-identity.json`（客户端身份按根独立）与 `space/input-intents`（按旧身份索引）。

### 4. 接口契约

- `dataRoot.get` → `{ current, source: test|setting|env|default, defaultRoot, envRoot, pointerRoot, editable }`（beta.9 起复制总是可用，`copySupported` 已删除）。
- `dataRoot.choose` → `cancelled` | `ok { path, hasData }` | `rejected { path, reason, detail? }`；`reason` ∈ `not_absolute, same, nested, network, unusable, unrecognized, has_data, incomplete_copy`。
- `dataRoot.apply { path | null, copyData }`：`null` 表示恢复默认（清除指针）。成功后进程退出，不返回。
- 指针文件：`{ "version": 1, "root": "<abs>" }`。

### 5. 实现步骤

1. 合并变量：`KODAX_HOME` 唯一，`KODAX_PROFILE_DIR` 弃用别名（0d4b2def）。
2. 启动前从设置指针解析数据根，提供启动回退对话框（3f05d389）。
3. 设置界面、校验、保存并重启、Host 停止路径。
4. SDK 原位复制与路径改写；Space 排除项、进度窗口、诊断日志。
5. 文档、ADR、测试指南。

### 6. 验收标准

- 设置中显示当前位置与来源；环境变量与设置冲突时有提示。
- 选择空目录或已有 KodaX 数据目录可保存并重启；新进程的会话、设置、凭据均来自新位置；旧位置文件逐字节不变。
- 非绝对、网络、相同、嵌套、不可写、含其他文件、未完成复制的目录被拒绝并给出原因。
- 其他 KodaX 客户端（如 CLI）连接当前数据时切换被拒绝，什么都不改。
- 复制后，MCPB `installDir`、会话中的工具输出路径等 JSON/JSONL 内的旧根绝对路径指向新根；客户端身份与 input intents 不复制。
- 拔掉移动硬盘后启动，弹出回退对话框，不会在原位置新建空目录。
- 恢复默认后重启，回到 `KODAX_HOME`（若用户设置）或 `~/.kodax`。

### 已知限制

- Linux 上 Partner 连接器密钥位于全局 keyring，Electron `safeStorage` 的密钥也在根之外，两者都不随根移动。沙箱 ACL 可能需要重新设置。
- 未挂载的挂载点会被当作空目录使用；映射网络驱动器（盘符）无法识别为网络路径。
- 复制期间外部进程的写入不保证被包含（Host 已停止，CLI 等客户端已被拒绝）。
- `~/.kodax` 形式、URL 编码的路径以及非 UTF-8 文件不改写；源根为驱动器根时不改写。atomic-file 备份不随复制迁移。
- Space 内置终端继承 Space 生效的 `KODAX_HOME`，在其中运行的 CLI 使用同一位置。

## FEATURE_149: Sidebar Pinned Area, Stable Ordering, and Archive-First Lifecycle

状态：Completed（2026-11-22，当前源码，未发布）。验收见 [测试指南](../test-guides/FEATURE_149_v0.1.47_TEST_GUIDE.md)。需求与决策已与用户对齐（to-spec 2026-11-22）；对照 ZCode、opencode 与 Codex 的左侧栏后修正 beta.1–beta.3 的排序与置顶行为，并推翻 F132 "用删除代替归档" 的决定。

### 1. 需求概述

**Problem Statement**

- 置顶不是一个状态：项目"置顶"只是一次性移到第一位，之后新加的项目会把它挤下去；任务置顶只在所属项目里排前，没有全局入口。
- 项目列表存在一个隐含的"没拖过"状态：不在 `order` 里的项目按 `addedAt` 排在最上面，用户无法从界面理解这条规则。
- 两个任务同时运行时，最近活动时间交替刷新，行会来回换位。
- 左侧栏只能删除任务 / 移除项目，没有归档入口；项目归档的底层能力已存在但界面无入口。更严重的是任务的置顶 / 归档 / 未读标记只存在 renderer 内存里，**重启即丢失**。
- fork 出的任务挂在父任务下，但重启后父子关系丢失，显示前后不一致；而 fork 本身就是一个新任务。

**Solution**

- 项目列表上方新增全局**置顶区**（有自己的“置顶”标题，位于“项目”标题之上，无置顶内容时整段不显示）：上半是单独置顶的任务（最近置顶的在最上），下半是置顶项目（置顶区内可拖排），置顶项目展开后的任务列表与普通项目规则一致。
- 项目主列表是**一个手动顺序**：不自动排序、可拖排，新项目加入时放在最上面。
- 项目内任务：**运行中的在前且位置稳定**，其余按最近活动时间排；fork 平铺。
- **先归档、再删除**：日常菜单只有归档；删除 / 移除只对已归档的任务与项目提供。任务的置顶 / 归档状态由 Space 主进程持久化，重启后保持。

### 2. 影响范围

- Renderer：左侧栏（项目树、置顶区、任务行悬停按钮、项目与任务右键菜单、"+N more" 弹窗）、app store（项目顺序、项目置顶、任务标记的加载与写入）、中英文案。
- Main：项目存储（`~/.kodax/space/projects.json`）增加置顶顺序并维护 `order`；新增任务标记存储（同目录 JSON 文件）；项目与会话 IPC。
- IPC schema：项目置顶、任务标记读取 / 写入、`session.list` 按 sessionId 读取。
- 测试与文档：现有左侧栏浏览器测试、项目存储测试、`project-reorder` e2e、用户手册 / `space_manual` 的左侧栏主题、CHANGELOG。

### 3. 技术方案（Implementation Decisions）

**项目顺序**

- `projects.json` 的 `order` 是主列表唯一的顺序来源，包含所有已知项目（含归档、含置顶）。
- 主进程加入新路径时把它插到 `order` 最前；重复打开已有项目只更新 `lastUsedAt`，不改顺序。
- 移除项目时同时从 `order` 和置顶列表中删除。
- 升级迁移在主进程加载时一次性完成：`order` 中缺少的项目按旧规则（未排过的按 `addedAt` 新→旧）补到最前并写回，用户看到的顺序与升级前一致。renderer 不再有 `addedAt` 补排逻辑。

**项目置顶**

- `projects.json` 增加 `pinned: string[]`（规范化路径），同时表示"是否置顶"与"置顶区内的顺序"。新置顶的项目放在置顶项目的最上面；置顶区内拖排只改 `pinned`。
- 主列表渲染时过滤掉置顶项目，但不改动 `order`；取消置顶即回到 `order` 中的原位置。
- 归档项目时自动从 `pinned` 中移除；取消归档后不恢复置顶。归档项目不能置顶（沿用现状）。
- 删除现有"置顶 = 移到第一位"的行为及其入口逻辑；菜单项改为"置顶 / 取消置顶"。
- 项目两个工作面（Coder / Partner）共用，置顶项目在两个工作面的置顶区都显示。

**任务标记持久化**

- 主进程新增任务标记存储（与 `projects.json` 同目录的 JSON 文件），按 sessionId 记录 `pinnedAt` 与 `archivedAt`（毫秒时间戳；字段缺省即未置顶 / 未归档）。
- renderer 启动时读取全部标记并填入 `sessionFlags`；置顶 / 归档操作先更新界面，再写主进程，写失败时回滚并提示。
- 删除任务时一并删除它的标记。
- 未读标记不在本 feature 内持久化，保持现状。
- 不使用 SDK `archiveSession`：它会把任务移出默认列表，与"归档任务可变暗显示、可打开、需要处理时仍列出"的现有行为冲突。代价是 Space 内归档的任务在 CLI 中仍可见。

**置顶区**

- 只在当前工作面显示属于该工作面的置顶任务，按 `pinnedAt` 新→旧。
- 置顶任务不出现在所属项目的列表里；取消置顶后回到项目列表，按排序规则自然归位。
- 归档任务时自动取消置顶；取消归档后不恢复置顶。
- 置顶区必须显示所有置顶任务，不受每个项目的加载上限（200 条）和项目是否展开的影响：`session.list` 增加按 sessionId 列表读取的过滤条件，用于补齐尚未加载的置顶任务。

**项目内任务排序**

- 平铺，不再按 `parentSessionId` 构建父子树（fork 与其他任务一样）；左侧栏与 "+N more" 弹窗用同一排序。
- 两层比较：运行中（状态为 `running` 或 `awaiting`，即仍处于一轮执行中）在前，按 `createdAt` 新→旧、再按 `sessionId` 打破平局；其余按 `lastActivityAt` 新→旧。
- 超出显示上限时把当前任务与需要处理的任务提上来的规则不变。

**归档与删除入口**

- 任务行悬停显示"置顶 / 取消置顶"与"归档 / 取消归档"按钮；项目行的悬停按钮不变。
- 未归档任务的右键菜单：有归档、无删除；已归档任务：只有取消归档与删除。
- 未归档项目的右键菜单：有归档、无移除；已归档项目（底部 Archived 分组）：只有取消归档与移除。项目归档使用现有 `project.recent.setArchived`。
- 已归档内容统一在底部 Archived 分组查看：归档任务按项目分组，归档项目随后（见第 5 节实现后调整）。不新增归档页面。
- 对话面包屑菜单里的归档 / 删除与右键菜单规则保持一致。

### 4. 接口契约

- `projects.json`：`{ version: 1, projects: [...], order?: string[], pinned?: string[] }`。
- `project.list` 返回 `order`；置顶以每个项目上的 `pinnedIndex`（置顶区位置，缺省 = 未置顶）表达，而不是单独的 `pinned` 数组——这样现有直接使用 `projects` 的调用点无需改动（实现时的调整）。新增 `project.pinned.set { pinned: string[] }`，与现有 `project.order.set` 对称。
- 任务标记文件：`{ version: 1, sessions: { [sessionId]: { pinnedAt?: number, archivedAt?: number } } }`。
- 新增 `session.flags.list → { flags: Record<sessionId, { pinnedAt?, archivedAt? }> }` 与 `session.flags.set { sessionId, pinned?: boolean, archived?: boolean } → { flags }`。主进程负责"归档即取消置顶"。
- `session.list` 增加可选 `sessionIds: string[]` 过滤（最多 1000 个）；给出时忽略 `limit`，在最近 50,000 个任务内查找。
- renderer `sessionFlags[sessionId]`：`{ pinnedAt?, archivedAt?, unread? }`；`pinned` / `archived` 布尔值由时间戳派生。
- 不改 SDK，不新增 SDK 能力门槛。

### 6. 验收标准

**User Stories**

1. 作为用户，我想把任务置顶到左侧栏顶部的置顶区，以便不论它属于哪个项目都能一眼找到。
2. 作为用户，我想让最近置顶的任务排在置顶区最上面，以便刚关注的任务最显眼。
3. 作为用户，我想在取消置顶后让任务回到原项目列表中按时间应在的位置，以便列表保持一致。
4. 作为用户，我想置顶项目，并让它和它的任务列表一起显示在置顶任务下方，以便常用项目固定可见。
5. 作为用户，我想在置顶区内拖动调整置顶项目的顺序，而不影响主列表顺序。
6. 作为用户，我想在取消置顶项目后让它回到主列表中原来的位置，以便我之前排好的顺序不被打乱。
7. 作为用户，我想让新加入的项目出现在主列表最上面，以便马上看到它。
8. 作为用户，我想让项目只按我拖动的顺序排列，打开或使用项目都不改变顺序，以便列表位置可预期。
9. 作为升级用户，我想在升级后首次启动看到和升级前相同的项目顺序。
10. 作为用户，我想让同时运行的任务在流式输出时保持位置不动，以便我能稳定地点中它们。
11. 作为用户，我想让运行结束的任务按最近活动时间归位。
12. 作为用户，我想让 fork 出来的任务和其他任务一样平铺显示，因为它本身就是一个新任务。
13. 作为用户，我想在任务行悬停时直接置顶或归档，以便快速整理。
14. 作为用户，我想从右键菜单归档任务或项目，并且日常菜单里不出现删除，以便不会误删。
15. 作为用户，我想在已归档的任务或项目上取消归档或彻底删除 / 移除，以便"先归档、再删除"。
16. 作为用户，我想让置顶与归档状态在重启后保持。
17. 作为用户，我想在归档一个置顶的任务或项目时让它自动离开置顶区，取消归档后不自动恢复置顶。
18. 作为 Partner 用户，我想只在 Partner 置顶区看到 Partner 的置顶任务，但能看到共用的置顶项目。
19. 作为用户，我想让很久以前置顶的任务即使不在当前加载的任务窗口内，也出现在置顶区。

**Testing Decisions**

- 只测外部行为。两个 seam（已与用户对齐）：
  1. **左侧栏浏览器测试**：在真实浏览器中渲染 `<LeftSidebar>`，用桩 `window.kodaxSpace` 提供 IPC，断言用户可见结果——置顶区内容与顺序、主列表顺序、运行中任务稳定、fork 平铺、悬停按钮、右键菜单的选项集合、拖排结果、发出的 IPC 请求。先例：`sidebarListOrder.browser.test.ts`、`projectDragSort.browser.test.ts`。
  2. **主进程存储单元测试**：项目存储（新项目前插、升级补齐、移除同步清理、置顶列表、归档取消置顶）与任务标记存储（读写、归档取消置顶、删除清理、损坏文件处理）。先例：`electron/test/projects.test.ts`。
- 现有 `tests/e2e/project-reorder.spec.ts` 随新行为更新，不新增 e2e。

**验收清单**

- 置顶任务出现在置顶区顶部，最近置顶的在最上，并从所属项目列表中消失；取消置顶后回到项目列表、位置由排序规则决定。
- 置顶项目显示在置顶任务下方，可在置顶区内拖排；取消置顶后回到主列表原位置；新置顶的项目出现在置顶项目最上面。
- 新加入项目出现在主列表最上方；打开、使用已有项目不改变顺序；拖动后的顺序与置顶状态重启后保持；升级后首次启动顺序与升级前一致。
- 同一项目内两个任务同时运行并持续输出时相对位置不变；运行结束后按最近活动时间归位。
- fork 出的任务没有缩进，与其他任务平铺；重启前后显示一致；"+N more" 弹窗与左侧栏顺序一致。
- 未归档任务 / 项目的菜单有归档、无删除 / 移除；已归档的只有取消归档与删除 / 移除。
- 任务行悬停显示置顶与归档按钮，点击生效且不切换当前任务。
- 置顶、归档状态重启后保持；删除任务后其标记一并清除。
- 归档置顶中的任务或项目会离开置顶区，取消归档后不恢复置顶。
- Coder 与 Partner 置顶区只显示本工作面的置顶任务，置顶项目两边都显示。
- 超出项目显示上限时，当前任务与需要处理的任务仍被提上来；归档但需要处理或正打开的任务仍列出。

### Out of Scope

- 使用 SDK `archiveSession` / `unarchiveSession`，以及与 CLI 共享归档状态。
- 独立的归档管理页面、按时间分组视图、可选的排序 / 分组菜单。
- 项目按最近使用自动排序。
- sub-agent 子任务在左侧栏的显示（保持不显示）。
- 任务在置顶区内的手动拖排。
