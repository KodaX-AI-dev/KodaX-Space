# 模块 · 信息图 / 数据可视化 / 长图

一张或一组以数据或知识为主角、脱离交互也能独立读的图走这里：信息图、数据报告插图、小红书长图、海报式科普。按 SKILL.md 的本次范围、交付格式与方向需求工作，下面的配方按需采用。

## 先定观看距离和容器

- 手机信息流里刷到（小红书、朋友圈）：1080 宽，第一屏（约 1080×1350）必须单独成立——标题、主视觉、一个最强的数字
- 打印或大屏：先定物理尺寸和观看距离，再定字号
- 嵌在文章里：跟随正文宽度，图内文字不小于正文

## 数据是主角，不是装饰

- **只用用户给的或能核实的数字**，示意图要在图上标「示意」。编一个看起来像数据的数字比留空糟糕十倍
- 先问这组数字要说什么关系，再选形式：比例 → 按比例缩放的实物或面积；变化 → 一条曲线或时间轴；路线与空间 → 地图；构成 → 拆开的整体；规模 → 一个超大对象和一个熟悉的参照物
- 一种颜色只代表一个意思，图例写在图上
- 主角素材优先用真图、公共领域的科学插图和地图（`references/materials.md`），而不是图标拼盘

## 做的顺序

1. 依据目标关系和已知方向选择结构；用户需要比较时再按 `references/directions.md` 制作适量代表内容，不固定三个方向。
2. 填全本次内容、校对每个数字和单位，按实际显示尺寸渲染检查。
3. 需要图像时按目标宽度导出整页长图，例如 `npx playwright screenshot --full-page --viewport-size=1080,1350 file:///… out.png`；仅按本次用途裁切。

## 体检

```bash
# $HD = 本 skill 的根目录（SKILL.md 所在目录），不是用户的项目目录
python3 "$HD/scripts/design_lint.py" check info.html --viewport 1080x1350 --min-body 36 --min-label 28
```

图内最小字号按最终显示尺寸算：1080 宽的长图在手机上大约缩到 390pt 宽（约 2.8 倍），所以画布上正文 ≥36px、标签 ≥28px，到手机屏上才有 13–14pt。打印或大屏按实际观看距离另算。
