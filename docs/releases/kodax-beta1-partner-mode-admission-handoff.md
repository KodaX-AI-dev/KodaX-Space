# Partner 工作模式的 Host 原子准入约束

Space 对正式 `@kodax-ai/kodax@0.7.97-beta.1` 补审发现：Partner 正常输入已设置 `workMode:'agent'`，但 Main 在启动前 CAS 设置不能保证实际准入/排队消费时仍为 Agent，另一客户端可以在其间改变 Session 工作模式；command/review/tool/workflow 等静态授权入口同样有窗口。公开 execution profile/source、binding request 和 host services 没有可信的 required/expected workMode 或 Host 已解析的准入模式，resolver 的 view 只读检查也可能命中旧 loading 快照。请在既有可信 Main→Host authorization/profile 契约补声明式模式约束或等价的安全准入上下文，由 Host 在实际 Session 准入锁/执行装配边界核对已解析模式：符合才准备 Skill/hooks、启动模型或工具副作用；不符合则返回稳定结构化拒绝，保留原 Session/inputId、问题、队列与历史，不偷偷改设置或重放。即时输入、after-turn 重绑/消费、command/review/tool、workflow 实际装配和原 Run 恢复须定义一致边界；恢复遵守捕获模式，独立 Actor/specialist 使用自己的授权。新增能力需协商，旧 Host 要求安全升级，不由 Space 写本地配置或创建第二 Runtime 绕过；未声明约束的其他产品保持原行为，不收紧 Partner shell/write/子 Agent。验收用独立 Host 和两个客户端，在 Main 设 Agent 后、真实准入/消费/workflow 装配前插入 Coding/Script 修改，覆盖缺省、忙碌、旧 Host、断连、重绑和冷恢复；结果只能为实际 Agent 配置与模型 system/tool 载荷一致，或在错误模式的模型/方法 hook/副作用发生前拒绝。检查 Run/effectiveConfig、原输入仅执行一次、原文/附件/nativeHistory 不变、无锁重入死锁，Coder 三模式不回归。依据：SDK release `src/client-host-authorization.ts:8-24,41-55,249-261`、`src/sdk-runtime.ts:12578-12615,13154-13207`、`src/session-view.ts:394-400,492-494`；Space `runtime-host-adapter.ts:6455-6563,7664-7742`。这是静态核实的契约缺口，尚非新 SDK 修复或并发回归通过；Space 先修冷身份、入口设置与 UI，正式 SDK 发布后闭环原子保证。
