# Promotion 后的 SDK view 元数据缓存

正式 `@kodax-ai/kodax@0.7.97-beta.1` 的真实独立 Host 可复现：临时 Session 回答后调用 `sessions.promote`，回执及 `sessions.load` 已返回正式 `tag:'code'` 和新 metadataRevision，但已有及新建 `observeView` 仍返回 `space-ephemeral` 与旧修订，正文和 `readHistory` 实际保留。Space 因旧标签继续隐藏该帧，导致提升后重载再打开会话时正文空白。静态链路为 sdk-runtime.ts 的 promote 调用 `sessionViews.changed(sessionId)`，默认 historyDirty=false；已有 view 的增量快照沿用 previous.session，未重读元数据。请让成功 promotion 正确失效并刷新 view 的 Session 元数据、capture/history 修订（例如此处使用 `changed(sessionId, true)`，或等价的独立元数据失效），同时保留原 ID、canonical/nativeHistory、附件、lineage 和统计，不引入第二 writer 或无关逐 token 全历史读取。验收要求通过正式公开 API 和独立 Host 覆盖提升前已订阅的观察者、提升后新观察者及第二客户端：tag/metadataRevision 与 promote/load 一致，正文、工具原文分页、附件和新 historyBoundary 正常；忙碌、冲突、重复同 requestId、丢响应和重连仍保持原语义。复现证据在 Space 的 `artifacts/diagnostics/sdk-post-alpha12-review/promotion-view-probe.json`，其中 load 已为 code，而两类 observeView 均仍为旧临时标签。Space 已加窄兼容：只在请求正式显示同一 Session 时通过公开 load 核实 Host 的正式标签，随后显示原 SDK items；不改写 SDK tag/正文，也不放开其他临时会话。SDK 缓存根修仍需后续发布包闭环。
