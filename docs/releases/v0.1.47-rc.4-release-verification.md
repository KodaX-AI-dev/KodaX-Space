## Source gate and the Windows rerun

- [Full source build](https://github.com/KodaX-AI-dev/KodaX-Space/actions/runs/46097598311): static checks and the Windows, Mac ARM, Mac Intel and Linux smoke builds passed on attempt 1.
- [Full source E2E](https://github.com/KodaX-AI-dev/KodaX-Space/actions/runs/46097598306), attempt 1: both Ubuntu shards and Windows 2/2 passed. Windows 1/2 failed one case on all three attempts: `tests/e2e/provider-file-credentials.spec.ts:36` "Provider settings report file storage and explicitly change the approved environment source". The provider card reported `[provider.useEnvironment] handler threw: OAuth credential storage failed.` while the source stayed at both values; the two other cases of the same file passed right after. The case had passed on its first attempt in the seven earlier ci runs, and the release-preparation commits `0cda9314` and `c373e7e8` do not touch that path.
- The failure was investigated on the local Windows machine instead of by re-running CI. Without load the case passed 10 of 10. With one busy loop per core (24) and the CI timeouts, 8 of 10 passed, 1 passed on retry and 1 failed all three attempts with the same card error. A probe that drives the SDK file credential store directly did not fail in 80 writes under the same load, and `powershell.exe`, which the store starts twice per write, took about 230 ms per start there. The cause sits in the SDK's store, which reports every unexpected error of a write as `storage_failed`; it is recorded as [Issue 259](../KNOWN_ISSUES.md#issue-259--windows-switching-a-provider-to-the-environment-source-can-fail-with-oauth-credential-storage-failed-under-load).
- Re-run of the failed job only (attempt 2): Windows 1/2 passed. No assertion or timeout was changed for it.
