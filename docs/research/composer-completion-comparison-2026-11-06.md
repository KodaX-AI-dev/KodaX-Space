# KodaX Space 如何让命令、技能、文件补全清楚显示并完整删除？

> 实施更新：用户已批准第 7 节方案，当前源码已实现。第 1–6 节的 Space 现状与行号描述的是下述基线 commit，保留为调研证据；不代表实施后的输入组件仍然是 textarea。当前行为与验收见 [版本实现记录](../features/v0.1.47.md#composer-tokens--2026-11-06) 和 [回归指南](../test-guides/FEATURE_031_0.1.47_TEST_GUIDE.md)。

结论摘要：建议把已确认的补全项保留为有类型、有真实值的行内对象，采用 ZCode 的统一 token 思路，参考 DeepSeek 的引用展示和 Codex 的原子编辑边界；只美化候选列表无法解决整体删除。此处是基于本地源码的设计建议，尚未实施或做运行时体验验收。

调研日期：2026-11-06。Space 基线：`527df095bcf6d7993781218f4652b9560cfca6ab`。四个参考项目均读取用户指定的本地 checkout，没有拉取更新，也不把开源 CLI 的实现等同于同名闭源桌面产品。各项目 commit、逐条源码引用、测试证据与局限见配套笔记。

## 1. 四个项目的差别

| 项目 / 范围 | 已选命令、技能 | 已选文件 | 可借鉴之处 |
| --- | --- | --- | --- |
| ZCode / Web 桌面输入组件 | command、skill 使用统一 PromptMentionNode token | 使用同一 token；展示名与真实路径分开 | 最贴近本次目标：统一身份、显示、序列化；补全后的专用空格与 token 一次删除 |
| deepseek-harness / Web 输入组件 | command 是独立原子节点；skill 的 `/name` 仍为可编辑文字引用 | 独立 DecoratorNode 引用 | 类型明确的展示、引用信息与命令删除策略；不能称所有 skill 都原子化 |
| codex / Rust TUI | 已识别 slash 和选中的 skill/plugin mention 有原子 element；mention 另存路径绑定 | 路径补全仍是普通字符串，含空格时加引号 | 光标跳过对象、整块删除、显示文字与真实目标绑定分离 |
| pi / CLI 与 apps/p2 | slash、skill 补全主要是普通文字 | 文件补全仍是普通文字 | 补全和路径处理；原子编辑主要见长粘贴占位符，不是完整引用方案 |

## 2. Space 的现状与缺口

### 2.1 候选列表已经知道类型，选中后丢失了类型

`SlashPickerItem` 已区分 slash、skill、workflow、slash-arg；列表里有名称、描述、参数提示和来源，也对 command 与 skill 使用不同色彩。选中后 `onSlashPick` 只把 `insertText` 拼回字符串，输入组件仍然是 `textarea value={prompt}`。所以问题不只是候选不够好看，而是编辑状态没有保留选中对象的身份。[SlashCommandPopover.tsx:29](../../apps/desktop/renderer/src/shell/SlashCommandPopover.tsx#L29)、[SlashCommandPopover.tsx:744](../../apps/desktop/renderer/src/shell/SlashCommandPopover.tsx#L744)、[BottomBar.tsx:2382](../../apps/desktop/renderer/src/shell/BottomBar.tsx#L2382)、[BottomBar.tsx:2744](../../apps/desktop/renderer/src/shell/BottomBar.tsx#L2744)。

文件候选已把 basename 与目录分开显示，但确认后直接插入 `@${picked} `，调用方仍只做字符串拼接；后续普通删除没有文件对象边界。[AtPathPopover.tsx:114](../../apps/desktop/renderer/src/shell/AtPathPopover.tsx#L114)、[AtPathPopover.tsx:153](../../apps/desktop/renderer/src/shell/AtPathPopover.tsx#L153)、[BottomBar.tsx:2820](../../apps/desktop/renderer/src/shell/BottomBar.tsx#L2820)、[BottomBar.tsx:2524](../../apps/desktop/renderer/src/shell/BottomBar.tsx#L2524)。

### 2.2 已有附件标签，但不等于行内补全对象

拖入/选择的文件存为 `pendingFileRefs`，有图标、名称、路径和删除按钮；删除是从数组移除整个项。发送时将 reference 拼接到正文，并另行收集真实绝对路径。行内 `@` 补全没有复用这套身份表示。因此不能把 Space 描述为完全没有文件 chip；目前是两条入口的表达不统一。[BottomBar.tsx:578](../../apps/desktop/renderer/src/shell/BottomBar.tsx#L578)、[BottomBar.tsx:1083](../../apps/desktop/renderer/src/shell/BottomBar.tsx#L1083)、[BottomBar.tsx:2700](../../apps/desktop/renderer/src/shell/BottomBar.tsx#L2700)、[BottomBar.tsx:2070](../../apps/desktop/renderer/src/shell/BottomBar.tsx#L2070)、[fileReferences.ts:123](../../apps/desktop/renderer/src/lib/fileReferences.ts#L123)。

### 2.3 展示与路径转义也应统一

`@` 候选查询遇空白就结束，选中结果未经路径引用格式化便直接拼入。附件入口则已检查空格、括号、引号等字符，不适合 `@path` 时生成 Markdown file URL。这里可确认的是两条入口格式化不一致；尚未验证 SDK 对所有特殊路径的最终解析结果，不把潜在风险描述为已复现失败。[AtPathPopover.tsx:32](../../apps/desktop/renderer/src/shell/AtPathPopover.tsx#L32)、[AtPathPopover.tsx:118](../../apps/desktop/renderer/src/shell/AtPathPopover.tsx#L118)、[BottomBar.tsx:253](../../apps/desktop/renderer/src/shell/BottomBar.tsx#L253)、[BottomBar.tsx:271](../../apps/desktop/renderer/src/shell/BottomBar.tsx#L271)。

当前 slash 用 Tab 接受候选、Enter 发送；文件候选同时用 Tab/Enter 接受。该差别是实际代码行为，若统一需要明确交互决策，不能作为无意的重构副作用。[SlashCommandPopover.tsx:690](../../apps/desktop/renderer/src/shell/SlashCommandPopover.tsx#L690)、[AtPathPopover.tsx:113](../../apps/desktop/renderer/src/shell/AtPathPopover.tsx#L113)。

### 2.4 视觉类型相同不意味着执行语义相同

Space 目前仅对以 `/` 开头的提交做命令解析；未知 command 回到普通 session 输入路径，冲突的 skill 名称使用 `/skill:name` 避免误执行。不能因为界面支持行内 token，就顺便宣称消息中间的 `/clear` 也能执行，或任意位置、多 skill 的组合语义已经成立。[BottomBar.tsx:2078](../../apps/desktop/renderer/src/shell/BottomBar.tsx#L2078)、[BottomBar.tsx:1272](../../apps/desktop/renderer/src/shell/BottomBar.tsx#L1272)、[skillSlash.ts:25](../../apps/desktop/renderer/src/shell/skillSlash.ts#L25)。

## 3. 建议的交互

以下是面向 Space 的建议，不是竞品事实，也不是已批准的实现规格。

1. **候选明确区分类型。** command、skill、file 使用图标和文字类别；主行名称，次行描述/目录。同名技能补来源，同名文件补目录，不只靠颜色。复用现有发现接口和文件搜索。
2. **确认后变为行内标签。** 命令显示 `/review`，技能显示其名称与技能图标，文件显示 `BottomBar.tsx`；悬浮/详情可见完整路径与来源。输入中的普通说明、参数继续是文字。
3. **显示、身份和提交值分开。** 标签短名称不承担真实文件路径或技能目标的职责；编辑器中的每次插入有自己的对象身份，避免删一个引用时误删同名的另一个。
4. **按整个对象编辑。** 左右键跨过标签；Backspace/Delete 在相邻边界删除整个标签；跨标签的选择删除也移除完整对象。明确处理补全自动添加的分隔空格，且不吞掉用户自己输入的空格或正文。
5. **删除可恢复。** 一次撤销恢复标签、真实身份和相邻文本；复制/剪切有可读文本降级，不复制 DOM 外观或只复制短文件名。草稿恢复、失败重试和历史回填不能只恢复一个好看的名字而丢失目标。
6. **参数不并入命令标签。** `/review` 与 `--lean src/` 是不同编辑单位；命令位于提交开头的既有规则先保留。粘贴进来的示例、URL、正文中的斜杠，不应盲目按正则变为可执行命令。

其中“转义”应拆成两个概念：编辑态把长路径/标记呈现为简短标签；提交态按既有 SDK 输入契约正确编码真实值。两者不应互相替代。依据是 Space 已有的附件路径处理和 ZCode 的 label/value/markdown 分离：[fileReferences.ts:114](../../apps/desktop/renderer/src/lib/fileReferences.ts#L114)、[PromptMentionNode.ts:28](C:/Works/PubProj/ZCode/packages/ui/src/mentions/nodes/PromptMentionNode.ts#L28)、[PromptMentionNode.ts:158](C:/Works/PubProj/ZCode/packages/ui/src/mentions/nodes/PromptMentionNode.ts#L158)。

## 4. 最小实施方向

建议单独抽出输入编辑组件，以少量带类型的 token 节点承载 command、skill、file；现有候选发现、命令分发、文件引用处理继续作为数据与执行边界。ZCode 的 Lexical token 节点可作为实现参考；是否采用 Lexical 需要小范围验证，当前 Space 桌面依赖里没有 Lexical，不把引入编辑器当成已作出的决策。[Space package.json](../../apps/desktop/package.json)、[ZCode token 创建](C:/Works/PubProj/ZCode/packages/ui/src/mentions/nodes/PromptMentionNode.ts#L188)。

不建议继续在 textarea 上叠一层彩色文本来承担整套体验：那样仍需自行维护光标、选择、原子删除、复制和撤销与显示层的同步。这个判断来自本次所需能力及 Space 当前纯字符串模型，并非声称 overlay 技术不可行。[当前编辑状态](../../apps/desktop/renderer/src/shell/BottomBar.tsx#L566)、[当前输入与选区](../../apps/desktop/renderer/src/shell/BottomBar.tsx#L2744)。

实施顺序建议：先用文件补全打通“选择 → 标签 → 继续输入 → 删除 → 撤销 → 提交/失败恢复”，再覆盖 skill 与 command；最后统一候选展示与历史恢复。不先建设通用插件系统，不迁移其他无关文本框。

## 5. 后续验收重点

本次只读源码与测试文件，没有启动竞品或运行测试。以下是未来实现应先写的行为用例：

- token 前后与自动分隔空格处的 Backspace/Delete；同一目标插入两次，只删除当前位置的一次。
- 光标穿过 token、鼠标跨 token 选择、剪切、粘贴、撤销和重做。
- 中文输入法候选确认不能误触发送/补全；换行、软换行、历史上下键语义保持明确。
- 空格、中文、括号、引号、`#`、Windows 盘符/UNC 路径；同 basename 的不同目录。
- 命令与技能重名；命令参数继续编辑；正文中的命令示例不被意外执行。
- 发送快照、慢命令、切换 session、失败恢复时，对象身份与用户新输入保持对应。

这些验收建议分别针对已看到的文本/节点边界、路径序列化、输入法与提交所有权，不以仅验证 CSS 类或只测字符串 helper 代替真实编辑行为。

## 6. 未证实与未解问题

- 未证实：四个 checkout 对应的实际发布版本在所有操作系统下的体验；浏览器原生选择和 Lexical 默认行为不能仅凭节点配置视为完整验收。
- 未证实：Space SDK 是否支持任意位置、多个 skill 的结构化组合调用；本次建议不扩大其语义。
- 待决策：标签 Backspace 一次删除，还是先选中再删除？建议采用一次删除 + 撤销，与用户提出的完整删除目标相符。
- 待决策：候选打开时 Enter 是否统一为接受？建议单独明确，避免改变现有 slash 发送习惯而未被察觉。
- 待验证：Lexical 小范围接入是否满足现有输入法、附件、历史和发送时序；若采用，应以真实浏览器交互测试确认。

## 7. 追加：视觉与交互的完整推荐方案

用户追加要求：视觉也要好看，需一并考虑完整、合理的方案。以下是方案建议，供后续实施采用；不是已完成的视觉验收或正式 feature 规格。第 6 节的产品分叉在此给出推荐取舍，技术未证实项仍保留。

### 7.1 设计目标与现有风格

目标体验是“输入仍像写一句话，引用像嵌在句子里的小对象”：读得到、认得出、容易改、不留半个标记。完成一次选择后，用户应能看出选了什么、真实目标在哪里、如何移除，以及发送时会发生什么。

沿用 Space 已有的暖石墨 / 暖纸白、Geist / 中文字体回退、JetBrains Mono、局部玻璃、琥珀焦点。输入区样式必须来自现有语义 token；类别主要靠图标和名称区分，不给每类贴满高饱和背景，不把“运行蓝”“成功绿”“警告黄”用成永久类别色。[主题定义](../../apps/desktop/renderer/src/styles.css#L35)、[既有设计方向](../design/space-ui-integration.md)、[字号与组件约束](../design/space-ui-refinement-2026-10-20.md)。

本次没有新画视觉原型；下列尺寸是组件设计起点，需要在真实窗口、缩放和中英文样本中校准，不能仅据数字声称视觉效果已合格。

### 7.2 三个区域，各自只承担一种职责

| 区域 | 内容与层级 | 推荐呈现 |
| --- | --- | --- |
| 输入主体 | 正文 + 行内 command / skill / file | 视觉中心；与正文共同行进和换行，保持连续阅读 |
| 补全浮层 | 当前触发词对应的候选 | 只有正在补全时出现；名称优先，说明和路径次之 |
| 附件与环境 | 图片、拖入附件、项目及现有运行控制 | 继续使用已有位置；附件与行内文件共享图标、命名和详情规则，避免同一引用因补全自动在两处重复显示 |

既有 context gauge、吉祥物、模型、运行/排队控制保持各自的功能和布局责任。这次输入设计不借机改动全局字号或重排整套工作台。既有设计明确保护 context 和 mascot，局部新组件也应遵循。[保护范围](../design/space-ui-refinement-2026-10-20.md#protected-surfaces-and-constraints)。

### 7.3 行内标签：轻而清楚

| 属性 | 推荐规则 |
| --- | --- |
| 形状 | 紧凑圆角矩形，约 6px 圆角、1px 细边；避免长胶囊占据过多行宽 |
| 尺寸 | 约 24px 高，左右约 6px 内边距；正文约 14px、24–26px 行高，标签文字 13px；跟随应用缩放，不改全局字号 |
| 图标 | 14px 左右，复用已有 Lucide；command 用命令图形，skill 用技能/书本图形，file 用文件/目录图形；不使用 emoji |
| 默认态 | 中性薄底、清晰文字、细边，存在感略高于 inline code；浅色与深色分别配 token，不能机械反色 |
| hover / 键盘焦点 | 背景稍加强；焦点有明确轮廓；不通过加粗或换尺寸造成正文跳动 |
| 选区态 | 使用可辨识的统一选中底色，保留文字与图标对比；不与错误态混用 |
| 长名称 | 标签上限建议为输入宽度的 60%，且不超过约 240px；保留扩展名，必要时中间省略；整个 token 换行而不拆成两段 |
| 重名 | 同一草稿内有同 basename 的不同文件时，增加最短可区分目录；skill 重名显示来源；详情始终给完整身份 |
| 错误态 | 仅在已确认目标失效时显示错误图标与说明；发现服务暂时失败不等于对象失效 |

command 保留 `/`，技能保留当前可执行调用语法对应的名称，文件以短文件名显示。三类可共用外观骨架，但仍保留类别信息；不能把一个文件看起来做成要执行的命令。

行内标签默认不放常驻小叉，避免一段话变成连续按钮栏。键盘相邻删除是主路径；点击标签打开小型详情浮层，包含类别、完整路径/来源、复制引用、移除，文件可使用已有打开入口。详情中的删除按钮使用正常命中面积。悬浮可预览身份，键盘也能打开同一详情，不能只靠浏览器 `title`。删除后焦点回到原标签附近，不跳到句尾。

附件条保留现有直接删除按钮，不为追求外观统一削弱已有操作。标签点击只查看，不执行命令，也不改变编辑草稿。

### 7.4 补全浮层：扫描快、宽度稳、状态完整

- **位置**：锚定输入区左侧，默认在上方；空间不足时翻转或收缩高度，保持光标和当前输入可见。沿用公共浮层的层级策略，避免被滚动容器截断，不在局部继续堆更高 z-index。
- **宽度**：桌面起点约 440px，随输入容器收缩；窄窗贴合可用宽度并留边距。不要随最长候选每次跳宽，也不默认铺满宽屏输入区。
- **条目**：约 44–48px 两行布局。左侧 16px 图标；第一行 14px 名称，第二行 12px 描述/目录；右侧仅在有意义时显示来源。名称不要像当前实现那样用固定最小列宽挤压窄窗描述。
- **分组**：`/` 下分“命令 / 技能”，保留已有工作流及参数入口；`@` 下显示当前文件能力支持的结果。组标题小而清楚，不做大卡片。查询中优先按匹配质量排列，稳定排序；不凭空添加“最近使用”数据。
- **高亮**：当前项使用琥珀柔和底色与轮廓；匹配文字用字重或细微前景变化，宽度保持稳定。键盘改变选中项时让该项可见，鼠标静止不抢回键盘选择。
- **详情**：候选默认显示一行摘要，选中项的较长说明可在固定详情区域展开；不因为每次上下键都改变行高而推移列表。
- **底栏**：只放当前有效的操作提示，例如“↑↓ 选择 · Tab/Enter 插入 · Esc 关闭”；参数补全按实际动作更新。不要显示一整排无关快捷键。
- **状态**：首次查询显示安静的加载状态；后续查询保留面板几何。无结果显示具体查询和建议；失败显示可重试状态，不能伪装为空列表。旧查询结果可以短暂保留视觉，但不得作为新查询的可确认项。

浮层正文用实色或高不透明度材质，边界细、阴影轻；输入外壳可继续现有玻璃效果，候选列表与每个 token 不叠加 backdrop blur。这与现有“长文与菜单不用背景模糊、玻璃局限于静态 chrome”的约束一致。[组件材质边界](../design/space-ui-refinement-2026-10-20.md#protected-surfaces-and-constraints)。

### 7.5 推荐的完整操作规则

| 场景 | 推荐行为 |
| --- | --- |
| 输入 `/`、`@` | 在有效边界打开对应候选；光标移动或选区变化后重算触发范围 |
| 候选有效且已打开 | Tab 或不带修饰键的 Enter 插入当前项，关闭该轮候选；不同时执行命令或发送 |
| 候选加载/失败/无结果 | 不选旧项；普通 Enter 不穿透发送，避免网络快慢决定是否误发；Esc 关闭后可发送原文，发送按钮保持明确可用 |
| 候选关闭 | Enter 沿用发送语义；Shift+Enter 换行；Ctrl/Cmd+Enter 沿用现有排队语义；Tab 正常移动焦点 |
| Esc | 每次只关闭最上层候选/详情，不在同一次按键中继续触发停止运行 |
| 中文输入法组合态 | Enter/空格/方向键先交给输入法；组合完成后再更新候选，不误发送、不替换中间态文字 |
| 刚选中 token | 光标在 token 后的自动分隔空格后，可直接继续写；候选不会因选中结果又立即反复打开 |
| Backspace / Delete | 光标紧邻 token 时删除整个 token；插入后未编辑的自动分隔空格可与 token 一次删除；用户后来输入的空格和正文不被连带吞掉 |
| 左右键 / 单词导航 | 光标落在对象前后，不落入对象内部；包含 Home/End、修饰键导航和鼠标定位的边界验收 |
| 选区删除 / 剪切 | 与 token 相交时按完整对象处理，明确显示实际选中范围；移除的是该次插入对象，不是所有同名引用 |
| Undo / Redo | 一次恢复/移除同一编辑动作的文本、token 身份及选区；单击移除和键盘删除进入同一撤销历史 |
| 复制 / 粘贴 | 对外提供可读、可往返的标准引用文本；对内保留可验证的结构化数据；无法识别的数据降级为文字，不通过标签外观猜真实身份 |

这里明确建议统一候选 Enter 为“插入”，这是相对 Space 当前 slash Enter 发送行为的有意改变，应在实现说明与测试中单独覆盖。选择后再次 Enter 才发送；参数补全和带修饰键的发送需要使用同一个键盘优先级规则。

命令参数继续是普通文本，可调用既有参数补全；已确认命令位于开头时才拥有命令语义。把命令移入正文时，推荐降为普通引用文字，不能保留误导性的“将执行”外观。手工输入和粘贴的普通文本保持可用；只有明确接受候选或可验证的结构化恢复才建立对象身份，不把所有 `/词`、`@词` 自动实体化。

技能不因视觉变成标签就增加任意位置/多个技能组合执行能力。所有调用仍受现有 Runtime/SDK 契约约束；必要的区别在界面说明，而不隐藏在提交时的猜测里。

### 7.6 动效、可访问性与窄窗

使用既有 `motion-fast`（150ms）作为微反馈起点。候选首次显示可做轻量 opacity 过渡，hover/focus 只改变颜色与边界；上下键、文字输入、token 删除、撤销立即生效。不要对每个候选错峰入场，不把 token 缩放/滑动到位置，也不对行高做动画。极简档和 reduced-motion 瞬切。[现有动效 token](../../apps/desktop/renderer/src/lib/motion.ts#L26)。

正文和必要说明的对比度目标至少 4.5:1，焦点与重要非文字边界目标至少 3:1；这些是验收目标，不是已测量结果。类型辨识不只靠颜色；读屏获得类型、名称与必要路径，候选有有效活动项，详情与移除都可键盘操作。加载/失败通知不应每按一键都重复播报。

宽度按输入容器而非整屏判断。建议验收输入可用宽度 320 / 480 / 720px、100% / 125% / 150% 缩放、深浅主题、中英文。窄窗候选次行换行/省略，详情可展开；输入 token 整块自然换行，保留发送按钮与底栏可达性。图片仍采用附件预览，不强行压成行内文字标签。

### 7.7 最小技术方案与生命周期

优先验证 Lexical 作为局部输入引擎，按现有三类真实对象建立最小带类型节点，复用候选数据源、样式 token、路径处理及命令执行层。正式依赖决策以 IME、剪贴板、撤销、提交恢复的验证为依据，不引入无关富文本格式工具栏、通用编辑器插件平台或新的用户配置。

编辑器状态作为编辑阶段的唯一事实源；候选查询从光标附近读取文本投影，发送边界再生成现有输入格式。不要每次输入都把整份编辑器状态序列化成字符串，再由 React 回写重建节点，否则容易丢选区、IME 和历史。

每次插入对象同时保存“本次插入身份、类别、显示信息、真实目标”，不以 basename/显示名作为唯一键。不同类别需要的字段使用明确类型；command、skill、file 的序列化分别遵守既有契约。目录等既有能力沿用自己的类别，不为了共用外观改运行语义。

发送捕获不可变草稿快照，包括 token、附件与来源会话；恢复失败草稿时必须核对请求和当前会话/草稿版本，不能覆盖用户提交后的新输入。候选查询绑定项目、query 和请求代次；过期结果不可插入到新草稿。会话切换、历史回填和草稿恢复都要恢复完整编辑状态，跨会话持久化则只扩展确有需求的既有存储边界。

存在历史纯文本记录时，优先显示原文；只有能从现有受支持引用格式可靠重建身份的内容才恢复为标签。同名 skill 无法消歧时不自动绑定错误目标。旧数据无需为了视觉统一强制迁移。

### 7.8 分阶段实施与完成标准

1. **视觉验证**：使用真实名称、同名文件、长路径、中英文和多标签句子，校准正文、标签、候选、详情四者的层级；覆盖深浅与窄窗。静态方案用于选型，最终仍以真实组件截图验收。
2. **文件纵向闭环**：补全 → 行内对象 → 继续输入 → 整体删除/撤销 → 复制 → 提交/失败恢复。视觉样式在这条闭环一起实现，不先交付无样式的半套输入系统。
3. **命令与技能**：复用经验证的对象编辑规则，接入命令/技能冲突、参数补全和开头执行约束；统一候选键盘语义。
4. **生命周期和完整回归**：历史、项目/会话切换、附件、队列、重试、IME、无障碍、缩放与材质档位；实际截图与浏览器交互确认后再视为完成。

业务行为采用测试先行，在既有 Electron E2E 的输入/发送公共边界验证；序列化与范围变换使用必要的单元测试。不用测试 CSS 类名来证明好看，不用人工截图来代替剪切/撤销/提交行为测试。变更模块覆盖率遵循仓库 ≥80% 要求，同时关注边界用例是否真正覆盖。

完成时必须同时满足：用户能清楚区分类别；长名称不压垮布局；一次删除不留残片；撤销恢复真实目标；中文输入不误发；发送内容与标签身份一致；失败/会话切换不丢或串草稿；深浅、窄窗与缩放的实际截图通过审阅。性能以现有输入基线对照检查，输入不等待异步检索，流式回复不反复重建编辑器；若有可见卡顿需用实际 profiling 定位。

本次追加完成的是方案整合，未修改产品代码，也未将推荐取舍标为用户已经批准的实现细节。
