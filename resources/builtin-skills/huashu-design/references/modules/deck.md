# 演示稿

交付格式由本次请求和既有文件决定：HTML 演示、静态 PDF、可编辑 PPTX 分开处理。无需先产出所有格式；不把整页截图或 HTML 声称为原生可编辑对象。

## 选择路径

- HTML：沿用现有结构；新建时按实际需要选择单文件 Stage 或多文件概览。读 [slide decks](../slide-decks.md)，不按固定页数强制改架构。
- PDF：使用当前可用的导出能力，确认文字、图像和页面布局；HTML 架构匹配时可采用 scripts/export_deck_pdf.mjs 或 scripts/export_deck_stage_pdf.mjs。
- 可编辑 PPTX：优先当前已注册的原生 PPTX 能力。采用 HTML 转换时，按 [editable PPTX](../editable-pptx.md) 或 [rendered HTML](../pptx-from-rendered-html.md) 选择适合已有视觉稿及客户模板的路径，验证编辑能力与内容完整性。

需求明确时直接制作；需要探索才提供代表页比较。已有风格不重复确认，后续改稿不重新进入方向选择。只有用户确需取舍时等待，不在内部规划和实现阶段增加审批。

## 页面与检查

按受众、观看距离和讲述/阅读用途决定层级、字号与密度，材料超量时拆页或重新组织。页面角色和版式服务于内容，数据图形反映数据关系，不固定套用同一个大数字模板。

HTML 保持一致舞台与缩放，页码只由单一来源控制，避免外壳和内容重复。演讲者备注、概览和局部编辑按需要提供。读 [content guidelines](../content-guidelines.md) 时把字号表作为适用场景参考，实际以可读性和用户设计规范验证。

渲染每一页及最终导出，核对文字、图片、裁切、溢出、遮挡、页序和需要的备注。转换器的文本检查不代替视觉检查。只交付本次所需文件和必要使用说明。
