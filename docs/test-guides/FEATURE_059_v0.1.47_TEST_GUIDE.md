# F059：文件型成果预览与文件操作回归

日期：2026-11-09。状态：源码修复，未打包发布。

## 复现与根因

用户会话 `20261109_113749_hk5cd1a1ed63a7` 中，`ego-lite-anatomy.html` 被以 `kind: file`、工作区路径注册。文件存在且可由项目预览服务读取，但通用成果分发只识别富媒体，没有把 HTML 路径交给 Web 预览，显示「无法渲染该 Artifact（file）」。同会话的 PDF 可预览；二者均因工作区引用被排除在另存为能力之外而没有保存入口，卡片也没有文件操作菜单。

HTML 文件预览现在复用现有项目 Web 预览服务；另存为复制经所属会话项目验证的源文件，保留文件名与扩展名。源文件与成果登记保持不变。文件缺失、越界或不是普通文件时，在弹出保存对话框前失败；原有导出策略与审计继续适用。

## 交互约定

| 入口                   | 操作                                                                         |
| ---------------------- | ---------------------------------------------------------------------------- |
| 对话成果卡片左键       | 继续在成果面板预览                                                           |
| 卡片右键或「…」        | 另存为、在文件管理器中显示、复制文件路径、在独立窗口打开                     |
| 侧栏、全屏成果预览顶部 | 显示带文字的「另存为…」；工作区文件显示文件管理器按钮；「…」复用文件操作菜单 |
| 独立成果窗口           | 与主窗口使用相同另存为和文件操作行为                                         |

统一使用「另存为…」，不另设重复的「下载」。正文型成果仍可导出；没有工作区源路径时，不展示伪造的文件管理器或复制源路径操作。所有动作对应用户选中的成果版本。

## 人工验证

1. **P0 / 正向、兼容性**：打开上述会话的交互原版 HTML。预期标题、导航和 SVG 图表正常显示，不再出现不支持 `file`；打开同会话 PDF，分页阅读保持正常。另测 `.htm` 和大写 `.HTM` 文件。
2. **P0 / 正向**：在 HTML 和 PDF 预览顶部点击「另存为…」，保存到另一个临时目录。预期保留正确扩展名，副本可打开，源文件仍存在且哈希不变。
3. **P1 / UI**：分别通过卡片右键、卡片「…」、预览顶部「…」操作。预期能定位实际源文件、复制正确路径、另存为；卡片仍支持左键预览及独立窗口打开。菜单支持方向键、Escape 和点外部关闭，不被对话滚动区裁切。
4. **P1 / 边界**：准备两个版本，分别引用不同文件。切换预览版本后另存为或定位文件，预期操作对应选中版本；对话中的旧版本卡片也使用自身版本。
5. **P1 / 负向**：取消另存为对话框，预期不显示错误或「已保存」。模拟写入失败，预期显示错误，界面可继续使用；移走源文件后，预览或导出应明确失败。
6. **P1 / 安全**：在隔离测试项目中使用越界路径、缺失路径或目录作为文件引用。预期被 Main 拒绝，不弹出保存对话框、不生成副本，不放宽项目边界和网络策略。
7. **P2 / 性能、布局**：在窄侧栏与全屏之间切换并阅读多图 HTML；菜单不引发文件重建，预览保持可滚动，常用操作可见且无工具栏横向溢出。
