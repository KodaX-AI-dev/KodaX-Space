# v0.1.46-rc.5 release readiness

Date: 2026-09-24. Previous release: v0.1.46-rc.4.

## Scope

- Fix the F022 auto-update platform policy (application-side only; the KodaX
  dependency stays pinned at `0.7.96-rc.11` with unchanged capability gates):
  - macOS builds are unsigned (`mac.identity: null`; the FEATURE_027 signing plan
    was dropped 2026-06-05). Squirrel.Mac validates the code signature before
    replacing the app, so updates downloaded and passed checksums but the final
    swap failed asynchronously and silently — the banner button stuck at
    "Installing..." forever. `initAutoUpdater` and the `updater.check` channel now
    no-op on darwin: state stays `idle` and the update banner never appears until
    signing is restored. macOS users update via the GitHub Releases DMG.
  - Windows `updater.install` calls `quitAndInstall(true, true)`: the `/S` silent
    install reuses the recorded install directory and `--force-run` relaunches the
    app, so the full NSIS setup wizard no longer pops up on every update.
  - Linux keeps auto-update (AppImage replaces the file directly; deb downloads
    then prompts for sudo via pkexec).
- Synchronize workspace versions, changelog, READMEs, capability ledger, product/
  architecture/usage docs, user manual, feature list, `docs/features/v0.1.46.md`,
  and kodax_manual (rc.5/rc.11 stamp with anchored contract test including the
  darwin updater note).

## Qualification

- New `e2e/auto-update-packaged.mjs` verifies the Windows flow end to end against
  a packaged build: real NSIS install → local generic feed → update banner →
  click → silent install → relaunch → auto-uninstall. Unit coverage in
  `updater.test.ts` covers the platform gate and the silent-install flags.
- Typecheck and lint pass; the full local unit chain passes (see the verification
  record for the pre-push run).

## Remaining boundaries

macOS auto-update stays disabled until builds are code-signed; restoring signing
re-enables the darwin path and is a separate piece of work. The deb path still
requires an interactive pkexec sudo prompt by design. Pure configuration-type
extension commands remain CLI-owner-only; the Issue 217 native macOS acceptance,
Partner Coder sharing, real external-account acceptance, and automatic library
replacement remain open from earlier readiness records. FEATURE_275 long-term
guarantees are unchanged.
