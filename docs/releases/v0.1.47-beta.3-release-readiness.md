# v0.1.47-beta.3 release qualification

日期：2026-11-21。用户指定 Space `0.1.47-beta.3` 预发布；精确依赖 npm Registry `@kodax-ai/kodax@0.7.97-beta.13`（`sha512-4/dwRjmMLpXURjmf/U28a6ccO2QkI1sD1pmAWxfAjweQKPUd1lwflb5za4OYhqmhwfRVcbp88j87HPxTHnFwfA==`），四个 workspace 与 lockfile 统一 Space 版本。稳定版保持 v0.1.46，不向正式版自动推送预发布。已发布的 beta.2（beta.11 构建）与 beta.1/alpha.4/alpha.5 记录保留为上一轮发布历史。

## 发布范围

- SDK beta.13 精确固定（root/Desktop/lockfile 同一 Registry tarball）并要求 `actorSettlementConvergence` v3：每次 Stop 都到达最终结果；Actor 结算无法确认持久化时 Run 以 `actor_settlement_not_persisted` 失败收尾（`effectOutcome: 'unknown'`），失败详情带脱敏 Provider/本地错误原文（`failureDetail.detail` 行），Session 在后台自愈期间以 `conflict` 拒绝 `runs.start`/`acceptInput`（composer 保留草稿并提示 `session_recovering`），该 Session 不再阻塞 Host 停止；只有 `host_shutdown_verified` 证明旧 Host 已退出。
- 集成健康（MCP/Skills/扩展）每 2 秒走 Host 轻量 `integrations()` 查询（Host 声明 `integrationConfigResilience.healthQuery` 时），不再在每次轮询触发完整管理预检——预检自身被 SDK 缓存（Issue 430），空闲时不再反复扫描 profile；无该查询的旧 Host 在连接时读一次，Host 重启后恢复自动刷新。会话列表只读每个会话文件首行前 4 KB（Issue 429），Host 恢复结束带原因。
- 新 Session ID 改用 UUIDv7；未命名会话以 ID 末 8 位标注（UUIDv7 前 8 位是时间戳，同一批创建的会话会重名）。SA 模式退役：每个根 Run 走托管 Worker，`agentMode: 'sa'` 启动仅返回警告。
- 侧栏“需要你”的会话（等待确认、出错、完成未读）不再被侧栏未列出的位置隐藏：未选中的 Coder/Partner 标签与折叠的“已归档”项目分组显示与折叠项目相同的标记和数量；需要你或正打开的已归档会话即使未开启“显示已归档会话”也列在所属项目中，处理后再隐藏。从未拖动过的项目恢复最新置顶排序（beta.1 起曾变成最旧在前、升级后列表看起来倒置）；拖动顺序保存在其下，之后新打开的项目仍排在最上方。
- Settings → 技能 ZIP/文件夹安装接受最多 32,768 个文件的技能（原 4,096），CyberPPT（11,685 文件）可安装；超限 zip 在解压前由中央目录计数拒绝（零写入），临时文件带重试删除，删除失败记录日志而不是静默留下 `.install-tmp`（Issue 253，随本版发布）。
- Partner 产物文件链接可靠打开：Partner profile `2026-11-20` 要求所有 Partner run 复用交付工具返回的 `kodax-space://partner-delivery/` 链接、按项目根相对路径引用项目内文件、不再引用裸 run-output 路径（`write_partner_deliverable` 相应改标签）。链接轻微写错（缺/多一层目录、丢分隔符）时按唯一最优候选以文件名打开：先查本 Session 的 Partner 交付与工具触碰过的路径，再无缓存、无 `.gitignore` 地重扫项目（`project.fileSearch` 新增 `locate`）；同名并列以警告列出，不猜。
- `@` 文件搜索与文件列表跟随项目根 `.gitignore`：`dist`/`build`/`out`/`target`/`coverage` 与 `.agent` 等隐藏目录除非被忽略均可搜索；依赖/版本控制/缓存目录（`node_modules`、`.git`、`__pycache__`、`.venv`、`.gradle`…）始终跳过；超过 50,000 文件报告截断。
- 每个 live 子 Agent 行显示自己的 token：↑ 输入（含缓存）/↓ 输出按其已完成步骤求和，Main 从 SDK 已转发的子步骤 usage 按子上下文 agent 折叠，无新事件或 IPC。Run 标记完整旋转一圈并在 live 工具组展示工作期间保持显示（等待子 Agent 的 Run 不再看似停滞）；对话跟随末尾在窗口失焦/ refocus 后保持，只有滚动操作才停止跟随。设计记录见 [run-mark](../design/run-mark/direction-approved.md)。
- 当前 README、文档索引、PRD/HLD/DD、USAGE、能力/凭据台账、Feature List、内置技能记录、Known Issues、用户手册与应用内 `space_manual` 话题同步 beta.13 / beta.3 基线；Issue 253 状态更新为 Resolved in 0.1.47-beta.3，Issue 254（Run 期间历史翻页重复/乱序）记录并推迟到下一大版本。SDK 自有 `kodax_manual` 不被覆盖。

## 验证与发布门

- 本地 Windows 完整源码检查：typecheck、lint（`--max-warnings 0`）、workspace 单测（desktop electron/renderer、ipc-schema）与 `npm run test:release`（含 `skills:check`、原生资源预热与 `scripts/test/*.test.mjs`）全部通过（2026-11-21）。
- 发布需同一 SHA 的四平台完整源码检查（ci.yml E2E 双分片 + build.yml 四平台 smoke、静态检查与门禁）、成品构建和成品消费验收。Mac arm64/Intel 在候选归档前通过 `codesign --verify --deep --strict`；Windows 打包 smoke 继续校验 SDK 原生资源哈希与内置 Skill 解包完整性。
- 最终 SHA、运行链接、平台结果与资产校验记录在发布后补记的验证文档（`v0.1.47-beta.3-release-verification.md`）。该记录未确认的项目不得以源码通过替代。

## 保留边界

- macOS ad-hoc 不等于 Developer ID 或公证，首次启动仍可能有 Gatekeeper 提示；通知/图标角标需要系统权限，macOS 仍手动下载 DMG 更新。Windows 安装器未签名。
- SDK Repo-intelligence Host 真实诊断/预热等接缝沿用 [beta.1 完整验收](kodax-beta1-full-acceptance.md)与 beta.2/beta.3/beta.8/beta.9 记录；不因升级宣称已消失。
- Issue 371 首次历史读取延迟仍未关闭，Host ready 不等于历史加载完成；Issue 254（Run 期间历史翻页重复/短暂隐藏/乱序）推迟到下一大版本，本版保持 SDK 0.7.97-beta.13 与现有缓解。不因升级宣称所有恢复性能或智能质量问题已解决。
- 外部账号、真实模型质量/计费、覆盖安装/断电、客户 Kylin/真实 Mac 权限设置仍需对应环境验收。
