# v0.1.46-beta.3 release readiness

Date: 2026-09-14. Previous prerelease: v0.1.46-beta.2. Stable release remains v0.1.45.

## Scope and ownership

This beta integrates the existing Partner library into the organization Space distribution. A fresh profile receives the bundled library without a separate extension download. Users can choose experts and methods, retain the expert binding across Partner session restoration, and connect supported services with their own account and session resource authorization.

The library stays at `0.1.0`, with host API 4 and explicit capability requirements. Space root, Desktop, IPC schema, UI kit and lockfile move together to `0.1.46-beta.3`; KodaX remains exactly `0.7.96-rc.4`. Electron main owns extension provisioning, connectors and privileged operations. Partner keeps its embedded owner; this change does not migrate it into the Coder daemon or add Coder expert/connector UI.

Existing same-ID packages are preserved. Disablement and uninstall intent survive restart. This initial provisioning does not implement automatic replacement of already-installed library versions.

Shared fixes preserve SDK extension execution context, restore the Partner home materials panel, and retain executable node-pty helpers for both prebuilt and source-built installations. The user manual, in-app help and current architecture notes describe the same scope.

## Release procedure

1. Open the organization PR with user effects, ownership boundaries, exact commands, test results and remaining manual checks. Let the complete CI and installer workflow run on the candidate.
2. Resolve failures and review findings before merging; preserve the contributor author and verify the merged SHA belongs to main.
3. Tag only that verified commit as `v0.1.46-beta.3`. The existing tag-triggered release workflow builds all four platform targets and extracts the corresponding CHANGELOG section. Do not overwrite an existing tag or Release.
4. Verify the prerelease flag, Windows Setup/Portable and zip fallbacks, macOS Intel/Apple Silicon DMG/ZIP, Linux AppImage/deb, blockmaps and updater manifests. Record the workflow and Release links.
5. Keep `releases/latest` and documentation's stable-release label at v0.1.45. Beta users select beta.3 explicitly from all releases. Only record publication as complete when the Release and assets actually exist.

## User-facing limits

- A beta does not become the default stable download or automatically deliver Partner to stable-channel users.
- Connector catalog availability is not real-account acceptance. Account permissions, service-specific operations, remote receipts and content-verification state remain explicit. This release must not advertise every connector as production-validated.
- Coder sharing of Partner experts/connectors and automatic upgrades of an existing library are follow-ups.
- Existing beta.2 SDK limitations, including remaining FEATURE_275 guarantees and image-recognition observations, are not closed by this integration.
- Installers follow the project's current unsigned distribution model.
