## FEATURE_147: Integrated Workspace and Full Settings Surface

### 需求概述

2026-10-16 用户批准融合原型进入正式产品。以连续画布、分栏、局部玻璃与克制动效统一工作区和设置，默认保留全部既有能力、多项目并行、深浅/系统主题与三档视觉质量。任何功能删除先另行对齐。此项为当前源代码后续改进，不修改既有发布声明或版本号，不关闭 F139 的独立剩余范围。

### 影响范围

Renderer Shell、左右侧栏、SurfaceTabs、BottomBar 外壳、Partner 外壳、设置容器/appearance、共享 styles 与相关 E2E。完整保留映射见 [功能清单](../design/space-ui-integration.md)。

### 技术方案

复用真实 React 组件及状态源；CSS tokens 与局部材质负责视觉，设置作为 Shell 内工作面，后台工作区保持挂载并隐藏/inert；所有设置入口统一，保留嵌套确认的焦点与 Escape 优先级。原 Artifact/Diff/专注能力承接 B/C，不创建第二个执行模型。无新增第三方依赖。

### 接口契约

SDK/IPC/持久化合同不变。主题与视觉质量继续用既有 appStore 和 localStorage；设置 tab ID、六分类、语义控制 broker 不变。设置从遮罩对话框改为命名 region，关闭/返回和 Escape 保留，背景单击关闭随遮罩消失由页面导航替代。

### 实现步骤

1. 记录逐项功能映射；E2E 先验证设置工作面、草稿保持、全部主题/质量和定向打开（RED）。
2. 实施连续 Shell、共享分栏及统一材质，保留所有组件与 handler。
3. 设置页面化，复用全部设置子面板，添加共享 appearance 入口。
4. 运行回归、类型/静态检查与构建；实际深浅截图与三档/性能验证；Standards + Spec 评审。

### 验收标准

- 功能清单中的原能力均有入口，无未对齐删除。
- 工作区/设置统一视觉，多项目工作状态继续可见，切换设置不丢输入草稿或停止运行。
- 深浅/系统主题与三档质量在标题栏、菜单、设置之间同步并持久化。
- 设置六分类/编辑、Provider 错误恢复、键盘、嵌套确认、关闭返回均可用。
- 流式/历史/后台效果降载与 reduced-motion 保留；无新动画运行时依赖。

Acceptance is at the actual browser input and Electron IPC send boundaries. See the [regression guide](../test-guides/FEATURE_031_0.1.47_TEST_GUIDE.md) for evidence and platform/visual checks. This is source work; it does not replace the published alpha.4 binary or claim publication.

## FEATURE_144: Windowed Continuous Transcript Virtualization

> Status: Completed (2026-11-11; phase 1 complete 2026-11-10, phase 2 tickets 3–8 complete 2026-11-11) → `v0.1.47`, two phases (rescheduled 2026-11-09 from `post-v0.2.x`)
> SDK gate: None; consumes the Registry SDK beta.4 saved-page contracts

**排期（2026-11-09）**：第一段 = 票 1–2，立即开工，不引入窗口化。第二段 = 票 3–8，同在 v0.1.47 内完成，开工须同时满足：(a) 票 1 决策门结论为“DOM/布局为主”；(b) 历史滚动/翻页基础可验证地稳定（2026-11-10 起替代原“一个 alpha 周期内无新回归”的观察期，后者无法在开发期执行）：b1 票 1 基线发现的 Issue 242/243 已修复并有回归测试；b2 历史相关 E2E 与浏览器测试全绿；b3 重跑 10k/30k 基线，首次较早页无 stale 失败、后接锚点漂移 ≤2 px。第二段在 env gate 后推进，gate 关闭时与现状一致；v0.1.47 正式版须完成票 8（默认开启并移除整列挂载路径），否则第二段整体不随正式版发布。

**决策门（票 1 结束）**：按[历史浏览设计](../design/session-history-browsing-and-actions.md)的规模优化依据，开销拆到 IPC、解析、挂载、布局。DOM/布局为主 → 进入第二段；IPC/正文解析为主 → 先收窄预取或解析成本，第二段顺延并在本节记录理由。

### 1. 需求概述

After a user repeatedly loads older pages, tens of thousands of canonical messages must remain reachable through one continuous transcript without keeping every row mounted. The visible result must behave like the current natural scroll surface rather than page switching: older content grows upward, the live tail remains at the bottom, and the user's current reading position does not jump. Windowing must be visually invisible: no blank gaps, no scrollbar-thumb jitter, no reset of what the user expanded, and no replayed entry animation.

### 2. 影响范围

- `ConversationStreamV2` render rows shared by Coder (SDK `productItems`, accumulated saved collection, `around` locate window) and Partner (same SDK `productItems` path on the runtime host — the history backend ignores surface; the legacy `items` path remains only for the legacy/embedded host); viewport anchoring and long-Session cache eviction.
- Row-local UI state that resets on unmount: long-question collapse (`CollapsibleUserMessageContent`), tool-card manual expand (`ToolCallCard`), `ToolDiffView` expand/editor mount, "show all edits", error-notice details, and restored-tail entry animation (`RESTORED_REVEAL_TAIL_ITEMS`).
- Loaded-content Ctrl+F (`usePageFindMatches` walks mounted DOM rows), query rail, jump-to-bottom, keyboard/touch/wheel/held-scrollbar navigation, focus, selection/copy, and screen-reader reading order.
- Fork/rewind actions on SDK turn targets whose rows may be unmounted.
- Live view source, queued inputs, observation recovery, `resync_required`/`data_changed`, and the explicit bottom action that selects the live source.
- History-loading diagnostics marks and packaged Windows/macOS/Linux acceptance corpora.

The feature does not change KodaX transcript storage, canonical ordering, cursor semantics, raw audit retention, or Space's strong-identity-only reconciliation policy.

### 3. 技术方案

**现状基线（beta.4，2026-11-09）**：保存历史与推进中的 view 是两个来源；Coder 保存来源在同一 revision/sourceRevision 内按 SDK item ID 去重累积，较早页前插、较新页后接，两端只保留未读游标；`around` 打开独立定位窗口并可返回原集合；边缘翻页只响应用户手势方向；锚点以 DOM 行 + top 偏移捕获；屏外行由 `content-visibility: auto` 跳过绘制，但 DOM 与 React 树全量保留。

**结构**

- Window over CSV2 render rows (after turn/receipt grouping), so Coder and Partner share one mechanism. The live view source stays outside the window.
- Edge-true window: when the window reaches either end of the loaded collection, the spacer on that side is zero, so the DOM edge equals the collection edge. The existing gesture-intent edge paging and prepend anchor restore then work unchanged; the paging code stabilized during the last alpha cycle is not rewritten.
- One owner of scroll corrections: the existing anchor restoration, generalized to SDK item ID + intra-row offset. The virtualizer must not apply its own scrollTop adjustments; the ticket 4 library choice follows this constraint, and a small in-house window is acceptable.
- Row-local disclosure state lives in a session-scoped store keyed by row identity, so unmount/remount and Session switches keep what the user expanded and keep heights stable.

**视觉与交互保真**

- Overscan by pixel distance (about one viewport on each side, more in the scroll direction), not by row count, so fast wheel scrolling and held-scrollbar drags do not expose gaps.
- Unmeasured space renders as quiet, theme-aware placeholder blocks that follow the transcript rhythm (no shimmer); a bare blank area is never shown.
- Height estimates come from per-row-kind running averages of real measurements. Corrections above the viewport compensate scrollTop, and corrections are deferred while the native scrollbar is held so the thumb does not jitter under the pointer. Images reserve their aspect ratio when dimensions are known.
- Pinned rows never unmount: rows holding the active selection, keyboard focus, an open menu/popover, inline editing, or streaming output.
- Entry animation plays once per row identity; remounts never replay it.
- Query rail markers use logical offsets and update throttled, so markers do not drift while estimates converge.
- Ctrl+F searches the loaded row model (including loaded-but-collapsed bodies; unfilled bodies are never fetched for search), counts across the whole loaded collection, and on jump expands and materializes the target before highlighting.
- Rows expose `aria-setsize`/`aria-posinset` inside a feed so assistive tech reads the full length.

**上线**

- One temporary env var gate (`KODAX_SPACE_TRANSCRIPT_WINDOWING`) during tickets 4–7; ticket 8 made windowing the default and deleted the gate and the full-mount path. Per-row `content-visibility` was also removed in ticket 8: windowing needs real heights of the mounted rows, and the gate-on path had already overridden it to `visible`. No lasting setting is added.

### 4. 接口契约

- KodaX remains authoritative for newest/older/newer saved pages, `around` locate pages, opaque item IDs, revision/sourceRevision fences, `data_changed`/`resync_required`, conversation status/issues, and fork/rewind turn targets. No SDK change is required.
- Space owns the accumulated saved collection, render-row projection, row UI state, measurements, mounted window, overscan, anchor restoration, navigation, and diagnostics. The advancing SDK view remains a separately selected source; virtualization must not combine its body with saved history.
- Every row is addressed by SDK item identity (legacy-host rows: their existing strong row identity) scoped to its source/revision; historyBoundary is an action anchor, not row identity. Timestamp, equal content, visual position, or page-local index must never be used to reconcile records.
- A Session switch, collection replacement, revision change, resync, or user-owned navigation invalidates stale measurement/restoration work before it can move the viewport.
- Search, query navigation, fork, and rewind resolve against the full loaded collection (or an SDK `around` page when the target is unread), never merely the mounted DOM.

    - “底部”只对读取时的那批行有效。较新页到达贴底读者下方时，窗口不追底，保持在读者所在的行上。
    - 窗口变化后，hook 自己把读者所在行（或底部）钉回原位，原生 anchoring 已保持时这次写入是空操作。原因：Chromium 若在视口里只有 spacer 时选了粗锚点，会一直用到下一次滚动。
    - CSV2 待执行的历史恢复锚点行固定挂载，到恢复完成为止。原因：Chromium 在部分后接时会在恢复前把视口跳约 950 px。

### 6. 验收标准

- Loading at least 10,000 mixed-height conversation rows keeps mounted `conversation-render-row` nodes at or below 500; the bound is independent of accumulated history length in either direction.
- Repeated older- and newer-page loads preserve one continuous scrollbar and the active row within 2 px after dynamic layout settles; there is no page swap or forced return to the newest page.
- Fast wheel scrolling, held-scrollbar dragging, jumping to newest, returning from an `around` locate window, and returning to an earlier reading position never show a blank area, duplicate row, reordered row, stale-page flash, replayed entry animation, or a scrollbar thumb that jitters under the pointer.
- Expand/collapse state of user questions, tools, diffs, and error details survives scrolling away and back, and Session switches.
- Expanding/collapsing, delayed Markdown/image/font layout, viewport resize, and live streaming preserve the intended anchor and remain immediately cancelable by real user input.
- Text selection and copy, keyboard focus, open menus, and screen-reader reading order survive window movement.
- Loaded-content Ctrl+F, search, and query navigation locate targets outside the mounted window, requesting SDK pages only for unread targets. Fork and rewind use the exact SDK turn target even when its row was initially unmounted.
- Active and queued Runs retain spinner, Stop, interactions, live tail, and observation recovery semantics while historical DOM remains bounded; Partner behaves identically.
- Packaged Windows, macOS, and Linux acceptance records DOM bound, heap trend, first paint, page-prepend latency, anchor drift, and long-scroll frame responsiveness; regressions fail the feature gate rather than silently falling back to full mounting.
