> 状态：持续演进

> 当前 Feature：PF001、PF002、PF003
> Space 映射：F146 <- PF001, PF002, PF003

## 1. 文档职责

本文是 Partner 详细产品需求的权威来源，回答 Partner 为谁服务、解决什么问题、提供什么能力，以及哪些事情不做。

本文不重新定义 Space 总体产品定位、共享技术架构、Partner Surface 的全局决策或 Space 正式发布状态；这些内容分别以 [Space PRD](../PRD.md)、[Space HLD](../HLD.md)、[ADR-007](../ADR/ADR-007-partner-surface-model.md)和[Space Feature List](../FEATURE_LIST.md)为准。

## 2. 产品定位

Partner 是 Space 中面向知识工作的工作面。用户可以围绕本地资料、网络信息和已授权连接器，与一个具备明确角色和能力边界的 Agent 协作，完成研究、写作、分析、整理和平台原生交付。

| 维度         | Coder                | Partner                        |
| ------------ | -------------------- | ------------------------------ |
| 主要对象     | Git 代码库           | 文档、数据、网页和外部业务资源 |
| 主要任务     | 编码、修改、测试     | 研究、整理、生成、分析和交付   |
| 证据要求     | Diff、测试、Verifier | 来源、引用、内容核验和回执     |
| 主要结果     | 代码变更             | 本地成果或平台原生资源         |
| 默认安全边界 | 编码工具与项目权限   | 受限工具、资料范围和连接器授权 |

Partner 不是新的执行内核。它在同一 KodaX Runtime 基础上组合 Partner Profile、工具策略、Skill、Artifact、专家和连接器能力。

## 3. 产品目标

### 3.1 Partner 工作面

- 用户可以用自然语言开始并持续推进知识任务。
- 任务资料、协作过程和成果保持可见且可恢复。
- 本地产出与平台原生产出使用真实、可追踪的结果表示。
- 普通用户不需要理解内部运行状态或插件实现细节。

### 3.2 插件库

Partner 通过可安装的插件包扩展两类能力：

- **专家**：角色说明、用途、提示词、示例任务及可选的现有 Skill。
- **连接器**：外部服务声明、账号连接、会话选择、资源范围和受控操作。

插件可以安装、启用、禁用和卸载，但不能因此获得任意主进程代码、凭据、文件系统或 IPC 权限。

### 3.3 Space 融合

- 复用 Space 的 Runtime、Provider、权限、会话和可观测性。
- 外部账号、CLI、OAuth、凭据和真实远端操作由 Electron 可信宿主管理。
- 共享接口采用明确、版本化的 IPC/Host Contract。
- Partner 能力不得改变 Coder 专属布局和执行语义。
- 进入 Space 前必须提供共享链路和 Coder 回归证据。

## 4. 目标用户与核心场景

| 用户                   | 主要需求                                 | 典型结果               |
| ---------------------- | ---------------------------------------- | ---------------------- |
| 产品、运营和管理人员   | 研究、PRD、方案、周报和协作资料          | 文档、报告、平台链接   |
| 研究和分析人员         | 多来源搜集、核验、总结和数据分析         | 带来源报告、表格和图表 |
| 内容和设计协作者       | 写作、演示、内容改写和结构化表达         | 文稿、PPT、可视成果    |
| 开发团队中的非编码工作 | 架构整理、发布说明、需求拆解和评审摘要   | 可交付知识文档         |
| 外部办公平台用户       | 读取指定资源并在授权范围内创建或修改内容 | 平台原生资源           |

## 5. 产品模型

### 5.1 Partner 会话

- 会话是任务、专家、连接器选择和结果的归属边界。
- 新会话默认不继承其他会话的专家或连接器。
- 恢复、重启和明确 fork 后保持自己的配置。
- 运行中的一轮使用固定快照，配置变化从下一轮生效。
- Coder 会话不接收 Partner 专属绑定。

### 5.2 专家

- 专家是 Partner 基础 Profile 上的产品化角色配置，不是新的 Agent。
- 一段会话最多绑定一个专家。
- 专家包含名称、说明、提示词和示例任务，并可配置零或一个现有 Skill。
- 用户显式选择的 Skill 优先于专家默认 Skill。
- 修改专家生成新版本，不静默改变旧会话。
- 插件缺失或专家不可用时必须明确显示，不能静默替代。

### 5.3 连接器

以下状态必须分开管理：

1. 插件声明连接器；
2. 用户连接账号；
3. 当前会话选择账号；
4. 用户授权特定资源范围；
5. 某项写入满足额外审核或确认要求。

“已连接”不能表示整个外部空间已经授权。连接器必须按平台真实支持的官方 CLI、OAuth、MCP 或受控宿主适配接入，不能把一种机制伪装成另一种。

### 5.4 可信宿主

- 凭据、OAuth 回调和 CLI profile 不进入插件 UI、提示词或普通日志。
- 前端状态不是授权依据，真实调用必须由宿主重新校验。
- 账号连接、会话选择、资源范围和写入权限逐层收窄。
- 连接失效、权限撤销、冲突或未知结果必须失败关闭。
- 插件页面只能通过有限、版本化的消息协议请求宿主。

详细实现见 [Partner HLD](HLD.md)，共享边界见 [Integration](INTEGRATION.md)。

### 5.5 结果与交付

- **本地成果**：报告、文档、表格、演示或其他可预览文件。
- **平台原生结果**：由连接器真实创建并返回的远端资源。
- **受审修改**：对已有远端资源的追加或修改方案。

用户明确要求平台原生交付且连接器可用时，不应静默用本地文件冒充。远端创建只有在宿主确认成功、完成必要核验并取得可信 canonical URL 后，才能显示为成功。

## 6. 核心用户流程

### 6.1 使用专家完成任务

用户选择专家后保留当前草稿；首次发送时绑定专家快照，后续回合持续生效。用户可以在下一轮开始前切换或移除专家。

### 6.2 使用连接器读取资料

用户通过可信界面连接账号并为当前会话启用连接器；宿主校验账号、会话和资源范围后，Partner 获得带来源的只读快照。

### 6.3 创建或修改平台内容

宿主根据连接、范围和操作能力进行风险路由：符合既定契约的低风险新建可以直接执行并核验；修改既有内容先展示方案并等待确认。成功后返回真实资源身份、标题和链接；`unknown` 或 `partial` 不自动重试，也不显示为成功。

## 7. 产品要求

### 7.1 交互

- 选择专家或连接器不得覆盖草稿或自动发送消息。
- 当前专家和连接器应在输入区域清楚可见。
- 资料、协作、成果和远端网页只在语义适用时出现。
- 错误信息应给出可执行的恢复动作。
- 插件被禁用或卸载后，核心 Partner 对话仍可使用。

### 7.2 安全与隐私

- 默认最小权限，密钥和 token 不进入 renderer、插件包、成果或普通诊断。
- 远端读取只限明确授权资源；修改已有资源需要审核。
- 删除、覆盖、权限修改、批量操作和后台同步不因提示词自动开放。
- 自动测试、fixture 和 UI 展示不得冒充真实账号验收。

### 7.3 兼容性

- 不新增第二套 Runtime，不复制或替换 Space Skill 系统。
- 不修改 Coder 专属业务逻辑来获得 Partner 能力。
- 共享 Shell、IPC、会话或主进程改动必须验证 Coder。
- 插件与宿主通过能力握手判断兼容，不能只猜版本字符串。

## 9. 当前范围与非目标

PF001–PF003 共同覆盖插件库、专家、连接器、可信宿主、受控远端操作、任务详情工作区和 Space/Coder 融合验证；各自的精确边界以 [Partner v0.1.0 设计](features/v0.1.0.md)为准。

当前不包含任意第三方主进程代码、通用插件市场、新 Runtime、Skill 系统重写、无范围账号访问，以及删除、覆盖、权限修改、群发或后台自动同步。Partner `v0.1.0` 的本地整理也不代表已经对外发布；公开安装包、Extension 分发、Git tag 或 GitHub Release 必须先满足仓库 `LICENSE` 及适用书面授权要求。

## 10. 成功标准

- 用户能稳定开始和恢复 Partner 任务。
- 专家按版本跨轮次生效且不串会话。
- 连接器授权、会话选择和资源范围彼此独立。
- 外部读取和写入具有真实来源、权限与结果证据。
- 本地成果和平台原生结果不相互冒充。
- 插件禁用、卸载、授权取消和失败路径可恢复。
- 自动化、人工验收和真实服务结果分开记录。
- 共享链路通过 Coder 回归并在 [Integration](INTEGRATION.md) 留证。
- 只有对应目标提交真实进入 Space 主线后，PF001–PF003 才可分别标记 `Integrated`。
