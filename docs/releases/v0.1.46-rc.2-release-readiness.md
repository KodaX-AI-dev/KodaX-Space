# v0.1.46-rc.2 release readiness

Date: 2026-09-22. Previous release: v0.1.46-rc.1.

## Scope

- Pin the exact published KodaX `0.7.96-rc.9` in root/Desktop manifests and the lockfile
  (`sha512-FQKt9sKnYVTDkLzpj0yQpymNViIdcxjbae1cZTiW6HsdcmFprDh151YQQd0ZGYy0zZLd2zQDYPnzJRhk7w/ptw==`),
  superseding rc.8. Every capability contract is retained (`sandboxRuntime:11`,
  `runtimeAutoModeGuardrail:6`, `sharedSessionSettings:2`, `providerCredentialBroker:2`,
  `effectiveConfig:1`, daemon `sessionCancellation:1` with durable frontier,
  `toolInvocation:1`): no Space capability gate moves.
- Issue 216 (Windows credential restoration, Shell usability and packaged diagnostics,
  tracked in [KNOWN_ISSUES.md](../KNOWN_ISSUES.md)):
  - Windows credentials use the Electron safeStorage/DPAPI-encrypted v1 vault first —
    no native keyring load is required to restore an existing vault or save new
    credentials. Legacy keyring accounts migrate per known Provider (custom Providers
    and shared aliases included); single-account failures do not degrade all accounts;
    migration-time stale reads cannot overwrite newer credentials or cancel deletes;
    deletion tombstones block re-import.
  - Existing Runtime identities keep clientId, instanceId, account and secret.
    Persistent read/write errors propagate; a replacement secret is never generated for
    an existing schema-3 identity; new/legacy identities publish only after a durable
    secret write/read succeeds. Concurrent first start, file alias protections, macOS
    prompt suppression and the Linux keyring fallback are preserved.
  - Windows Auto shell resolution probes a no-profile, side-effect-free startup and may
    choose CMD; the Agent shell contract, environment hydration and the PTY host consume
    one shared resolution. Explicit shell choices and profile-only failure semantics
    stay intact; SDK daemon PowerShell dependencies are not removed.
  - The packaged updater gains the missing `electron-updater` production dependency
    (6.8.3) plus the CommonJS default-export getter loading fix, protected by a
    packaged smoke probe that never invokes the updater or touches user caches.
  - Structured diagnostics redact cause chains (cycles and numeric DOMException codes
    included), child-process fields (env/argv/output dropped), and SDK payloads via the
    new log bridge; credentials, environments and command payloads are never logged.
  - rc.9 contains the originally approved diagnostic-only SDK additions plus the
    separately authorized daemon-state atomic-rename contention repair; rc.9 must not
    be described as diagnostic-only.
- Synchronize workspace versions, changelog, READMEs, capability ledger, product/
  architecture/usage docs, user manual, feature list, `docs/features/v0.1.46.md`,
  kodax_manual (rc.2/rc.9 stamp with anchored contract test), KNOWN_ISSUES, and the
  [Issue 216 regression guide](../test-guides/ISSUE_216_0.1.46_REGRESSION_GUIDE.md).

## Remaining boundaries

The customer-specific lifecycle failure remains unconfirmed; this fix does not claim
that failure is resolved and does not remove the SDK's PowerShell dependency. Space
publication and customer-machine acceptance for Issue 216 remain pending until this
release ships and the customer verifies on the original profile. Pure configuration-type
extension commands remain CLI-owner-only; Partner Coder sharing, real external-account
acceptance, and automatic library replacement remain open from earlier readiness
records. FEATURE_275 long-term guarantees are unchanged.
