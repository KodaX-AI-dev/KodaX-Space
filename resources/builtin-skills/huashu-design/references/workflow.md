# 从需求到可用产物

本方法承接 SKILL.md 的范围和交付约定。开始前复用当前会话内容，已回答的问题、已选择的方向和已经给出的授权不再重复确认。

1. 确定本次交付格式、使用场景和必须保留的内容。只问会影响交付的缺口，能合理推断的选择注明依据后推进。
2. 读取相关设计系统、素材和参考。核对与本次任务有关的事实；缺少素材时说明占位或可行替代，不把所有任务变成固定调研清单。
3. 依据内容决定叙事、视觉层级、字号、密度和组件。构思问题供内部判断使用；用户要求比较方向时给适量真实预览，其余情况直接制作选定方向。
4. 在用户指定或项目适合的目录实现。已有文件局部修改优先沿用原结构，不为满足示例架构重写作品。
5. 检查实际渲染、关键交互和最终导出；修复具体问题后复验。没有相应能力的部分标明未验证。
6. 交付本次所需文件与简要说明。按需建议下一步，不默认增加发布、配乐、多格式导出或持久化学习。

只有新的关键取舍或授权缺口才需要等待用户。普通阶段转换、内部规划和已经确认的方向不设置审批门。短任务不强制产出 facts、brand、assumptions 或 direction-approved 等额外文件；长项目确需记录时放在项目内。
