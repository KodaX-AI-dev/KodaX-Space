# v0.1.46-rc.6 release readiness

Date: 2026-09-28. Previous release: v0.1.46-rc.5.

## Scope

SDK baseline updated on 2026-09-29; earlier dated verification records remain historical.

- Issue 216 follow-up driven by the field investigation of a Windows rc.5 machine
  ([docs/investigations/2026-09-28-runtime-credential-decryption.md](../investigations/2026-09-28-runtime-credential-decryption.md));
  the current KodaX dependency is pinned at `0.7.96-rc.14` with unchanged capability gates (see the rc.13/rc.14 follow-up sections below).
- Uninstall-safe AppData: the investigation confirmed the credential ciphertext lives
  in `.kodax/space` while the Electron `safeStorage` encryption key lives in AppData,
  so NSIS `deleteAppDataOnUninstall: true` could strand undecryptable credentials.
  Uninstall now preserves AppData (the Local State key and any existing credentials
  survive reinstall).
- Scoped Runtime credential self-heal (Windows only): when an existing Runtime identity
  secret fails decryption, Space reads the legacy Credential Manager candidate for the
  same account and verifies it against the SDK `host-tool-invocations.json` journal v1
  — exactly one fingerprint for the same `instanceId`, exact SHA-256 match, with
  symlink/hardlink/size-guarded reads (16 MB cap, `O_NOFOLLOW`). A verified candidate
  is re-encrypted with the current safeStorage, decrypted back as verification, the
  original vault bytes are backed up to `.before-recovery.json` (exclusive create), and
  the new ciphertext is installed through the existing conditional atomic replace;
  delete/save races, backup failures, and post-write verification failures abandon the
  recovery without touching the old vault. Wrong candidates, other `instanceId`s,
  multiple fingerprints, unknown journal versions, and missing or corrupt evidence fail
  closed. No replacement secret is ever generated; Provider API keys and machines
  without recovery material keep the explicit failure message. The journal is a
  compatibility reader for the rc.2 migration, not a new SDK public API; unknown
  formats fail closed.
- Terminal history errors: session history paging no longer treats a terminal
  `runtime_unavailable` as a transient startup wait — when the connection is
  `incompatible` (non-Partner surfaces), the pending workflow immediately shows the
  failure reason, marks in-flight workflows pending, and stops retry polling; Runtime
  readiness still triggers the normal automatic reload.
- Synchronize workspace versions, changelog, READMEs, capability ledger, product/
  architecture/usage docs, user manual, feature list, `docs/features/v0.1.46.md`, and
  kodax_manual (the anchored contract test now derives the expected Space/SDK stamp
  from the manifest's declared dependency, including the self-heal note), plus the
  updated [Issue 216 regression guide](../test-guides/ISSUE_216_0.1.46_REGRESSION_GUIDE.md)
  and the new investigation record.

## Qualification

- Isolated regression suites cover restart recovery, wrong candidates, other
  `instanceId`s, multiple fingerprints, unknown journal versions, missing/corrupt
  evidence, delete/save races, backup failure, and unreadable new ciphertext; the
  corrupted-vault JSON path remains bypass-proof. The credential lifecycle release
  gate (`scripts/test/credential-lifecycle.test.mjs`) covers the vault/keychain/
  identity chain end to end.
- Recorded during the 2026-09-28 integration: the focused paging + recovery suites
  passed 103 tests / 0 failures / 1 Windows symlink-permission conditional skip;
  typecheck and ESLint on changed files passed. Read-only verification against the
  actual field data returned `automaticRecoveryEligible: true` without modifying the
  production vault.
- The manual-topics contract derives the expected rc.6/rc.14 stamp from the declared manifest dependency and pins the scoped self-heal, so a future SDK bump cannot leave a stale expectation behind.

## Remaining boundaries

The self-heal runs only on source right now — this release is its first packaged
form; the customer machine's actual recovery has not been executed against production
data. Users whose legacy keyring entry or identity fingerprint evidence is gone cannot
self-heal and must restore their original encryption state or reconfigure. Provider
API keys never use this identity-fingerprint path. Pure configuration-type extension
commands remain CLI-owner-only; the Issue 217 native macOS acceptance, Partner Coder
sharing, real external-account acceptance, and automatic library replacement remain
open from earlier readiness records. FEATURE_275 long-term guarantees are unchanged.
