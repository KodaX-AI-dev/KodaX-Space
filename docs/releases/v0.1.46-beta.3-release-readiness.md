# v0.1.46-beta.3 release readiness

Date: 2026-09-14. Previous prerelease: v0.1.46-beta.2. Stable release remains v0.1.45.

## Scope and ownership

This beta integrates the existing Partner library into the organization Space distribution. A fresh profile receives the bundled library without a separate extension download. Users can choose experts and methods, retain the expert binding across Partner session restoration, and connect supported services with their own account and session resource authorization.

The library stays at `0.1.0`, with host API 4 and explicit capability requirements. Space root, Desktop, IPC schema, UI kit and lockfile move together to `0.1.46-beta.3`; KodaX remains exactly `0.7.96-rc.4`. Electron main owns extension provisioning, connectors and privileged operations. Partner keeps its embedded owner; this change does not migrate it into the Coder daemon or add Coder expert/connector UI.

Existing same-ID packages are preserved. Disablement and uninstall intent survive restart. This initial provisioning does not implement automatic replacement of already-installed library versions.

Shared fixes preserve SDK extension execution context, restore the Partner home materials panel, and retain executable node-pty helpers for both prebuilt and source-built installations. The user manual, in-app help and current architecture notes describe the same scope.

## Release procedure

1. Open the organization PR with user effects, ownership boundaries, exact commands, test results and remaining manual checks. Complete final-head PR CI and local package verification. Retain earlier platform installer evidence with its exact commit and limits.
2. Resolve code and review findings before merging; preserve the contributor author and verify the merged SHA belongs to main. The final correction only deduplicates identical macOS esbuild binaries; Windows/Linux packaging is unchanged. Final Intel size and all four release installers are mandatory gates in the tag workflow, rather than repeating a second manual four-platform build before that same tag build.
3. Tag only that verified commit as `v0.1.46-beta.3`. The existing tag-triggered release workflow builds all four platform targets and extracts the corresponding CHANGELOG section. Do not overwrite an existing tag or Release.
4. Verify the prerelease flag, Windows Setup/Portable and zip fallbacks, macOS Intel/Apple Silicon DMG/ZIP, Linux AppImage/deb, blockmaps and updater manifests. Record the workflow and Release links.
5. Keep `releases/latest` and documentation's stable-release label at v0.1.45. Beta users select beta.3 explicitly from all releases. Only record publication as complete when the Release and assets actually exist.

## User-facing limits

- A beta does not become the default stable download or automatically deliver Partner to stable-channel users.
- Connector catalog availability is not real-account acceptance. Account permissions, service-specific operations, remote receipts and content-verification state remain explicit. This release must not advertise every connector as production-validated.
- Coder sharing of Partner experts/connectors and automatic upgrades of an existing library are follow-ups.
- Existing beta.2 SDK limitations, including remaining FEATURE_275 guarantees and image-recognition observations, are not closed by this integration.
- Installers follow the project's current unsigned distribution model.

It exposed Windows-specific test fixture assumptions, a connector read/atomic-write race, one macOS expert-selection test timeout, a 206.94 MiB Linux AppImage and a 202.73 MiB Intel Mac DMG above the unchanged 200 MiB limit. These failures were resolved before the final candidate passed the full matrix.

The correction shares the existing connector transaction lock for reads and writes, adds concurrent-read and Windows replacement-gap regressions, makes fixture paths/archive targets explicit, waits for the expert dialog's successful host acknowledgement, and selects AppImage xz plus maximum macOS compression. node-pty prebuilds are limited to the target platform/architecture that its loader actually selects; the SDK native bundle remains byte-complete. Prior Windows/Linux and Apple Silicon installer evidence is retained at `b01290d5` in [run 34818499415](https://github.com/KodaX-AI-dev/KodaX-Space/actions/runs/34818499415); its Intel ZIP failure is documented below. The final correction `38cf0253` passed [CI](https://github.com/KodaX-AI-dev/KodaX-Space/actions/runs/34822660999), [three-platform smoke build](https://github.com/KodaX-AI-dev/KodaX-Space/actions/runs/34822661027) and local Mac packaging. The tag workflow then rebuilt and verified all four actual release targets, including the corrected Intel ZIP.

The second package candidate `b01290d5` passed Windows, Linux and Apple Silicon installer gates. Intel unit tests and its 184.80 MiB DMG passed; its 200.38 MiB ZIP still exceeded the 200 MiB limit. The final correction replaces only a byte-identical macOS esbuild CLI copy with a relative link to the retained native binary. Both entry points retain version reporting and TypeScript transformation, including after extraction from the actual ZIP. A differing CLI wrapper or absent native package is left unchanged. The SDK native bundle and size limit are unchanged.

Local correction verification: 88 release tests passed (including 3 new packaging regressions, with the main regression observed failing before the fix); lint and syntax checks passed. Apple Silicon DMG is 178.10 MiB and ZIP 192.46 MiB. All package checks, both physical esbuild entry points, SQLite, SDK workers and the complete native bundle passed. The first added direct-ASAR esbuild JS probe attempted an unsupported physical spawn path; verification now targets the two physical executable interfaces affected by this change. This does not claim direct-ASAR JavaScript API acceptance. Final-head PR CI and all tag installer gates have now passed; see the workflow and published asset links above and below.
