# v8 工作动作抖动排查

2026-10-17。用户反馈：「我看播放的时候怎么一抖一抖的，是不是帧动画，画的不够连续平滑，还是中间帧很奇怪？」

结论：确实存在原画与相邻帧连续性问题，并叠加一处明确的制片定位错误。本轮只诊断和记录，不重绘原画、不修改运行图集或播放代码，不将当前版本标为已修复或自然顺滑。

## 可重复复现

```powershell
node artifacts/companion-working-v8/diagnose-continuity.mjs --check
```

该命令直接读取工作区正在使用的 `working-atlas.webp` 和 `frames.json`，提取小狗最大连通主体，检查开头两个坐姿之间的横向跳位。重复运行均为退出码1；首个坐姿跳转的主体像素质心横移约−10.25px，超过诊断中2px的警戒值。这个警戒值用于锁定已观察到的跳位，不是自动判断整段动画美术质量的标准。

报告：[逐帧几何数据](../../../../artifacts/companion-working-v8/continuity-report.json)、[失败输出](../../../../artifacts/companion-working-v8/continuity-red.txt)。位置单位均为运行图格的112px坐标；像素质心是画面测量，不是动物物理重心。

## 已确认的原因

1. **道具影响角色定位。** `build-working.mjs` 的 `normalize()` 对整张非透明包围盒重新居中，包括地上的任务卷。第一张起身原画中，小狗包围盒中心为169，带卷轴包围盒中心为199.5；按实际比例折算，会把小狗向左推约9.85px。这与图集测得的约10.25px跳位吻合。后者还包含原画本身细小的轮廓差异。
2. **过渡跨度过大。** 4.125s的cel62到4.1875s的cel63，单帧间主体轮廓高度从64px变为81px，主体质心上移约7.13px。浏览器逐帧看得到由低头检查直接跳到撑身抬头，中间姿态不足。5.0625s附近另有约16px的单帧高度变化；剔除瑕疵帧而没有补齐合适姿态，会加剧这种问题。
3. **多批原画接缝与造型漂移。** 起身、主故事、趴下、坐回来自不同批次原画，采用不同固定缩放系数后拼接。它们的头身、轮廓和细节没有达到连续动画需要的一致程度。结尾cel88到原中性cel0，一帧间主体宽度减少7px、高度减少5px，存在可见的收缩换形。固定底线和更多帧数没有解决这些差异。

## 浏览器确认

在用户正在看的完整工作区暂停后，通过时间轴Home和「下一帧」精确定位，而不是依赖播放计时。

- 0.2500s → 0.3125s：验证开头角色横移与卷轴出现同时发生。
- 4.1250s → 4.1875s：验证检查到回应的一帧姿态突跳。

两组均是相邻一帧，间隔62.5ms。源帧离线检查和浏览器手动逐帧都能复现，因此这些跳变不需要浏览器性能下降或实时漏帧就会发生。本轮没有做完整浏览器帧时序分析，不将所有可能的计时抖动一并排除。

[实际逐帧截图对照](../../../../artifacts/companion-working-v8/jitter-actual-pairs.png)。原始全工作区截图也保留在同一目录，未以重新绘制的UI代替证据。排查结束恢复原速播放。

## 修订门槛

应按角色的稳定解剖锚点注册画面，道具不参与决定角色位置；统一原画角色比例及各批次接缝；对抬头、趴下、撑起等跨度大的地方重画真正的中间姿态，并核对运动轨迹和速度变化。提高帧率、复制同一张图或交叉淡化不能替代这些修正。

此前19项检查验证了打包、状态、计时与资源行为，没有验证美术连续性。上一轮把机制通过及动作内容完整视作动画观感合格，复审结论应撤回。当前v8未达到用户要求的自然顺滑标准；正式产品没有替换。
