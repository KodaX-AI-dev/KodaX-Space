# v0.1.47-rc.4 release qualification

日期：2026-11-28。用户指定 Space `0.1.47-rc.4` 预发布；SDK 为 npm Registry `@kodax-ai/kodax@0.7.97-rc.4`（自 rc.2 的 rc.2 升级，含 rc.3 与 rc.4 两个 SDK 版本），四个 workspace 与 lockfile 统一 Space 版本。稳定版保持 v0.1.46，不向正式版自动推送预发布。原计划的 rc.3 没有打 tag，也没有发布，其准备内容并入本候选；已发布的 rc.2（SDK rc.2 构建）及更早 beta/alpha 记录保留为上一轮发布历史。

## 发布范围

- SDK `0.7.97-rc.4` 接入。rc.3 让 `mcp_call` 按目标工具的注解执行：server 声明为只读（`readOnlyHint` 且未声明 destructive）的 MCP 工具在 Plan 和“接受编辑”下直接执行，Coder 与 Partner 规则相同，其余 MCP 工具在“接受编辑”下需要确认、Plan 下不执行，“始终允许”覆盖该工具的任意参数。MCP 调用默认 300 秒超时（server 有进展时重新计时），停止 Run 时在 server 上取消；server 配置支持 `enabledTools` / `disabledTools`，`.mcpb` 升级保留用户设置的这两项；`mcp_search` 行带参数签名，`mcp_describe` 一次最多 10 个 id；只读内建工具失败时不再代为运行同名 MCP 工具；列出多个独立修复的请求通常每条修复一条 writer lane。
- Windows 沙箱 setup（F143 流程；Issue 258，SDK Issue 448）。rc.4 只改这一处：整个 setup 只请求一次 UAC（替换旧沙箱账户时也一样，过去要三次），等待提示有独立的 10 分钟计时，稍后批准不再失败，第二个调用方等待并复用正在运行的 setup（不再 35 秒后失败），中断的 setup 以 `[windows_setup_interrupted]` 报告，`activateKodaXSandbox()` 的结果带稳定的 `code` 与 `onProgress` 阶段。Space 侧：setup 在独立子进程中执行（`sandbox-setup-process.ts`，90 分钟上限只是兜底），主窗口不再卡死；SDK 的 `code` 映射为本地化原因（UAC 超时、另一个设置仍在进行、沙箱账户忙、原生文件缺失或被拦截、批准后某步失败、ACL 清理未确认、设置在完成前中止），原始错误与 SDK 警告写入诊断日志；阶段经新增的推送通道 `sandbox.setupProgress` 显示在卡片上；Windows 需要 setup 时，启动几秒后右下角卡片提供“现在设置 / 以后再说”，中途停止的 setup 以“完成设置”再次提供。
- 视频审阅：安装 ffmpeg 时 Artifact 工具可以采样 GIF、动态 WebP 与 MP4 / MOV / WebM（`artifact_capture` 的 `kind: 'temporal'` 返回指定秒数的 PNG 帧，采样不算连续播放）。`space-artifacts` 只从固定安装位置解析 ffmpeg（Windows：`Program Files\ffmpeg\bin`、winget 链接、Chocolatey / Scoop shim；macOS：Homebrew；Linux：`/usr/bin` 或 `/usr/local/bin`），不从 PATH 或工作区查找；没有 ffmpeg 时视频保持未验证。
- Windows 原生沙箱辅助程序（Issue 257）：SDK 不再通过 PowerShell 写入受保护的 `kodax-windows-sandbox.exe` 副本；写入后被安全软件移除时以 `native_artifact_removed_after_provision`（`retryable: false`）一次性失败，不再消耗自动重试。启动失败原因包含 native artifact 时，启动横幅提示安全软件可能拦截或隔离了该文件，并说明需要信任的目录。
- 文件查看器：无法预览的文件（超过大小上限、无法读取、解析失败、不支持的媒体编码）显示“用系统默认应用打开”。新增 `shell.openFile` 通道，只放行允许列表目录内的常规文件和固定的文档/媒体扩展名，拒绝可执行文件、快捷方式、HTML/SVG 与可启用宏的 Office 类型；`shell.openPath` 仍不对任意文件开放。PDF 查看器的“上一页”恢复生效。
- 长对话中途打开的实时视图：窗口在某轮中间打开时，历史边界说明本轮提问在历史消息中，首个提问之前的工具组显示“至少运行了 N 个命令”。
- 安装包瘦身：不再随包发布 `huashu-design` 内置 Skill（约 37 MB），排除 `@napi-rs/canvas`（约 36 MB）与未使用的 `pdfjs-dist/legacy`；安装包排除规则作用于应用自身构建产物，渲染层生产构建不再输出 source map。Windows 安装器 215 MB → 157 MB。
- Linux x64 包兼容 glibc 2.28：发布工作流在 `quay.io/pypa/manylinux_2_28_x86_64` 容器中重编译 `better-sqlite3` 与 `node-pty`，`scripts/check-linux-glibc.mjs` 校验包内全部 ELF 不引用高于 `GLIBC_2.28` / `GLIBCXX_3.4.25` / `CXXABI_1.3.11` 的符号。Anolis OS 8.10 等 RHEL 8 家族系统没有 `dpkg`，请使用 AppImage 并安装 `libX11-xcb` 与 `fuse-libs`。
- 文档：README、文档索引、Feature List、版本设计（`v0.1.47.md` 新增沙箱 setup 小节，`v0.1.35.md` 的 F143 设计加注）、DD、HLD、PRD、USAGE、内置 Skill 说明、用户手册、已知问题与能力台账随 rc.4 更新。应用内 `space_manual` 的 `runtime-host`、`settings`、`install`、`preview-terminal`、`sessions`、`mcp`、`troubleshooting` 主题覆盖上述说明，SDK 自有 `kodax_manual` 不被覆盖。新增人工测试指导 [F143 v0.1.47](../test-guides/FEATURE_143_v0.1.47_TEST_GUIDE.md)，F143 v0.1.35 指南顶部指向它。Issue 257、258 的 Space 修复随本版发布，客户环境的确认仍待完成。

- 打 tag 前在同一 SHA 上确认发布准备提交的 GitHub `ci`（Windows / Linux 各两个 E2E 分片）与 `build`（四平台 smoke、静态检查与门禁）全部通过；release 的源码资格检查只接受同一 SHA、全部 job 成功的运行，文档跳过不算数。

- 最终 SHA、运行链接、平台结果与资产校验记录在发布后补记的验证文档（`v0.1.47-rc.4-release-verification.md`）。该记录未确认的项目不得以源码通过替代。

## 保留边界

- Windows 沙箱 setup（Issue 258）：客户机器上的真实 UAC 验收待完成，SDK 变更日志同样列为待办。卡片没有自动化界面测试（e2e 夹具在每次启动时预先写入“以后再说”，不让它盖住其他用例的控件），人工用例见 F143 v0.1.47 指南。已知待打磨：设置页确认框仍写“可能显示一次 UAC 提示”，与新的 setup 说明不一致；`elevation_cancelled` / `setup_failed` 归入通用的“设置在完成前中止”；部分沙箱诊断在简体中文界面仍为英文；点过“以后再说”后启动卡片不再出现，即使之后升级再次需要 setup（入口保留在设置页）。
- Issue 257 的 SDK 修复随本版发布，但尚未在装有客户安全软件的机器上确认。
- macOS ad-hoc 不等于 Developer ID 或公证，首次启动仍可能有 Gatekeeper 提示；通知/图标角标需要系统权限，macOS 仍手动下载 DMG 更新。Windows 安装器未签名。
- Issue 371 首次历史读取延迟仍未关闭；Issue 254（Run 期间历史翻页重复/乱序）推迟到下一大版本；Issue 256（macOS 上关闭转录搜索后回到顶部）的修复不在本版；Full / Light 模式的首次路由耗时（Issue 213）未在 rc.4 重新测量。
- Linux glibc 2.28 兼容性目前由发布流程中的静态 ELF 符号版本校验保证：rc.4 包尚未在 Anolis OS 8.10 实机或虚拟机上运行验收（SQLite 目录、内置终端、keyring、ASRT、GPU 加速与 Wayland），UOS、麒麟等系统的实机验证同样待完成。这类系统还需要 `libX11-xcb`、`fuse-libs` 和非特权用户命名空间，缺少后者时 AppImage 会以 `--no-sandbox` 启动。
- ffmpeg 视频审阅依赖用户自行安装的 ffmpeg，Space 不随包提供。
- 外部账号、真实模型质量/计费、覆盖安装/断电、客户 Kylin/真实 Mac 权限设置仍需对应环境验收。
