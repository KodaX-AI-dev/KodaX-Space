# F146 首批多连接器双轴评审

日期：2026-09-01。范围：独立插件库 0.6.0、三个新官方 CLI 的授权及指定资源只读、宿主会话边界和配套 UI。其余六家、远端写操作、共享 Skill 与 SDK 不在本批范围。未纳入用户原有的 shell/ChipBar 改动及应用图标。

## Standards

独立评审者检查了规范、安全边界、共享安装/进程基础设施与宿主改动。原评审者本人编写的腾讯会议 adapter 不计入该轮独立覆盖。

发现并处理：

1. **高：复用 native 或等待异步权限检查后缺少最终完整性复验。** 三家均加入固定大小与 SHA-256 验证；原异步权限/身份检查后重新验 hash，并在最后同步 guard 后立即验文件元数据，然后无 `await` 地分派。篡改 fixture 从 RED 到 GREEN；腾讯会议与企业微信修复随后由非作者独立只读复核，相关 25 条测试通过。钉钉由主任务复核修复与 14 条 adapter 测试。没有宣称这是操作系统级原子 `fexecve` 保证。
2. **中：adapter 接受的正文/标题可能超出宿主持久化契约。** 新增统一 `checkReadConnectorDocument`，三家 adapter 与宿主保存前均校验 128 KiB UTF-8 / 280 字符，超限明确拒绝，不截断；新增中文多字节、精确边界与超限测试。

当前无已知未解决 Critical/High finding。源码和受控测试不能代替真实账号、上游服务或企业权限验收。

## Spec

另一评审者独立检查批准范围、飞书兼容、只读分派、会话绑定和授权取消。该评审者本人编写的钉钉 adapter 不计入该轮独立覆盖，由 Standards 与主任务补充检查。

发现并处理：

1. **高：企业微信在 `beforeRead` 前调用同步 `assertRead`，被真实宿主拒绝。** 移除提前 guard；保留真正业务进程分派前的异步授权与紧邻 spawn 的同步检查。实际 adapter + service 组合测试先 RED 后 GREEN。
2. **高：企业微信返回内部引用，和调用者已授权的官方 URL 不一致。** 校验上游文档 ID 后保留原始、已校验的输入引用；分别覆盖内部引用与官方 URL。
3. **高：钉钉原安装器 inventory 不匹配官方归档中的 `./` 目录头。** 用实际归档目录编写失败测试，共享安装器仅允许显式列出的 type-5/size-0 目录，且不将目录条目落盘；真实官方归档静态解析、固定摘要验证与临时原子发布通过，未执行 native。
4. **中：文档仍将用户已同意的路线写成等待确认。** 当前状态已改为批准、首批实现与其余待实施；保留历史核查记录并明确其时间边界。

最终独立补充检查确认：最终分派 guard 无新的阻断项，正文大小检查确实接入三家 adapter 和宿主保存路径。新三家只有明确资源只读，不能借用混合飞书会话的写工具；旧飞书记录缺省 adapter 的兼容保留。
