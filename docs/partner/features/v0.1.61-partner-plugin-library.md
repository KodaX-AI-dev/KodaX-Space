## 1. 需求概述

### 已确认的产品边界

- Partner 左侧“新对话 / 文件”下面增加“插件”，库内只有“专家”和“连接器”两个分类。
- 专家是角色名称、用途说明、场景提示词和创建者可选配置的 Skill 的产品化组合，不是新的 Agent 执行引擎。
- Skill 仍是 Coder / Partner 共用的能力。保留现有技能库、入口、发现、调用和权限逻辑；不增加技能分类、安装器、自动匹配、推荐、替代或“Skill 引用解析”宿主服务。
- 专家没有配置 Skill 时，只增加专家提示词，不额外处理 Skill；这不关闭 Space 原有的独立 Skill 能力。
- 一段 Partner 会话最多一个专家，可选择多个连接器。专家对后续每轮对话生效，不是只给第一条草稿填入模板。
- 连接器通过每个平台实际支持的官方 CLI、MCP 或宿主适配接入第三方系统；账号连接、当前会话选择、资源范围和写入授权是不同状态，不能相互冒充。
- 输入框展示当前专家和连接器。资料、待审核、成果和本地 Artifact 只在各自语义适用时出现；低风险远端新建以聊天中的真实链接和右侧原生网页为主，不强迫用户经过这些中间栏目。
- 插件库整体必须位于可独立安装、禁用和卸载的 Space Extension 包，不能仅成为带开关的内置页面。

### 本轮计划采用的最小范围

- 第一版允许专家配置零或一个明确的现有 Skill。当前显式调用会拒绝同条消息中的多个 Skill；不为本功能改写该共享规则。多 Skill 组合不作为本期已解决能力。
- 第一包由本项目提供，携带前端资源和专家 / 连接器声明；不开放插件市场、任意主进程代码、安装脚本或 SDK filesystem hooks。
- 先贯通一个纯提示词专家，再迁移现有八个场景预设、添加专家编辑和可选 Skill 配置，随后接入连接器读写。
- 远端第一期支持能力已确认的文档读取、低风险新建和受审修改。新建个人空间文档或在本轮已授权目录新建文档可以直接执行；修改既有文档仍需差异审核。删除文档、覆盖、改变共享权限、群发和后台自动同步不在本期范围。
- 用户明确指定远端平台时不得静默生成本地文件或 Artifact；连接器未启用、未授权或失效时应给出准确的启用 / 授权恢复动作，并保持用户指定的交付目标。
- 不改 Coder 布局、运行时所有权、共享 Skill 机制、模型选择和现有权限底线。

## 3. 技术方案

### A. 可独立投放的包与最小宿主

- 包内包含版本化 manifest、预编译 UI 静态资源、专家提示词、连接器声明和普通资源，不含 main / preload 入口、安装脚本或 Skill 安装内容。
- UI 在隔离的浏览器 frame 内运行，通过有限、版本化的消息桥请求宿主；不与可信主 renderer 同源加载任意模块，不获得 Node、完整 IPC、账号 token 或任意文件权限。
- 扩展资源限制在经验证的包根目录，校验大小、入口、路径穿越、符号链接、资源完整性和兼容版本。完整性 hash 不能被描述为发布者身份认证。
- 安装只校验并登记，不自动连接第三方服务。启用后才挂载导航 / 页面 / 声明；所有注册和请求都带扩展归属并由主进程校验。
- 新增宿主自有“设置 → 扩展”管理入口。即使插件库卸载，该入口仍能重新安装包。
- 独立前端加载只是 UI 宿主，不新增 Agent 执行引擎，不开启 SDK 任意代码扩展总开关。
- 声明可组合已支持的连接器工具；新原生适配能力不能仅靠 manifest 伪装成已经支持，需另行增加受审适配或使用实际具备该能力的 MCP 服务。

### B. 专家、草稿与会话

- 选择专家先绑定当前 Partner 草稿，不覆盖草稿、不自动发送、不隐式新开或清空已有会话。
- 首次发送时，主进程按已启用包中的专家 ID / 版本解析配置并持久化；前端不直接提交权威系统提示词。
- 每轮执行读取会话配置，组合“Partner 基础 profile + 专家配置”，保留基础验证与权限。读取历史、重启和上下文压缩后仍能恢复该绑定。
- 专家更改 / 移除在下一轮生效并可见；运行中的一轮固定其配置。新建其他会话不自动继承；显式 fork 按原会话继承配置。
- “下一轮”按实际开始执行划分：after-turn 排队消息在新一轮开始时读取已成功保存的专家；仍由 SDK 在当前轮消化的 interrupt 消息保持当前角色。保存尚未完成时不能提前让新配置生效。
- 修改专家定义产生新版本，不悄悄修改旧会话角色。旧会话缺少扩展或专家时显示不可用状态，不静默使用已经卸载的提示词。
- 专家编辑只管理名称、说明、提示词、示例任务及可选的一个明确 Skill 配置。预置专家编辑为用户副本，不修改共享 Skill 或已安装包的只读资源。
- 配置 Skill 后沿用既有调用准备和拒绝规则；缺失、项目不可用或权限不支持时明确提示，不搜索替代、不自动安装。用户仍可独立使用原 Skill 入口。
- 现有 SDK 的动态上下文在 Partner 中禁止执行命令；它可能将正文替换成“host 禁用”占位后继续模型回合。本插件保留此语义，不新增整轮拒绝规则，也不能把占位当成动态命令已执行。hook/fork 等继续各自现有拒绝路径。
- 专家默认配置与用户本轮显式 Skill 选择冲突时，以用户显式选择为准，该轮不叠加第二个 Skill；下一轮恢复专家默认配置。缺失 Skill 的降级需用户明确选择仅按角色继续，不能显示为技能已成功执行。

### C. 连接器与远端文档

- 分开保存连接器声明、账号连接状态、会话绑定和文档范围。账号已连接不会给其他会话授权全部知识库。
- 从当前会话发起连接，完成账号授权和范围确认后添加输入框标签。移除标签仅解绑本会话；断开账号和卸载扩展是独立操作。
- Partner 输入框“＋”菜单的连接器悬停面板从已启用插件读取连接器声明，稳定地将已连接服务排在未连接服务之前，最多展示八个。已连接服务提供本会话开关；未连接服务的“连接”和底部“更多”进入插件库连接器页。关闭本会话开关不删除账号连接，也不等于全局断开。
- 凭据使用宿主保管的引用，不能进入插件 UI、提示词、普通配置、日志和成果；SDK 原有全局 / 项目 MCP 配置不能被插件安装隐式覆盖。
- 模型只能看见本会话允许的连接器工具；实际调用也必须校验同一权限，不以提示词、UI 状态或 MCP 工具自报只读作为授权。
- 读取的文档带来源、明确文档身份、获取时间和可用版本信息，显示在“资料”；文档内容是证据，不是角色指令或授权。
- 远端写入按风险路由：创建全新飞书文档可在完整请求下直接执行；追加或修改既有文档继续按“生成方案 → 待审核 → 用户确认 → 后端提交”执行；删除、覆盖、权限与批量操作不因提示词而获得能力。只有后端结构化回执确认成功才能显示已写入。
- 远端提案绑定账号 / 会话 / 扩展、目标文档、操作、具体内容 hash 和可用基础版本。P8 后它仅用于既有资源的追加 / 修改；历史新建提案只为存储迁移和审计保留，不再展示、自动打开或提交。确认只覆盖追加提案，执行时重验授权、包状态与目标，不允许模型代替用户确认。
- 直接创建任务必须在提交前持久化并绑定账号、会话、扩展、连接 revision、目标目录、规范化标题 / 正文和输入 hash；提交前后重验授权。`unknown` / `partial` 不宣称成功、不自动重试，避免重复文档。
- 重复提交、权限撤销、版本冲突、超时及结果不确定有明确状态；能力不支持时不承诺版本锁、自动回滚或盲目重试。
- 账号断开后立即禁止新的远端调用。已保存引用和结果只按现有访问 / 留存策略展示，不因界面开关隐式删除或重新授权。

### 与既有规划的关系

这是当前 fork 的明确新增 F146，不将 F096 的未来连接器规划或 F102 的通用 slot registry 标记为已经实现。F146 复用 F096 关于账号、范围、来源、撤销的约束；插件入口和受审远端写入采用本次用户确认的新产品边界。只补本库实际需要的挂载点，不重启完整通用插件平台规划。F137 / F139 的既有范围和实现状态不变。

## 4. 接口契约

以下是已确认的五组职责；各阶段通过契约测试逐步交付，不将后续未实现能力当成已有 API：

| 接口组         | 最小职责和边界                                                                                                              |
| -------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 扩展生命周期   | 安装、列出、启用、禁用、卸载；manifest / 宿主协议兼容；所有能力按 extensionId 归属                                          |
| UI 挂载        | Partner 左侧入口、插件库视图、输入框标签和现有右侧详情；固定消息类型，不提供任意 invoke 或任意系统路径                      |
| 会话配置       | 获取 / 更新 / 订阅专家和连接器绑定；草稿转会话、配置版本、每轮快照、恢复 / fork / 删除；Coder 不接收 Partner 绑定           |
| 连接与调用     | 授权状态、凭据引用、连接 / 断开、会话选择和工具范围；本轮飞书使用官方 CLI 适配，既有 MCP transport 不变，主进程执行权限检查 |
| 文档执行与审核 | 资料引用、低风险新建任务、远端修改提案、人工批准 / 拒绝、执行与回执；直创成功打开真实网页，区分本地文件与远端资源           |

最低数据约束：

- ExpertDefinition：稳定 ID、extensionId、revision、名称、说明、prompt、可选 skillRef、示例任务，以及仅用于目录展示的 expertType / category / listingType。平台专家还可声明只读 capabilityGuide，以两级分组展示任务入口；每个入口只引用同包连接器并生成可编辑 prompt 草稿，不自动发送、不授予工具或写入权限。没有 skillRef 时不增加专家专用 Skill 操作；目录分类和引导均不增加权限或编排能力。
- SessionBinding：sessionId / surface / project identity、revision、可选 expertRef、显式 connectorBindings；不包含密钥；后端按实际账号授权和包状态收窄能力。
- RemoteProposal：operationId、extensionId、sessionId、connectionRef、resourceRef、append、不可变内容摘要 / hash、可用 baseVersion、审核与执行状态；兼容读取已有 create 提案。本增量不新增任意 update / overwrite 操作。
- PartnerNativeDocumentTask：稳定 taskId、provider / adapter、session / extension / connector / connection 归属、connectionRevision、提供方自有的可选授权目标、规范化 title / content、inputHash / scopeHash、`preparing | submitting | succeeded | failed | unknown | partial` 状态，以及仅在成功时出现且相互匹配的 resourceId、真实 title 和 canonicalUrl。飞书、钉钉、腾讯文档适配器共享任务、状态、通知和右侧打开契约；各提供方的创建参数、授权范围与回读校验仍由独立受控适配器负责。模型输入不接受任意 CLI 参数、凭据或未经授权的目标。
- Bridge 请求必须校验实际 frame / 包 / 会话归属、允许操作、有效长度和当前权限；不能信任消息正文自报的身份。返回值和日志统一脱敏。

## 5. 实现步骤

用户已确认按以下顺序开发。P1–P6 同时作为实现票号，后续票依赖前一票的接口；同一票的独立前后端适配可并行，验收不以界面文字替代实际运行。正式 seam 与本地验证记录见下。

| 阶段                     | 可交付闭环                                                                                                          | 进入下一阶段前的检查                                                                           |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| P1：真实扩展包           | 单独构建一个最小包；设置中安装、启用后出现“插件”及真实扩展视图；禁用 / 卸载后撤下，宿主可继续使用                   | 无包时开发 / 打包 / 启动正常；不向扩展暴露主 frame IPC；停用阻止新请求；卸载后可重新安装       |

#### 技术接缝

1. **Partner 基础 profile。** `partner-profile.ts` 先识别交付目标，指定平台的专用连接器优先于通用 delivery / Artifact；验证契约检查 `destination-fidelity`、`connector-result-truthfulness` 和 `no-silent-fallback`。该定向修改及回归测试已经完成，但单独不能产生直创能力。
2. **Typed task。** 在 `partner-connector` schema 增加通用 `PartnerNativeDocumentTask`，并把 task 摘要纳入 `PartnerRemoteRecords`；飞书首适配另有仅含可选已授权 folderUrl、规范化 title 和有界 content 的 provider input。connectionId、选择凭证和 invocation identity 均由宿主解析 / 注入。task 同时承载命令状态和验证结果，不生成要求 proposalId 的 legacy receipt；只有经 schema 校验并由对应 provider adapter read-back 成功的 `succeeded` 才能携带匹配的 resourceId、title 与 canonicalUrl。
3. **账号 eligibility。** 宿主投影非敏感 `PartnerDocumentCreateEligibility`：状态、枚举 reason、recoveryAction，以及需要选择时来自 live bindings 的 connectionId / accountLabel / connectionRevision 候选。0 个 eligible binding 时工具隐藏但 run context / UI 能区分未连接、扩展禁用、需重授权、缺 create/read scope 和宿主升级；1 个由宿主解析；多个时按安全 accountLabel 生成可信账号选择器，用户选择写入绑定 session、connectionId、connectionRevision 的 host-owned 记录后才可执行。自然语言、模型 tool args、列表顺序和最近使用都不能生成选择证据，binding 变化会使选择失效。
4. **持久化与一次派发。** store 从严格 v1 原子前迁移到 v2，加入 documentTasks、唯一 invocation key 与单调 record revision，保留旧 proposals / receipts / Base tasks。`PartnerConnectorService` 复用 Base 的 `preparing → submitting → terminal`、dispatch-owner、connection revision、scope hash 和提交前重验模式，调用现有受控 `FeishuCli.create`。每个 admitted 顶层输入在 runtime 构建前取得稳定 `turnExecutionId`：pre-admission retry / reconnect 沿用，interrupt 留在当前 ID，after-turn 下次 admission 才换新 ID。账号和目录解析后以 session、turn、resolved connection + revision + scopeHash、canonical target 和 normalized title/content hashes 组成 key；相同调用返回同一 task，CLI 至多派发一次，不同账号 / 内容 / 新 admitted turn 不碰撞。遗留 `preparing` 收敛为 `failed/not_dispatched`，死亡 owner 的 `submitting` 收敛为 `unknown`，均不重试。
5. **严格后置校验与目标证据。** `FeishuWriteResult` 没有 title，因此 task 内部 postcondition reader 只能对本次严格 create receipt 返回且 ID 匹配的 exact URL 使用同一账号和 readonly scope read-back；它不需要 URL 预先在 `binding.documents`，不创建 RemoteSource / Materials，也不扩张模型后续读取权限。reader 识别官方 Markdown 导出的 `<title>…</title>` 包装或 H1 标题，解码基础实体；title/body 均 NFC、CRLF→LF、去行尾空白，正文对比忽略导出器插入的纯空行但保持所有非空行内容和顺序。派发前错误=`failed`；派发后无可信 ID/URL=`unknown`；有可信身份但 read-back/后置条件不完整或不匹配=`partial`；全部匹配=`succeeded`。官方 CLI 暂无 parent metadata，因此目录证据明确来自已持久化 canonical target、live scope 重验和固定 `--parent-position my_library` / exact `--parent-token` argv；自动测试核对 argv，真实账号验收核对页面位置，不冒充远端 parent read-back。
6. **Run-scoped 工具与握手。** 首个适配增加 `partner_feishu_document_create`，仅在 Partner、非 Plan、`hostApiVersion >= 4`、宿主和扩展都声明通用 `partnerNativeDocumentDeliveryV1`、飞书 action enabled，且账号 eligibility 已解析时出现。列出后发生撤权 / revision 变化，在派发前返回结构化可恢复失败。工具只由 `createPartnerConnectorRunRuntime` 临时物化且不写 SDK 全局注册表，service 再断言 Partner surface。后续钉钉、腾讯文档用各自 provider tool/action，不改通用 delivery capability。本次最小发布组合是 v0.1.61-p.1 / library 0.9.1；未来版本仍按 capability 而非精确 SemVer 判定。
7. **兼容但不可执行的旧提案记录。** `partner_connector_propose`、proposal mutation IPC 和 `service.propose` input 全部 append-only；持久化 record/output 继续识别 `create | append`，避免旧数据库升级失败。历史 create 提案不进入待审核列表、不触发 opener，apply 会收敛为 rejected 且 0 dispatch；升级后不存在新造或执行 legacy create proposal 的 seam。
8. **Partner 专家路由。** 仅更新飞书平台专家 prompt、starter task 和 capabilityGuide：把“新建文档”路由到直创工具，把“追加 / 修改”保留在审核链。共用的 `feishu-office-suite` Skill 不作任何修改。用户说“随便写一份 / 你决定”时可推断标题和内容；专家 revision 随定义变化递增，旧会话继续保留不可变快照。
9. **直接打开平台原生资源。** `usePartnerRemoteRecords` 消费宿主 / store 所有的单调 revision + documentTaskId signal；provider-neutral direct-task opener 只挂载在 `PartnerWorkspace`，对 hydration 后首次发生的 `succeeded` 转换生成 open intent。它不判断飞书、钉钉或腾讯文档的登录态，也不渲染本地文档，而是把经过对应适配器验证的 HTTPS canonical URL 交给同一个 Partner 右侧浏览器；未登录时自然显示该平台官方登录页。旧 create-proposal opener 及其投影已删除；历史、失败、unknown、partial 不打开。
10. **简化可见流程。** 直创任务保留宿主侧最小审计记录，并在成功后登记为“任务产物”；正常路径不创建 RemoteProposal / RemoteReceipt、本地 Delivery / Artifact，也不进入 Pending review。任务信号会直接打开右侧平台网页；“任务产物”卡片预览与其展开后的完整列表读取同一份 `documentTasks`，点击后用相同 provider/resource 键复用右侧网页标签。既有资源的审核后追加回执也归入该完整列表；内部 taskId、hash、CLI 命令和凭据不展示给普通用户。
