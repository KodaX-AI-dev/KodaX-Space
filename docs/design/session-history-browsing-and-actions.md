# 共享 Coder 会话的历史浏览、搜索、Fork 与回退

**已接入 Registry SDK beta.4 · 2026-11-09**　本文记录 Space 桌面端共享 Coder 会话与配套 KodaX SDK 的设计约定。开发构建、Windows 桌面包、旧 Host 的兼容表现及性能测量见[实施验收记录](../test-guides/ISSUE_237_0.1.47-alpha.4_REGRESSION_GUIDE.md)。正式 SDK 的安装和成品结果见 [beta.3 接入记录](../releases/kodax-beta3-space-adaptation.md)。

## 一、用户体验

### 1. 打开会话

进入会话，先看到最近的提问、回答以及正在进行的输出。输入框、当前运行状态和停止按钮可用。长回答先显示可读预览；进入视口、展开工具或复制全文时，再按需要补齐对应正文。复制全文须等读取完整后才提示成功。

处于底部时，新输出自然跟随。用户向上翻就接管阅读位置。一项长正文读取失败时保留预览，在该项显示“重试”；相同版本的后台失败不会随每次刷新重复请求或堆叠右上角通知。首次读取失败、尚在加载、确实没有消息分别呈现。

### 2. 翻历史与快速浏览

从最新一条向上翻，先经过最近的已保存记录，再进入更早记录。即使所有历史只有一页、没有“更早一页”的游标，这一页也能打开。同一修订的相邻保存页保留在同一阅读区：向上补入较早内容，搜索定位后也能向下补入未读内容；已读内容不会因翻页消失或再次请求。普通向下滚动不会自动切回实时来源；旧数据无法对齐时，在接缝处提供“查看已保存记录”，打开保存页的最近端，并保留返回原处的入口。

用户读到一段长回答时，新输出留在会话末尾。展开上方工具、图片完成加载、改变字号后，尽量保持眼前的段落和键盘焦点。收到确定的新消息时，已有“回到最新”按钮可提示有更新；点击它才显式回到底部并恢复跟随。相邻翻页、搜索后的“返回原处”和“回到最新”各自有确定落点。

正文以提问与回答为主线。用户消息带固定的本地化发送者标签、浅蓝背景与强调边，长提问折叠和全文复制保持可用；思考、工具和长输出沿用可展开的细节。侧轨用可定位的提问摘录标记当前位置，随键盘焦点提供同样的预览。只有 SDK 能提供可信全局轮号时才显示该编号。部分历史可以恢复时照常展示可读部分，并在受影响处说明范围。浏览旧记录时，普通发送仍发往当前分支末尾；从旧处另起讨论使用 Fork。

### 3. 搜索

Ctrl+F 默认打开“本页查找”，可切换到“搜索会话”。两种范围保留同一个查询词，切换后刷新结果、计数和键盘行为。

| 意图     | 用户看到什么                                                                                                                      | 选中后去哪里                                                                                 |
| -------- | --------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 本页查找 | 当前阅读窗口、当前展示模式下可定位的匹配项，包含已显示的草稿和工具内容。计数单位为匹配的显示项，Enter、上下键、鼠标使用同一列表。 | 滚到对应项并高亮。切换展示模式时更新匹配范围。                                               |
| 搜索会话 | SDK 从已保存记录返回的相关结果及摘录。结果条数只描述此次返回的列表。                                                              | 能确认在当前分支的位置时，可选“在对话中查看”并阅读前后文。只能取得原文时，直接提供原文预览。 |

从搜索结果返回，先恢复查询、选中项和焦点；退出搜索后回到进入前的阅读位置。命中已过期时保留查询词，提供重新搜索。看起来相同的两条提问要按所选结果定位。已归档记录的来源只有得到 SDK 证实时才标注。

### 4. Fork

在一次提问及其回答旁提供“保留到这轮，创建分支”。一次用户提问、属于它的已保存回复和工具结果构成一个操作目标；长轮跨页、折叠工具、切换摘要视图都指向同一个目标。成功后进入子会话，显示继承到哪次提问；源会话可继续使用。工作区文件维持操作时的状态。

会话菜单、会话右键和无参数 `/fork` 从该会话的实际末尾派生。即使当前屏幕停在很早的记录，这些入口仍取实际末尾。对显式指定轮号的命令保留既有索引约定，须由 SDK 在源会话内精确解析；参数不支持或无法定位时提示原因并结束命令。活动会话按现有约束提示运行结束后再创建分支。未保存的草稿、归属不明的老记录可继续阅读。

### 5. 回退

行内入口叫“保留到这轮，回退后续记录”。确认框展示提问摘录，说明将截断其后的会话记录，以及工作区文件仍保持现状。若当前分支已到所选轮末尾，提示“这轮之后没有可回退的记录”。菜单和无参数 `/rewind` 的“撤回最近一轮”按会话实际末尾取上一轮；没有可保留的上一轮时说明原因。旧页的最后一问若在真实历史中还有后续，仍可选。

打开或取消确认框都只读。存在活动运行时，确认按钮明确写“停止当前运行并回退”。若确认期间出现新提问或换了运行，保留阅读位置并要求重新选择。若已成功停止原运行，随后写入因历史变化被拒，分别显示“运行已停止”和“历史未回退”。成功后显示实际保留轮的末尾，刷新和重新打开得到相同记录。

## 二、数据契约与归属

SDK 负责解释记录的来源、顺序以及能否安全改写。Space 负责保存用户看哪一段、想做什么以及如何展示结果。当前 view 和已保存历史允许使用不同读取方式。正文在同一时刻选用一个 SDK 来源；跨来源切换依靠可验证的来源引用。该设计遵循现有输出面决策。[ADR-010](../ADR/ADR-010-sdk-product-output.md)

| 对象或行为         | SDK / Host                                                                                                                                                                                                                                                 | Space 桌面端                                                                                                                                                                  |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 实时窗口与历史页   | 提供有序实时项、同一修订的已保存页、游标、完整性状态和正文分块。保留旧格式中仍可证明的来源。                                                                                                                                                               | 单独记录用户选中的阅读来源和页的前后关系；首个历史页可直接显示。按需读取正文，校验来源和版本，换会话后丢弃迟到结果。                                                          |
| 阅读位置           | 接受所见项及其来源版本，或 SDK 搜索引用。提供同一来源的有界上下文及可定位项，也可返回仅原文可读、过期或无法定位。                                                                                                                                          | 记住项内位置、屏幕相对偏移、焦点，以及搜索前的返回位置。只将同一修订的相邻历史页放在一个浏览窗口。定位不成功时保留已经读到的内容。                                            |
| 完整轮次目标       | 按请求解析所选轮、当前会话末尾或上一轮。沿实际分支找到完整轮尾，含已落盘且没有独立显示行的工具结果。返回提问引用、可展示的摘录、轮尾 entryId 与 sourceRevision；回退还返回当时分支头 expectedHead，可为 null。对部分恢复、未提交、忙或已变化给出具体结果。 | 行按钮传点击时所见项及来源版本，菜单与命令传各自意图。所有入口复用同一套解析、确认、提交和反馈逻辑。轮号用于显示或精确的命令参数；窗口数组下标只用于布局。                    |
| 写入与成功后的状态 | 写入层验证来源修订；回退同时验证已确认的分支头。返回实际子会话或保留位置。对活动运行按其身份核验停止与执行结果。                                                                                                                                           | Main 将已确认的目标原样传到 Runtime。依据写入结果重读会话、刷新谱系和关联通知。Space 自有通知仅在归属或截点能证明时继承、截断；缺少依据时保留原始数据，避免在子会话冒认归属。 |

**两个契约需要分开验证。** 阅读位置可指向工具正文中的某一段；SDK 现有 `historyBoundary` 指向一条持久消息之后；“保留到这轮”还要涵盖该轮随后保存的结果。前两者均不能直接充当完整轮尾。SDK 通过 resolveHistoryTurn 按需解析，避免为每个流式帧计算截断点。SDK 公共接口、daemon 传输和 Space 实际使用的 Runtime 路径都要覆盖。保存页定位使用 readHistory 的 around 参数，后续页使用 newerCursor。[SDK 边界与隔离派生实验](../research/sdk-view-history-action-boundaries-2026-11-07.md)

**确认与并发。** 解析时冻结来源会话、轮尾和修订；回退同时冻结分支头，活动运行场景记录用户同意停止的运行身份。确认后先检查这些条件，再停止对应运行；停止成功后仍由写入层校验已确认的目标。即使停止本身引发修订变化，也要据实返回结果并重新确认，不能偷偷替换修订继续截断。Space Main 将 SDK 解析出的完整目标原样传给 Runtime。遇到提交结果未知时先向 Host 核实，不盲目再次派生或截断。[实际调用链与停止顺序](../research/session-reading-model-2026-11-07.md#对局部轮号与写入时机的交叉复核)

**SDK beta.4 契约 v2。** `resolveHistoryTurn` 的就绪结果即操作目标：Session、轮起点、带 `kind:'turn_end'` 的轮尾和 expectedHead。Space 以 `{turn}` 原样提交 Fork 和回退，不再拼装边界。Host 在存储锁内按来源修订重建并校验整轮。目标过期时抛出 `resync_required`，`data.reason` 为 revision_mismatch、source_changed、selection_expired 或 head_changed。Space 将其显示为“记录已变化，请重新选择”，回退要求重新确认。活动运行仍为 `conflict`，显示为会话正忙；若已按确认停止运行，则提示停止未确认。未完成的工具交换以 `incomplete_turn` 返回不可用。Space 启动要求 Host 支持 `productHistoryLocation` 与 `productHistoryTurnResolution` v2；较旧的空闲 Host 由 SDK 启动器升级。

**旧会话与版本搭配。** 可验证的来源即可服务缺少 inputId/outputId 的旧记录；SDK 无法证明时明确返回原因。Space 不用正文、时间、显示 ID 格式或局部轮号猜测位置。使用旧 Host 时保留可用的分页、查找与原文预览；需要新能力的操作说明缺少的能力或所需升级。真实的查询在途才显示“正在定位”。首期覆盖共享 Coder，Partner、Mock 和临时 Quick Ask 按各自既有路径做兼容回归。

## 三、落地顺序与验收

第 1 步可单独交付。第 2、3 步都依赖来源信息，阅读定位和写入目标可以分别开发、分别验收。每步先保留能复现旧行为的对照，再从实际用户入口验证结果。

| 步骤                                  | 交付与依赖                                                                                                                                              | 通过条件                                                                                                                                                                                                                                                                                                                           |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1 · Space 打通阅读路径**            | 独立选择首个历史页；接好向前、向后、返回最新；区分两种搜索范围；按需补读和就地重试。使用现有 SDK。                                                      | 重放 120 条和 200 条短消息两个样本，双向翻阅可逐条抵达，1–40、51–120 均可读，同一窗口顺序正确且无重复。用只存在于历史的词验证本页零命中与会话结果的标签和键盘操作。构造重复失败的长正文，预览仍可读、同一版本不循环补读、右上角无逐项告警。                                                                                        |
| **2 · SDK 与 Space 接通阅读定位**     | SDK 返回可证明的位置及附近有界内容。Space 接入相邻翻阅、搜索直达、原文预览和返回位置。                                                                  | 覆盖旧无 ID、同文同时间、连续新输出、跨页长回答、压缩归档和引用过期。可定位命中进入正确段落；仅原文命中可读原文；返回恢复原项、焦点和相对位置，来源失效时保留已读页。滚轮与键盘均能完成流程，切换会话时迟到响应不串页。                                                                                                            |
| **3 · SDK 与 Space 接通 Fork 和回退** | SDK 按需解析完整轮尾。Main/IPC 传递来源修订、回退分支头及必要的运行身份。统一消息行、菜单、右键和命令各自支持的操作，按 Host 结果更新画面、谱系与通知。 | 在隔离副本核对持久消息序列。超 150 显示块的跨页轮、隐藏 tool_result、失败或中断轮均保留该保留的完整前缀。选择旧页第 41 问，旧缓存的第 1 问不能进入子会话。验证各入口作用域、Fork 源不变、回退后的即时画面和重开一致。注入确认后分支头变化、checkpoint 保存、运行更换、停止成功但截断失败；不得误停新运行、扩大截断范围或误报成功。 |
| **4 · 配套交付与长会话验收**          | 用真实 SDK 包、开发启动的 Host 和打包桌面端分别走五条用户路径；覆盖新旧 Host 能力差异。记录打开、翻页、搜索及长正文展开的成本。                         | 使用用户问题会话的隔离副本、含数 MB 思考的会话和万行混合高度样本。比对首屏可读时间、正文 IPC 字节、内存、长任务和锚点漂移；首屏不等待全历史或折叠正文读完。发布记录注明实际加载的 SDK/Host 版本、已通过样本和兼容表现。若需要 F144 虚拟化，按原目标另验万行挂载 ≤500 行、布局稳定后锚点漂移 ≤2 px，再替换渲染方式。                |

**规模优化的决策依据。** 如果长会话的主要开销来自正文读取，先收窄预取；如果开销集中在 DOM、布局或绘制，再推进虚拟列表。全局提问目录另用“记得话题但忘了关键词”的找回任务衡量正确率、耗时与误跳次数。首期沿用提问侧轨和搜索，待测量结果支持再扩大范围。[既有 F144 目标](../features/v0.2.x-plus.md)

## 四、评审依据

隔离实验中，200 条样本从第 121–200 条直接翻到了第 1–50 条。另一个实验按已显示成功的工具行 Fork，派生会话遗漏了持久工具结果。前者决定首个历史页必须可达，后者决定操作验收必须检查落盘前缀。这些数字来自构造样本。原用户会话中已确认的是旧项正文补读失败和 4 个提问仅 1 个关联到边界，尚未逐条测量其翻页缺口。[阅读模型与实验](../research/session-reading-model-2026-11-07.md) · [桌面阅读交互](../research/session-reading-ux-2026-11-07.md) · [操作入口调查](../research/space-history-action-entrypoints-2026-11-07.md) · [SDK 边界调查](../research/sdk-view-history-action-boundaries-2026-11-07.md)
