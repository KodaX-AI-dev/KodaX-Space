## Initial candidate failures and corrective checks

Candidate `7c6fe4cb` was blocked before publication: build run `41675615967` had a Mac Intel question-timeout fixture failure, and release run `41675695313` had a Linux smoke failure. The 250ms question could expire before list polling; subscribing before start and checking the actual creation event fixes the finite-deadline test. A deliberate 350ms delayed read reproduces the old failure and passes after correction. Ordinary indefinite questions still require a pending interaction.

Linux doctor-unavailable skipped both ordinary Bash executions but the final smoke assertion still required their backend evidence. The corrected probe always runs both ordinary commands through SDK policy, including automatic permission-policy fallback, and still requires exact output, zero exit, clean environment and valid SDK execution evidence. Only direct sandbox execution remains readiness-gated. No SDK bytes or permission policy changed. Eighteen focused tests, a final four-question rerun, lint and the actual packaged Windows smoke passed. Two-axis corrective review has no remaining findings. The unpublished candidate is replaced by the corrected source; failed/cancelled attempt logs remain available.

Candidate `b0b46256` passed all four installer builds, including `Signature=adhoc` and deep/strict verification on both Mac architectures. Its Linux full unit job then exposed a separate compatibility-probe race (`run.failed` count 0): the probe neither awaited subscription readiness nor waited for the independent event delivery before closing. The correction waits for readiness and at most five seconds for the real terminal event, retaining the exact count, event-type and failure-detail assertions. The real SDK focused test and lint pass; Standards and Spec have zero remaining findings. This candidate also remains unpublished and is superseded; its successful package checks do not substitute for the final source SHA's gates.

The same full Linux E2E run found two deterministic boundaries: source Electron metadata omitted `version`, causing updater initialization to reject `0.0`; an unsaved mock Session's task list incorrectly queried a non-existent Host Session. The build now writes the root manifest's real version. Task listing follows the existing mock Session creation boundary, keeping local tasks local while preserving real Host errors. Two new unit cases failed before the change and pass afterward (six total in that module); the actual cross-Session failure was also reproduced in the Windows package. Startup fixture evaluations now wait for the first native window, with early page/error listeners preserved, to avoid evaluating Electron's replaceable bootstrap context. There is no generic retry or ignored error.

Seven source UI cases passed in one zero-retry run after these changes: Reference Agent management, cross-Session task isolation/cancellation audit, notification settings, startup overlay and the three update shutdown cases. Typecheck, lint and both review axes pass. Candidate `8c641497` was stopped unpublished so the final candidate can include these corrections; no previously published tag or release assets were overwritten.

Candidate `9686ffc8` passed Linux and Windows full source checks and the Windows/Linux/Mac Intel installer builds. The ARM packaging job was never acquired by a GitHub hosted runner; the check annotations explicitly report macOS ARM capacity constraints. The same-SHA failed-job retry preserved the three successful platform candidates. The candidate remained unpublished when later source checks failed.

That full run demonstrated that the earlier source metadata correction was incomplete: Electron's bundled default launcher reads `packagePath/package.json` only for application-directory launches; passing `main.js` bypassed version initialization on Linux. E2E now launches the generated application directory and verifies native `app.getVersion()` against the root manifest on every launch. Waiting for a first window also did not eliminate the known [Playwright Inspector evaluate failure](https://github.com/microsoft/playwright/issues/33737). Only the idempotent native-dialog cancellation hook may repeat at most three times for the two specific collected/destroyed-context errors while the process is alive; version mismatches, SDK operations and other errors are never retried by this hook. Five source cases passed without test retries after correction.

Additional platform fixture corrections keep the SDK's symlink refusal intact by giving test workers a physical temporary profile root; exercise real keyboard navigation before checking focus-visible; and require the newly replaced preview document to be ready before clicking its animation control. The focused sandbox/keyboard checks passed. A separate manual Linux diagnostic workflow repeats native metadata, startup, update shutdown and local-frame navigation twice with zero test retries; it is supplementary and cannot qualify source or publish. Final full CI and release gates remain mandatory.

The Linux diagnostic on `367a9101` passed all 12 checks with zero retries, confirming native-version initialization and both preview network modes. Its full Mac ARM source run then exposed an unintended test-environment side effect: global TMPDIR canonicalization lengthened long-profile SDK Unix socket paths from 101 to 109 bytes; [Darwin's socket address field is 104 bytes](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/sys/un.h). The correction retains the physical credential home but preserves the OS's short temp alias for sockets. No SDK path validation or product Runtime policy is weakened. Mac Runtime diagnostics are added to validate actual containment, cleanup, shared ownership, learning and keyboard behavior. All five selected cases pass locally; Mac evidence remains separate.

A Windows expanded-expert restoration check exceeded its ten-second polling guard under CI load. The helper now yields for 20ms instead of spinning through setImmediate and uses a bounded 30-second CI budget (local ten seconds retained), still requiring the actual terminal state and exact controlled-Provider request count. The focused status-report restoration case passed in 6.5 seconds locally. No production prompt, permission, model or SDK package changed in these fixture corrections.
