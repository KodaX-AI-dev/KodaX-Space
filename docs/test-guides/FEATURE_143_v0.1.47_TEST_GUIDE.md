# F143 — Windows 命令沙箱 setup：子进程执行与启动卡片 测试指南

设计：[Windows sandbox setup out of process](../features/v0.1.47.md#windows-sandbox-setup-out-of-process--2026-11-28-source-ships-in-0147-rc4)。本文取代 [F143 v0.1.35 测试指南](FEATURE_143_v0.1.35_TEST_GUIDE.md)中的 Windows setup 步骤；该指南的只读诊断、macOS / Linux 指引和失败收敛场景仍然有效。

## 前置条件

- 一台可丢弃的 Windows 测试机或虚拟机，尚未配置 KodaX 沙箱账户（首次安装，或升级后沙箱账户被替换）。不要为了跑本指南而在生产机上删除可用的沙箱账户。
- 当前登录用户是标准用户或管理员：setup 会出现一次 UAC 提示，需要能批准它。
- 一台沙箱已就绪的 Windows 机器（对照组），以及 macOS / Linux 各一台。
- 卡片没有自动化界面测试，端到端夹具会在每次启动时预先写入“以后再说”：本指南的人工场景是卡片、UAC 等待和中途停止的唯一验收手段。客户机器上的真实 UAC 验收尚未记录。

## 人工场景

### A. 启动卡片（正向 / 界面）

1. 在需要 setup 的 Windows 机器上启动 Space：至少 2.5 秒后右下角出现非模态卡片“设置命令沙箱”，按钮为“现在设置”和“以后再说”；卡片不遮挡其他控件，界面其余部分照常可用。
2. 点“以后再说”：卡片立即消失，出现提示“可以随时在“设置 → 安全与沙箱”中完成命令沙箱设置。在此之前，命令仍按普通权限确认执行。”；不出现 UAC。
3. 重启 Space 两次：卡片不再出现。即使之后沙箱再次变为“需要设置”，也只从设置页进入（“以后再说”对以后一直有效）。
4. 在卡片上点“现在设置”：setup 直接开始，不出现设置页那样的应用内确认框；只出现一次 UAC。
5. 在沙箱已就绪的 Windows 机器上启动：没有卡片。

### B. setup 进行中（正向 / 性能）

1. 开始后卡片变为“正在设置命令沙箱”，显示“已用 m:ss”并每秒更新；没有按钮。
2. 批准前，卡片说明“请现在在 Windows 权限提示（UAC）中点“是”…提示最多等待 10 分钟”。让 UAC 提示只留在任务栏闪烁，过 15–60 秒再点开批准：setup 继续，不报失败。
3. 整个 setup（包括替换旧沙箱账户的升级）只出现一次 UAC，不再出现第二次或第三次同意请求。
4. 批准后卡片显示“已批准，正在完成设置，可能还需要几分钟…”。这几分钟里拖动窗口、切换会话、打开设置、发送一条消息：窗口一直响应，不再出现“未响应”。不要关闭 Space。
5. 成功：出现提示“命令沙箱设置完成，doctor 已确认就绪。”；沙箱状态变为已就绪；卡片消失。
6. 在 UAC 中点“否”：只出现提示“已取消命令沙箱设置。”，不显示失败卡片；状态仍是“需要设置”，可从设置页再次开始。本次启动卡片不再出现，下次启动照常提示。

### C. 与另一个 setup 同时进行（边界）

1. 先在终端运行 `kodax sandbox setup` 并停在它的 UAC 提示上，再在 Space 点“现在设置”：卡片显示“另一个沙箱设置正在进行（例如来自 kodax 命令行）。Space 会等它完成（最多 45 分钟）并沿用它的结果。”，不会在 35 秒后失败。
2. 完成终端里的 setup：Space 沿用其结果，不出现第二次 UAC。

### D. setup 未完成（负向）

1. 让 UAC 提示停留超过 10 分钟不批准：卡片标题为“命令沙箱设置未完成”，正文“Windows 权限提示（UAC）在 10 分钟内没有得到批准。如果提示没有弹到最前面，请留意任务栏上闪烁的盾牌图标，然后重试。”，按钮为“重试”“沙箱设置”和关闭。
2. 依次核对卡片和设置页会给出的其余原因，并与 SDK 的失败 code 对应：

   | 界面文案（简体中文）                                                                             | SDK code                                                                  |
   | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------- |
   | 另一个沙箱设置…45 分钟后仍在进行。请等它完成后再刷新。                                           | `setup_lock_busy`                                                         |
   | 无法确认沙箱账户处于空闲状态。请关闭在沙箱中运行的命令窗口…                                      | `sandbox_account_busy`、`idle_probe_failed`                               |
   | KodaX 原生沙箱文件缺失或被拦截。请检查 Windows 安全中心的保护历史记录…                           | `native_artifact_unavailable`，或错误文本含 native artifact / quarantined |
   | 批准权限提示后，有一个设置步骤失败了。请重试；如果再次失败，请在“设置 → 故障排查”中导出诊断信息… | `elevated_step_failed`                                                    |
   | 沙箱权限清理尚未确认。请重启 Windows 后再刷新。                                                  | 错误文本属于 ACL 恢复（优先于任何 code）                                  |
   | 设置在完成前中止。请查看沙箱设置中的指引后重试。                                                 | 其余 code（含 `setup_failed`、`elevation_cancelled`）或没有 code          |

3. 点“重试”：直接再次开始 setup（仍只有一次 UAC）。点“沙箱设置”：卡片收起并打开设置页的沙箱分区。
4. 把界面语言切到英文重复第 1 步：文案为 “The Windows permission (UAC) prompt was not approved within 10 minutes…”，不出现未翻译的 SDK 英文错误。
5. 设置 → 故障排查 → 导出诊断：日志中有 `sandbox` / `setup.failed` 的原始 SDK 错误和各条 `setup.progress` 阶段；卡片和设置页上不显示绝对路径、用户名或环境变量路径（安全）。

### E. 设置页（界面）

1. Settings → 安全与沙箱 → 命令沙箱（ASRT）：显示 doctor 确认的状态、ASRT 版本、后端、平台、有界诊断和设置指引；“刷新”只运行 doctor，不出现 UAC。
2. 状态为“需要设置”时才出现“设置沙箱”。点击后先出现应用内确认（“继续并等待 UAC”），确认后才开始 setup；进行中“刷新”和“设置沙箱”都置灰，右下角卡片同时显示进度。
3. setup 未完成后，分区里多出一行“上次设置：…”说明上次结果；成功后该行不显示。

### F. setup 中途停止（边界）

1. 批准 UAC 后、setup 仍在进行时关闭 Space。重新启动：doctor 报告上次 setup 被中断，即使以前点过“以后再说”，卡片也会以“完成命令沙箱设置”出现，按钮为“完成设置”和“以后再说”。
2. 在这张卡片上点“以后再说”：本次收起，但下次启动仍会提示（中断状态优先于“以后再说”）。点“完成设置”并走完：卡片不再出现。

### G. 其他平台与升级（兼容性）

1. macOS、Linux：从不出现启动卡片；设置页只显示依赖安装指引，Space 不调用包管理器。
2. 在已就绪的 Windows 机器上安装本版本：状态保持已就绪，没有卡片，也没有 UAC。
3. 从旧版升级且沙箱账户被替换的机器：卡片按 A 组出现，setup 只弹一次 UAC。

## 失败处理

- 卡片出现后 doctor 读取失败：卡片不出现，也不自动开始 setup；到设置页点“刷新”查看状态。
- setup 进程异常退出（例如被安全软件终止）：卡片显示“设置在完成前中止…”；重试仍失败时导出诊断，并在重启系统前记录进程列表。
- 子进程运行接近 90 分钟仍未结束会被结束，卡片显示“设置在完成前中止…”；正常情况下 SDK 自己会先结束等待（另一个 setup 最多 45 分钟，UAC 最多 10 分钟）。
