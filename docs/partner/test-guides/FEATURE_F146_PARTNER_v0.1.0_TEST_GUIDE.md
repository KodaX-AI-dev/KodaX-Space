## 2. 证据分级

| 级别 | 含义                           | 可以证明                                  | 不能证明                             |
| ---- | ------------------------------ | ----------------------------------------- | ------------------------------------ |
| A    | 自动化 fixture / contract test | schema、状态机、错误分支和本地契约        | 真实账号、真实权限、第三方服务可用性 |
| B    | 开发态 Electron 人工观察       | 真实桌面交互、会话、布局和本地生命周期    | 打包产物、多平台、真实第三方服务     |
| C    | 打包宿主人工观察               | 安装包中的宿主、独立 Extension 与数据保留 | 未执行的平台、未连接的第三方服务     |
| D    | 真实服务验收                   | 指定账号、scope、资源和操作的实际结果     | 其他租户、其他权限组合或未测操作     |

不得用低级别证据替代高级别证据。Mock 成功、fixture 成功、目录里出现卡片或按钮可点击，都不等于真实服务已通过。

## 3. 测试环境与前置条件

- 使用精确候选 commit 构建，记录 `git rev-parse HEAD`、操作系统、CPU 架构、Node/npm 版本和测试日期。
- 使用隔离的 Space profile、测试项目和测试会话；不要在个人或生产 profile 中卸载、替换或清除扩展。
- 构建并校验 `out/extensions/kodax.partner-library-0.1.0.space-extension`。
- 打包宿主必须显示 Space `0.1.46-alpha.5`，并协商 Partner Host API 4 与 `partnerNativeDocumentDeliveryV1`。
- 真实服务只使用经过授权的非敏感测试账号、测试文件夹和可删除的测试资源。不要把 token、cookie、授权 URL、二维码、密码或私密正文写进截图、日志或报告。
- 预先保存一段未改动的 Coder 基线会话，用于验证 Partner 变化没有改变 Coder 的模型、Skill、MCP、附件或执行路径。
- 如执行版本迁移，准备同 ID 的本地旧候选 `kodax.partner-library` `0.9.1` 及其隔离 profile；没有该产物时将对应测试记为 Blocked，不能假装升级已通过。
- 每次测试失败都记录复现步骤、实际结果、截图或日志位置；不要将失败环境中的敏感信息加入仓库。

## 6. 人工测试用例

### TC-001：独立 Extension 安装与生命周期

**PF**：PF001

**优先级**：高

**类型**：正向测试

**证据级别**：C

**前置条件**：使用打包的 Space `0.1.46-alpha.5` 和全新隔离 profile；尚未安装 Partner Extension；候选归档已构建并记录 SHA-256。

**测试步骤**：

1. 在“设置 → 扩展”选择 `kodax.partner-library-0.1.0.space-extension` 安装。
2. 检查安装后版本、Extension ID、专家数与连接器数，并确认默认未启用。
3. 显式启用 Extension，进入 Partner 的插件库、专家和连接器入口。
4. 依次停用、重新启用、卸载、重新安装并再次显式启用。
5. 每个阶段打开普通 Partner 对话和既有 Coder 会话，确认主应用仍可使用。

**预期效果**：

- [ ] 安装记录的 ID 为 `kodax.partner-library`、版本为 `0.1.0`，不会自动连接账号、安装 Skill、发送消息或启用 Extension。
- [ ] 只有显式启用后才出现 Partner 插件能力；停用或卸载后入口撤下，但主聊天、设置和 Coder 不受影响。
- [ ] 重装恢复 Extension 能力，不静默删除用户专家、会话历史或共享 Skill。

**优先级**：高

**类型**：正向测试

**证据级别**：B、C

### TC-003：用户专家、可选 Skill 与失败恢复

**PF**：PF001

**优先级**：高

**类型**：负向测试

**证据级别**：B、C

**前置条件**：Extension 已启用；准备一个内置专家、一个已安装且兼容的 Skill 名称，以及一个明确不存在的 Skill 名称。

**测试步骤**：

1. 编辑内置专家，确认系统创建用户副本而不是修改只读来源。
2. 编辑用户副本形成新 revision；检查旧会话仍保持旧快照，明确重新选择后才使用新 revision。
3. 从两份旧表单并发保存同一 revision，观察冲突提示；随后软删除该用户专家。
4. 选择配置了不存在 Skill 的专家并发送，观察错误；再明确关闭 `useSkill` 后重新发送。
5. 停用、卸载并重装 Extension，检查用户专家、软删除状态和会话快照。

**预期效果**：

- [ ] 内置专家保持只读；用户副本具有宿主管理的身份与递增 revision，并发旧 revision 不能覆盖新数据。
- [ ] 缺失 Skill 明确拒绝，不自动安装、替代或伪装执行成功；明确关闭后只使用专家提示词。
- [ ] 软删除不清除历史；停用、卸载或重装不静默删除用户专家和会话快照。

### TC-004：飞书 Preview 真实读取、创建与受审追加

**优先级**：高

**类型**：正向测试

**证据级别**：D

**前置条件**：使用获授权的专用飞书测试账号、测试文件夹、一个可读测试文档和一个可追加测试文档；不得使用生产数据；Extension 已启用但当前会话尚未授予范围。

**测试步骤**：

1. 从可信连接弹窗发起官方网页登录授权，返回后确认账号连接与会话范围仍是两件独立操作。
2. 只给当前会话选择一个测试文档，读取并在统一详情工作区核对标题、来源、版本/读取时间和 canonical URL。
3. 新建一份飞书文档，记录宿主返回的资源身份、canonical URL、创建状态和内容校验状态；在私有窗口重新读取实际内容。

5. 对既有测试文档发起追加，先拒绝一次，再重新审核并确认一次；检查原内容保留且只追加一次。
6. 断开账号并撤销所需 scope，再次尝试读取和写入。

**预期效果**：

- [ ] 连接账号不自动授予会话范围；未选择的资源不可读，新会话不继承当前范围。
- [ ] 创建成功只有在宿主验证资源身份和 canonical URL 后才显示；创建状态与内容校验状态分别记录，不把未验证内容写成成功。
- [ ] 既有资源修改必须经过明确审核；拒绝不写入，重复确认不产生第二次追加。
- [ ] 断开或撤销 scope 后新操作被拒绝，历史回执不被改写，凭据不出现在 UI、消息或日志中。

### TC-008：慢请求、切换压力与任务收束

**PF**：PF001、PF002、PF003

**类型**：性能测试

**证据级别**：A、B、C

5. 长时间停留连接器目录，检查是否持续轮询授权、重复启动 CLI 或不断增长后台任务。
