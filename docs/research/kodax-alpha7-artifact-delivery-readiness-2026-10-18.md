## 4. 根 SDK 已有的桥接为何还不够

1. **通用工具 Run 已公开**：`runs.startTool` 不经模型提示执行已注册工具，`runs.await/stop` 提供终态/停止；它不提供 Artifact renderer 或自动注册九工具。[已安装 client contract:938–949](C:/Works/GitProj/KodaX-AI/KodaX-Space/node_modules/@kodax-ai/kodax/dist/types-chunks/client-contract-CRm9ZpL2.d.ts:938)、[源码注册:39–45](C:/Works/GitProj/KodaX-AI/KodaX/packages/artifacts/src/kodax.ts:39)。
2. **图片附件字节读取已公开**：`sessions.readItem(...,{part:'attachment',attachmentIndex,attachmentOffset,expectedImageSha256})` 读取该 Host 项现有 PNG；只接受项身份与索引，不接受 UI 路径。每块最多512KiB，整图10MiB。这可以独立接入、验证，但不是 render/capture 实现。[已安装 options:1179–1185](C:/Works/GitProj/KodaX-AI/KodaX-Space/node_modules/@kodax-ai/kodax/dist/types-chunks/client-contract-CRm9ZpL2.d.ts:1179)、[正式说明:157](C:/Works/GitProj/KodaX-AI/KodaX-Space/node_modules/@kodax-ai/kodax/docs/SPACE_SDK_SEAMS.md:157)。
3. **受管进程桥接已公开**：`executeManagedProcess(scope,input)` 在 `/coding` 中；独立 adapter 仍需自己的 request decoder、runtime-entry worker、执行 backend、result/image 校验。自己抄写这些组件会变成另一份 SDK 实现，不能算消费正式独立包。[已安装 coding:217](C:/Works/GitProj/KodaX-AI/KodaX-Space/node_modules/@kodax-ai/kodax/dist/sdk-coding.d.ts:217)、[源码 adapter:57–81](C:/Works/GitProj/KodaX-AI/KodaX/packages/artifacts/src/kodax.ts:57)、[worker:8–27](C:/Works/GitProj/KodaX-AI/KodaX/packages/artifacts/src/runtime-entry.ts:8)。
4. **根 runtime 的 `artifacts` 是另一契约**：它只有 `create({kind:'image'|'file'|'video',path,...})/get/delete` 与 `artifact_ref` 输入，不是九操作 SDK，更不提供 ArtifactExecutionPort。[已安装 runtime:1770–1796、2229–2234](C:/Works/GitProj/KodaX-AI/KodaX-Space/node_modules/@kodax-ai/kodax/dist/sdk-runtime.d.ts:1770)。
5. **共享 Host 的独立 client port 负责不可省略的关联检查**：实际 Run/session/tool_call、`kodax-artifact/1`、附件归属、chunk offset/hash/dimensions、abort 后 stop settlement；无本地 fallback、自动重放或额外 Session。仅调用 `startTool('artifact_render')` 不能补齐尚未注册的实现与这些校验。[源码 client:8–60](C:/Works/GitProj/KodaX-AI/KodaX/packages/artifacts/src/client.ts:8)、[正式说明:187](C:/Works/GitProj/KodaX-AI/KodaX-Space/node_modules/@kodax-ai/kodax/docs/SPACE_SDK_SEAMS.md:187)。
