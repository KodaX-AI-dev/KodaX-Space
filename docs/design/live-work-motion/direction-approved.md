## 实现（2026-11-14）

用户确认「可以，按这个来吧」后落到产品代码：

- `apps/desktop/renderer/src/shell/toolClusterPulse.ts`：纯投影（节拍条、动作行、思考末行、耗时起点、token 估算）。

## 节拍条改为分类计数（C+，2026-11-14）

用户反馈真实运行里 12 根竖条「都是一点点长，也没有颜色区别」：真实读取只有几十毫秒，按耗时定高度的竖条几乎一样高；info 蓝与 run 天蓝在暗色下也分不清。

展示了 `beat-strip-options.html`（截图在 `previews/beats-*.png`）：现状、A 阶段条按个数、A+ 阶段条按耗时、B 构成条、C 分类计数、D 胶囊时间线、E 阶段胶囊。

用户原话：「C 看起来不错，简洁明了，不过能不能每个类别加个总时间，这样是不是就有动态了？」→ 加了 C+；随后「运行的时间长超过1m甚至1h可以简洁显示但是也有动态效果吗？」「你希望小时级也每秒都能看到在动,请一起改一下吧」。

定稿 C+：

- 每类一组「图标 + 次数 + 该类总耗时」，固定顺序：看代码 / 改代码 / 跑命令 / 其他 / 失败。失败（SDK `tool.status === 'error'`）单独成类。
- 看代码用中性色，改代码 accent，跑命令 run，其他 faint，失败 danger。
- 运行中：正在跑的那一类图标呼吸、时间用该类颜色并每秒往上走；新的一次调用让次数跳一下。结束后保留在历史标签上，静止。
- 时间最多两级单位：`2.4s` · `42s` · `3m07s` · `1h05m`；运行中小时级多带秒 `1h05m07s`。
- 没有耗时的旧历史只显示次数。
