# v0.1.46-rc.3 release readiness

Date: 2026-09-23. Previous release: v0.1.46-rc.2.

## Scope

- Pin the exact published KodaX `0.7.96-rc.10` in root/Desktop manifests and the lockfile
  (`sha512-ZiLYjsLDfiFaFbyvZUeKjYahudnuBbcOHfwA25Yn/tQHuudmVySLX8GlhZqwcRtdkq7B4AB7WkpB3fzPQkXxcg==`),
  superseding rc.9. Exports, dependency ranges, engine requirements and public capability
  versions are unchanged; existing startup/daemon capability gates
  (`sandboxRuntime:11`, `runtimeAutoModeGuardrail:6`, `sharedSessionSettings:2`,
  `providerCredentialBroker:2`, `effectiveConfig:1`, daemon `sessionCancellation:1`
  with durable frontier, `toolInvocation:1`) remain intact.
- Inherited SDK fixes ([integration evidence](kodax-0.7.96-rc.10-integration.md)):
  Runtime close drains owned terminal-maintenance and memory IO/review work before
  releasing ownership — Space already awaits `runtime.close()` in its host adapter and
  registers no custom reviewer, so no Space drain loop is added; the new memory-review
  cancellation parameters and internal ownership callbacks stay optional and SDK-owned.
  Edits-mode text transactions protect the canonical target without rejecting ordinary
  project files merely because the workspace contains protected native state.
- Installed-package regression: an already-aborted direct Run retains a defined
  interrupted result with exactly one terminal `onComplete` and no Provider request
  (the same case passes on rc.9; it protects Space's existing completion contract).
- Compaction telemetry fix (post-rc.2 follow-up, Issue 216 record): the `compact_stats`
  IPC schema accepts finite, bounded, nonnegative fractional `elapsedMs`/`commitMs` —
  SDK `performance.now()` measurements are fractional and the previous integer-only
  schema silently discarded statistics after otherwise successful compactions. Count
  and revision constraints are unchanged.
- Synchronize workspace versions, changelog, READMEs, capability ledger, product/
  architecture/usage docs, user manual, feature list, `docs/features/v0.1.46.md`, and
  kodax_manual (rc.3/rc.10 stamp with anchored contract test).

## Qualification

- Recorded during the 2026-09-23 integration: the exact-dependency assertion failed
  against rc.9 before installation; `npm ls @kodax-ai/kodax --all` shows one
  deduplicated rc.10 package; `assertKodaxReleaseDependencyState` passes Registry URL,
  SRI and installed bytes including the universal native bundle; no SDK bytes patched.
- Typecheck, lint, and `build:smoke` pass. The full `npm test` chain passed with
  4,222 tests / 0 failures / 20 platform-permission skips (release gates 86+7 skipped,
  desktop 3,774+13 skipped, ipc-schema 362), including real SDK startup probes,
  installed-package cancellation, shared-daemon ownership/cleanup, and Runtime host
  shutdown tests.
- The manual-topics contract pins the rc.3/rc.10 phrasing.

## Remaining boundaries

Windows packaged boot/exit evidence from rc.9 does not transfer to a newly packaged
rc.10 build; the release workflow's own packaged smokes cover the new binary. The
customer-specific Issue 216 lifecycle failure remains unconfirmed and customer-machine
acceptance stays pending. Pure configuration-type extension commands remain
CLI-owner-only; Partner Coder sharing, real external-account acceptance, and automatic
library replacement remain open from earlier readiness records. FEATURE_275 long-term
guarantees are unchanged.
