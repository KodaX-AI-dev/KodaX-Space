## 4. Core 与 Preview 边界

### Core candidate

- Partner Extension 可独立构建、安装、启用、停用和卸载；Extension UI 不作为可信 Renderer 模块静态编译。
- 内置专家、用户专家、可选单个 Skill、会话绑定和不可变专家快照形成稳定的 Partner 交互基础。
- 任务资料、协作、产物、专家、Skill、连接器和受控网页进入统一详情工作区，不改变 Coder 的产品逻辑或权限。
- 创建操作采用 receipt-first 语义：宿主先验证远端资源身份与 canonical URL，再分别报告资源创建状态和内容校验状态。

### Preview candidate

- 飞书：候选范围包括会话选定文档读取、受控新建文档与 Base，以及审核后追加既有文档；只有真实账号、真实资源和私有读回证据才能证明对应能力可用。
- 企业微信、钉钉、腾讯会议：当前只有适配器、受控 CLI 和 fixture/契约证据，不声明真实企业环境已通过。
- Notion、Airtable、Atlassian：当前只有 OAuth、远程 MCP 与本地契约证据，不声明真实租户端到端已通过。
- Slack、Zoom：缺少受审的产品级应用配置时必须保持 unavailable，不得发起授权或显示已连接。

任何 Preview 项都不得用自动化 fixture、Mock、目录展示或“连接按钮存在”替代真实服务验收。未实测的平台、账号、scope 或操作必须记录为 `Pending`、`Blocked` 或 `Unavailable`，不能记为 Pass。

## 9. 回滚边界

首选产品级回滚是停用相关连接器能力，或停用/卸载 Partner Extension。该操作不得删除会话历史、用户专家、专家快照、任务记录或已经存在的远端资源。

`0.9.1 -> 0.1.0` 是一次版本编号重整下的同 ID 替换，不应假设 Extension Store 会进行 SemVer 升级判断。替换后应保持禁用，等待用户明确重新启用；数据保留与回滚必须按测试指南实测。Space 宿主降级是另一项操作，在数据格式兼容性得到验证前不得声称安全。

## 10. 晋级规则

只要任一必需技术、人工作业、真实服务或授权门槛处于 Pending、Failed 或 Blocked，本文件就保持 **Release Candidate**。

只有在同一个精确候选提交上完成全部证据，并取得适用书面授权后，才可以：

1. 创建并评审专用 Partner release commit；
2. 创建 `partner-v0.1.0`，不得创建 plain `v0.1.0`；
3. 精确 push release commit 和该单个 tag，不使用 `git push --tags`；
4. 创建与相同 commit、Changelog 和产物校验值一致的 GitHub Release。
