# 完整工作区与设置融合预览

2026-10-16。用户要求将玻璃与动效融入完整多项目工作区及设置页面，而不止展示单独的效果，并询问之前 A/B/C 是否已融合。之前没有完全融合，本轮新增统一入口 `index.html#integrated`；保留原始 A/B/C 与独立材质实验供对照。

| 来源           | 在统一体验中的位置                                                                   |
| -------------- | ------------------------------------------------------------------------------------ |
| A：石墨工作台  | 具名项目分组、会话与并行状态、连续中央画布、按需详情                                 |
| B：纸白编辑室  | 同一工作区的「成果」视图，直接查看成果文件；浅色属于全局主题                         |
| C：专注审阅台  | 从成果进入完整审阅工作面，可隐藏项目导航专注阅读，再返回原会话                       |
| 材质与动效实验 | 输入框、固定栏、审批对象、局部通知的玻璃与受光；同组移动选中底板、短时入场与一次扫光 |

统一后的重点是一个产品内的不同工作模式。没有把三种布局并排常驻，也不增加三个正式产品风格入口。

## 可操作流程

1. 以三个示例项目和六个会话进入。窗口较矮时，初始折叠非当前项目，保留运行与待确认摘要；可以展开多个项目。
2. 切换项目会话，各自保留草稿与审批状态。
3. 顶部预览控制「播放并行场景」启动约 8 秒示例：两个后台任务陆续完成并留下未读和局部通知；Atlas Web 的人工确认不会自动跳过，当前项目不会被强制切走。
4. 切换「对话 / 成果」，打开文件审阅与专注模式；返回时恢复原工作区。审阅是工作面内的视图，保留左侧项目导航，专注时暂时隐藏导航；不是居中模态浮层。
5. 打开完整设置页。分类导航使用同样的移动底板，搜索与固定栏使用同样的材质；六类设置保留。
6. 设置中的明暗主题、视觉质量和动态偏好立即同步到缓存中的工作区。返回不重建工作区 iframe，保留项目、会话、草稿和视图；后台示例任务在设置页打开期间仍会完成，状态同步到设置页底部。

## 运动分镜

| 触发            | 构图与主角                       | 动作                         | 停留与终态                                   |
| --------------- | -------------------------------- | ---------------------------- | -------------------------------------------- |
| 项目 / 会话切换 | 项目导航中的当前行、连续中央画布 | 同组底板迁移，内容短距离淡入 | 一次 300ms，随后静止；折叠时不显示隐藏行底板 |
| 成果视图        | 成果标题与文件列表               | 顶部选中底板横移，成果轻入场 | 保留输入与项目位置                           |
| 完成通知        | 右下角局部玻璃通知               | 入场、一次 850ms 扫光        | 约 6 秒后收起；不抢走当前任务                |
| 审批            | 当前任务的局部玻璃操作面         | 点击后高光反馈与状态更新     | 等待人工操作，不自动批准                     |
| 审阅            | 连续 diff 工作面                 | 进入、专注 / 返回            | 项目与草稿不丢；不循环                       |
| 设置分类        | 安静的分类导航与设置正文         | 底板迁移、内容轻入场         | 切换结束即静止                               |

原型不调用真实 Agent、账号、测试或文件操作，不保存生产配置。没有新增动画库、WebGL 流体或付费实现。静态玻璃和局部指针高光也有绘制成本；本轮验证浏览器行为与布局，不宣称已通过 Electron GPU、功耗或目标设备帧率验收。
