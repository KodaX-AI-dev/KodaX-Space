# 项目管理方法

把交付目标拆成有依赖、有责任人、有完成条件的工作，而不是只有日期的任务清单。

先沿用会话中已确定的目标、交付范围、截止时间和可用人力。缺少估算或责任人时标记待确认，不编造团队承诺。区分期望日期、估算日期和已承诺日期；相对日期结合给定基准解释，没有基准则保留原话。

计划按“交付物 → 验收条件 → 前置依赖 → 负责人 → 工期/日期”组织。工作量不等于日历时长；考虑同一人的并行冲突、等待、评审和返工。没有依赖、工期和工作日规则，不声称算出了关键路径。增加人员不能自动消除“完成后才可开始”的依赖；改变硬性前置关系的方案必须说明需重新确认该约束，不把并行当成现有约束下可行。倒排出现不可能日期时直接指出冲突，比较缩范围、增资源、分阶段交付等选项。

复盘用证据更新完成状态；写了方案、开了会议不能自动标成已交付。将已发生问题与未来风险分开，风险记录触发条件、影响、应对、责任和复查点。范围变更说明对既定日期与依赖的影响，不能同时默认范围增加、资源不变、日期不变。

交付与当前任务相称的里程碑表、依赖图、风险/待决事项或进度备忘。逐项检查责任与验收是否闭合、时间是否矛盾、阻塞项是否可见。只做简短追问时更新受影响部分。在线文档或项目操作以当前授权工具为准，计划建议不代表已创建任务、通知团队或自动持续监控。
