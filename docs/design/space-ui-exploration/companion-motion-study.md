## 观看方式

- 顶部可直接选择 13 种动作；其中待机、思考、工作、等待确认、完成是任务流程的五种核心状态。
- 「播放流程」依次展示前四种状态，停在等待确认。主区的「示例确认」才会进入完成；不会自动批准。
- 左下角是实际停靠位置，点击可以打开或收起伴侣详情。右侧观察区与左侧共用同一帧，支持坐姿基准 40 / 64 / 120 px、慢放、暂停、时间轴、逐帧和重播。
- 保留项目切换、各会话草稿、深浅主题和原有设置预览。伴侣的示例状态分别保存在当前页面的各会话中。
- 「减少动画」或系统减少动画偏好会停止运动；「极简材质」也提供静态观察。无声音、自动弹窗或主区漂移动画。

## 实现边界

上一版 v3 只有五张关键姿态底图和细小网格形变。用户指出运动不可感知、丰富度低于旧宠物，这个评审成立。旧第一套有待机/思考/嗅探/成功各 6 张图片与 24 张步态；第二套每朝向 63 个素材格、9 类行为。旧模块 `companion-motion.js` 留作被否定的实验记录，工作区已改用 `companion-rig.js`。

v4 用内置 imagegen 按已选角色生成完整、可重叠的分层素材，再以 Canvas 2D 绘制头、眼、双耳、身体、尾巴与四肢。上臂/前臂/脚掌分开，四肢通过两段骨骼求解。状态切换用约 0.48 秒姿态插值，不再淡化两只整狗。所有运动连续求值，体态、脚掌、眨眼和耳尾具有不同节奏。

它是分层骨骼动画样稿，不是逐帧手绘动画。60 次/秒绘制不等于有 60 张手绘源图。近距离仍能看出分层关节、侧向腿部与身体遮挡的妥协；正式美术仍需评审这些细节，不能只凭自动检查称作最终动画质量。

素材：[角色部件](../assets/companion-dog-v4/rig-atlas.png)、[无项圈躯干](../assets/companion-dog-v4/torso.png)、[独立项圈](../assets/companion-dog-v4/collar.png)。生成方式为 imagegen 内置工具，完整提示词在 [部件提示词](../assets/companion-dog-v4/prompts.json)、[躯干提示词](../assets/companion-dog-v4/torso-prompt.json) 与 [项圈提示词](../assets/companion-dog-v4/collar-prompt.json)。原生成图片保留，项目引用副本位于该目录。

## 性能与验证

一只 256 × 256 缓冲区以最多 60 帧/秒绘制，实际尺寸和放大观察复用同一帧，无逐三角形纹理绘制。页面可见时持续播放，后台、暂停、减少动画与极简模式停止重绘，静态状态在操作改变时重绘一次。已移除上一版「失去焦点即停绘」的条件，避免侧边预览可见但不动。右侧可展开当前设备的测量，不能代替低配置设备验证。

`companion-rig.test.mjs` 检查 13 个动作各 30 秒/60 Hz 的数值、坐标边界与相邻帧位移，完成/回应的收束，以及步态的闭环与支撑阶段。这些检查不能替代视觉判断。

可用同一绘制器导出 PNG 序列：`node docs/design/space-ui-exploration/render-companion-frames.mjs`。动作片段与截图位于 `artifacts/companion-motion-v4/`。GIF 用 30 fps 导出，思考 144 帧、步态 57 帧、完成 72 帧，均来自同一分层动画求值；GIF 为评审循环播放，工作区中的完成只庆祝一次。正式代码、依赖清单和旧宠物资源均未替换。

## 本地启动

```powershell
python -m http.server 4181 --bind 127.0.0.1 --directory docs/design
```

打开 `http://127.0.0.1:4181/space-ui-exploration/companion-workspace.html?theme=dark`。该页面需要 HTTP 服务以加载模块。
