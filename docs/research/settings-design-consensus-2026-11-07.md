# Space 设置应该如何分类，才能更好找、看得清且不改变配置行为？

结论摘要：当前约束下，推荐“分组侧栏、直接进入具体对象”的结构：10 个主区入口，加底部“关于”。修正上一轮八页方案：MCP、技能、外部 Agent 直接可见；上下文压缩与运行限制单独归类；健康、迁移和诊断集中排障。此为三位子 Agent 独立研究、相互质疑后形成的设计建议，尚未实施，也未经过用户查找任务实验。

实施更新：用户批准后已完成源码重组，实际验证及全量测试限制见 [实施记录](settings-navigation-implementation-2026-11-07.md)。下文保留决策时的建议与待验收表述。

日期：2026-11-07。Space 设置研究基线为 `2e8bbd7e28b688a6fd5a9509140b828dce9fff56`，工作区另有工作模式开发；不把该并行开发中的临时状态作为新设置的产品要求。本轮只增加调研文档，不改产品代码、配置、IPC 或提交其他开发内容。

| 争议 | 反例与核对 | 最终取舍（设计判断） |
| --- | --- | --- |
| 八个入口是否更精简？ | “工具与集成”再含 MCP、技能、外部 Agent、插件、连接组件，减少的是首层文字，不是实际目的地；ZCode 将 MCP/技能作为可发现的独立入口 | 改为分组直达，避免为了八这个数字增加第二层导航 |
| 外部 Agent 是否与上下文放一起？ | 外部 Agent 已有注册、编辑、启停、移除、预检与一致性测试，不是压缩参数或 Workflow 预算；也不是仅一行状态 | 独立资源页，沿用现有能力门控；不可用时不显示一个永久空页 |
| MCP 内容浅，是否不该独立？ | 当前仅有配置来源、路径、数量与重载，并无完整服务器 CRUD | 保留可预测入口，做紧凑的“MCP 配置”页；不为了撑满页面新增管理功能 |
| 插件与连接组件能否合并？ | 都是安装物，但账号连接和当前会话授权是另外的业务动作 | 同页两个清晰分节；安装完成不能显示为账号已连接或会话已授权 |
| 安全页应不应该放在能力组？ | 现有页面对象是宿主沙箱后端、就绪状态、安装与诊断，不是 MCP/技能的会话权限 | 放“系统”，不新增一张全局权限表单 |
| 拆成多个页面能否直接提升性能？ | Runtime 的 refresh 同时取 overview、迁移计划，并同步压缩草稿；复制到新页会重复读取、可能重置编辑 | 按需首次挂载，复用必要读取，拆开迁移与表单同步；不复制整个 Runtime hook |
| 十一个入口是否会拥挤？ | 当前侧栏项最小高度及窄窗横向布局并非为多分组设计 | 接受可见入口增加，要求独立导航滚动、选中项可见、窄窗单层入口；视觉验证是实施完成条件 |

## 推荐导航与现有内容去向

分组标题只辅助扫描，不可点击、不产生空白落地页。主区没有第二排分类 tab。默认进入“常规”；关于固定在侧栏底部，窄窗也必须有可达入口。

| 组 | 入口 | 页面内容与边界 |
| --- | --- | --- |
| 应用 | 常规 | 语言、默认工作区、终端 shell、关闭行为、自动聚焦、系统通知；按应用行为、工作区与终端、通知分节 |
| 应用 | 外观 | 当前主题与视觉质量；保留有意义的预览 |
| 任务 | 模型与服务商 | Provider、凭据、端点、模型与默认项、现有连接测试；密钥存储说明放在凭据附近 |
| 任务 | 上下文与限制 | 上下文压缩、Workflow 运行限制；页头明确“上下文与运行限制”，不暗示人格、提示词或工作模式编辑 |
| 能力 | 外部 Agent | 当前注册、就绪状态、编辑/启停/移除、显式预检与测试；遵守能力门控 |
| 能力 | MCP | 标题“MCP 配置”；来源、用户/项目路径、服务器数量、现有重载操作；不暗示新增/编辑服务器能力 |
| 能力 | 技能 | 用户/当前项目技能路径、文件夹与 ZIP 安装，准确标明安装目标 |
| 能力 | 扩展与连接组件 | “Space 插件库”与“连接组件”两个分节，分别保留包安装/启用/卸载及组件安装/修复 |
| 系统 | 安全与沙箱 | 宿主沙箱就绪状态、现有 setup 操作、必要平台与后端说明 |
| 系统 | 故障排查 | 扩展/集成健康详情、Host 事实、配置路径与迁移、生效规则总览、诊断导出；常规资源配置全部迁出 |
| 底部 | 关于 | 版本与更新、许可证状态、许可证导入与请求导出；不把许可证伪装成账号 |

现有内容清单及来源见 [完整盘点](settings-information-architecture-comparison-2026-11-06.md#1-space-当前实际分配)。表格是迁移建议，不代表新增功能。外部 Agent 的可用性按现有状态决定，因此不是所有环境都必然显示完整十一项。

“故障排查”用健康摘要和用户可执行动作开头，路径、revision、后端细节按需展开；不再复刻一个重新命名的 Runtime 长页。资源本页可以显示自身状态及“查看排障详情”入口，详细维护信息只有一个主要归属。

## 视觉与交互规则

以下均为待实际页面验证的设计要求，沿用现有主题、色彩和材质系统：

1. **侧栏轻、内容清楚。** 短分组名、单行导航、统一图标，选中态保留现有克制的强调色。去掉无论在哪一页都显示的密钥安全底栏，将说明移至模型凭据附近。[当前底栏](../../apps/desktop/renderer/src/features/settings/SettingsModal.tsx#L269)。
2. **普通设置用行，资源用列表，预览才用卡片。** 标题与简短说明在左，开关/选择器在右；复杂编辑器另占完整区域。避免每个小开关都有大图标、整块卡片和大量留白。主题预览保持视觉表达，不将全部页面压成同一种模板。[当前偏好布局](../../apps/desktop/renderer/src/features/settings/SettingsModal.tsx#L524)、[实际截图](../../artifacts/settings-review/1-preferences.png)。
3. **页头与首屏对应。** 页头一句话说明能改什么；实际控件和可执行动作优先。技术字段、长安全说明、健康明细不抢占所有资源页首屏。[当前 Runtime 首屏](../../artifacts/settings-review/3-runtime.png)。
4. **保留必要点击面积。** 压缩装饰和分节空白，不靠缩小文字或点击目标塞进十一项。侧栏与内容独立滚动；键盘移动时选中项进入视口。短窗口可滚动找到全部入口，底部关于始终可达。
5. **窄窗只保留一层导航。** 沿用紧凑单层横向入口，分组文字可省略，但 MCP、技能等名称仍直接可见；关于包含在可达入口中。需适配现有 direct-child CSS，不增加第二条横向 tab 栏。[当前响应式规则](../../apps/desktop/renderer/src/workspace.css#L518)。
6. **不加统一“保存所有设置”。** 即时偏好、显式保存表单、导入、重载各用原有动作；保存失败保留输入。关于页先展示版本/更新及许可证关键状态，离线授权细节可展开。

模型页第一阶段保留现有能力及筛选，先改善层级与主要操作位置；不把重排扩大为新的模型管理系统。若后续重做列表/详情交互，另行验证现有草稿与保存行为。

## 作用域和生效规则是字段信息，不是全局开关

不能因为页头有“当前项目”就把所有写入称为项目级。压缩参数实际保存到共享 KodaX 配置，`projectRoot` 用于返回项目相关 overview；MCP 展示用户与项目来源，技能安装才确实有用户/项目目标。[写入实现](../../apps/desktop/electron/kodax/user-config.ts#L311)、[IPC](../../apps/desktop/electron/ipc/settings.ts#L152)、[资源展示](../../apps/desktop/renderer/src/features/settings/SettingsModal.tsx#L1384)。

推荐在相关字段附近标识真实范围及生效时间，例如应用偏好、共享 KodaX 配置、安装到当前项目；不在每页顶部安装一个事实上不支持的“全局/项目”切换器。通用生效规则保留在排障，重要字段旁显示对应简短说明。

当前会话内权限及 reasoning effort 操作还会记住后续默认，不能在重排文案中承诺“只影响当前会话”。本轮也不从遗留 schema 推导新的默认模式/权限控件。[权限操作](../../apps/desktop/renderer/src/shell/ModeSelector.tsx#L191)、[effort 操作](../../apps/desktop/renderer/src/shell/ModelEffortSelector.tsx#L269)。详细对象、连接与授权边界见 [领域笔记](settings-review-domain-2026-11-07.md)。

## 性能、token 与最小实施边界

- **不引入模型调用。** 导航、筛选、作用域说明均使用本地元数据与现有状态；若未来加设置搜索，只检索本地标题/说明/别名。不把设置目录、搜索过程或新说明注入会话上下文，因此方案不增加聊天 token。现有用户主动测试动作仍明确触发，不在打开页面时自动执行。
- **首次访问才挂载，访问后保留。** 保留范围是本次设置打开期间；关闭设置原本会卸载，不能宣称关闭后保留草稿。隐藏已访问页面不重复挂载；必要的安装任务继续工作，昂贵的可见性刷新只在对应页活跃时执行。[当前全部挂载](../../apps/desktop/renderer/src/features/settings/SettingsModal.tsx#L300)。
- **共享必要读取，分离副作用。** 原 Runtime overview 按实际需要复用；迁移计划只在排障相关任务读取。刷新 MCP 或切分类不得覆盖尚未保存的压缩输入；表单在初始化、目标切换的明确策略、成功保存后同步。项目切换时不能把旧项目请求结果或安装目标带入新项目。[当前同步](../../apps/desktop/renderer/src/features/settings/SettingsModal.tsx#L855)。
- **按新增成本验收。** 统计打开设置额外产生的请求；Shell 原本已有的扩展 catalog 应复用，不算作设置懒加载失败，也不能另建一套读取。[现有 catalog 复用](../../apps/desktop/renderer/src/features/extensions/SpaceExtensionsProvider.tsx#L60)。
- **保持旧入口。** `preferences→常规`、`providers→模型与服务商`、`runtime→上下文与限制`、`extensions→扩展与连接组件`、`diagnostics→故障排查/诊断导出`、`license→关于/许可证`。旧 runtime 是宽泛入口，无法无损代表所有新页，选择稳定默认；具体故障入口显式定位排障。
- **区分内部页面与外部兼容标识。** Shell 与设置内部使用新页面标识同步，旧 key 在边界解析；不能把 MCP 选择回传成 runtime 再触发 initialTab effect 跳回默认页。自动化协议、观察结果和调用目录的现有不一致必须盘点并保持兼容，不借重排扩张接口。详见 [工程笔记](settings-review-engineering-2026-11-07.md)。
- **不用注册框架扩大改动。** 沿用小型静态导航数据和现有组件组合；不新增插件化设置平台、全局配置抽象或新后端接口。

先完成分类搬迁、控件层级、作用域文案、状态保持与入口兼容，再决定是否有必要增加全文设置搜索或更复杂的资源管理。搜索不能用来补救不清楚的分类。

## 实施前后如何验证

本轮是调研，没有产品代码变更，不以跑测试替代方案验证。实施时至少验收：

| 维度 | 可观察的通过条件 |
| --- | --- |
| 查找 | 从设置打开后可直接定位模型、MCP、技能、压缩、诊断导出和许可证，不依赖猜测 Runtime |
| 分类完整性 | 现有清单每项均有归属；没有新增虚构的管理、权限或项目写入能力 |
| 视觉 | 浅/深色、现有视觉质量档、1440×960、短高窗口及 ≤650px 宽度下入口/控件可达，没有双重分类栏或横向溢出 |
| 键盘 | 现有快捷打开、Esc 返回、方向键/首尾项、焦点回到原位置可用；选中项滚入视口 |
| 草稿 | 压缩或凭据编辑后切页再回来仍保留；刷新其他资源不覆盖；保存失败保留输入 |
| 性能 | 开常规页不触发未访问资源页读取/迁移计划；切页不重复初始化；隐藏页无新增非必要轮询；安装任务不被误中断 |
| 作用域 | 共享压缩写入、用户/项目技能安装、项目切换均保持现有正确目标；页面文案如实对应 |
| 兼容 | 六个旧设置入口、错误跳转、Shell 状态及自动化观察均稳定；MCP 不因旧 runtime 回写而跳页 |
| token | 打开/切换/本地筛选没有模型请求，不修改会话提示词或附加资源说明；现有显式测试例外不自动运行 |

以上是设计验收目标，尚不是已测结果。任务查找速度与十一入口的实际视觉密度需要原型或真实实现验证，不能仅凭源码宣称全局最优。

## 未证实与未解问题

- 用户对 MCP/技能等任务的实际访问频率没有遥测或访谈依据；直接入口是基于明确术语和现有对象边界的选择。
- 尚未验证重组后的布局、所有分辨率、读屏和保存流程。既有截图只证明当前布局问题，不证明新布局已通过。
- 外部 Agent 在不同 SDK/能力状态下的可用性须沿用运行态；未知状态下不应先闪现再消失，也不应为了决定导航而执行重型预检。
- “上下文与限制”的最终本地化文字可在真实侧栏中微调，归属不受此影响。

本报告取代上一轮比较笔记中的八页导航建议；原笔记仍保留为研究过程和源码证据。
