## 九种姿态与动作制作方向

姿态表按大图从左到右、从上到下排列。表中时长/帧数只是后续动画制作起点，本轮尚未制作或验证。

| 状态     | 关键姿态             | 后续动作                          | 建议节奏                      |
| -------- | -------------------- | --------------------------------- | ----------------------------- |
| 待机     | 坐姿，双前爪落地     | 呼吸、偶尔眨眼，小幅尾巴动作      | 低频待机，不连续吸睛          |
| 回应     | 抬头、轻微侧头       | 从待机抬头，尾巴回应一次再归位    | 约 0.6–0.9 秒的一次性动作     |
| 思考     | 坐着侧头、向上看     | 很小的头部/耳根调整，保持身体稳定 | 轻缓，状态文字解释任务        |
| 工作     | 四爪站立，身体前倾   | 进入工作姿态，少量耳朵/尾部动作   | 与思考状态靠体态区分          |
| 等你确认 | 坐直，轻抬一只前爪   | 从坐姿抬爪后停留，收到回应后落爪  | 一次进入，不反复挥爪催促      |
| 需要检查 | 低头回看、轻微疑问   | 注意力转向提示文字，随后保持安静  | 无哭泣、恐慌和反复跳动        |
| 阶段完成 | 坐高、轻微张嘴与抬尾 | 小幅挺身与摇尾，然后回待机        | 约 0.8–1.2 秒，一次结束       |
| 小步移动 | 自然的四足中间步态   | 前后腿交替的完整步态循环          | 需补至少 8 个一致步态帧再评估 |
| 休息     | 蜷卧、头枕前爪       | 坐下到卧下的过渡，闭眼与轻呼吸    | 仅无任务或显式休息状态        |

## 为什么需要新动作源

旧侧面插画与剪影在头部转向、耳朵、表情和身体姿态上约束较多。本轮先提供不同姿态作为完整角色，而非把一张狗图的可见像素切开后硬掰；后续每个大动作都需要连续源帧或真正含隐藏重叠区域的分层源文件。

新造型在浅色与深色页面、32 px 等待姿态及 56 px 姿态列表中做了浏览器查看。小尺寸下前倾工作、抬爪和蜷卧的体态有明显区别；思考与需要检查的眉眼差异仍然细小，必须结合文字，不能声称仅凭宠物就能准确辨认所有状态。

## 动画交付仍需完成

1. 确认最终角色造型，再锁定头身比例、毛色区块、耳朵长度、项圈和眼鼻位置。
2. 同一动作补齐连续帧：待机闭环；回应/抬爪/完成含进入、停留、返回；步态完整闭环。
3. 统一相机、主体尺度、脚底基线、重心与动作位移。当前九姿态生成图并非严格校准的 sprite atlas，不能直接按等分网格播放；评审页已经按实际主体边界取景，避免相邻姿态串入。
4. 检查透明边缘杂点、姿态间身份漂移、腿数与遮挡、32–40 px 的轮廓、深浅背景、循环接缝和状态打断时的过渡。
5. 把所有动作接到任务伴侣的真实状态和降级策略，极简用静态，减少动画时停止，后台/不可见时暂停。状态语义仍由文字与真实任务事实表达。

这些设计图没有通过骨骼、步态或帧间连续性验收。本轮评审页只切换静态姿态，未使用整张缩放/弹跳来冒充新的角色动画。
