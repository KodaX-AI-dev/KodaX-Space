## 动作内容

一段约7.9秒的完整动作：坐姿注意到任务卷 → 前倾起身 → 低头叼取 → 叼住短走两步 → 屈前肢趴下 → 前爪按住检查 → 抬头回应 → 鼻尖推开完成的卷轴 → 撑起坐回 → 约2秒休息。身体有坐、四足站立、行走、趴下和坐回的明显轮廓变化。

这是一段工作动作，不冒充覆盖原版所有随机玩法。原版巡视、玩球、舔爪等动作和输入反应均没有从正式产品删除；本次也没有将新增工作动画接入正式运行状态。

角色身份沿用原图的杏色毛、奶油色额纹与口鼻胸口、棕色垂耳、鼠尾草绿项圈和圆牌。完整身体运动允许项圈随身体移动，不再要求角色固定坐着或项圈在画布中逐像素不动。

## 原画与制片

使用内置 image_gen，原图和完整提示词见 [prompts.json](prompts.json)，所有使用的资产都已复制到本目录，generated_images 原文件保留。112张生成原画来自64格工作故事、16格起身、16格站立至趴下、16格趴下至坐起。运行图集使用其中88张完整角色原画及1张原 v6 中性帧；126个播放步骤包含有意的停顿，不能将播放步数当作原画数量。

原图画格并不严格等宽等高。`extract-cels.mjs` 识别完整角色及相邻道具，隔开接触的图列；`build-working.mjs` 统一整帧比例和脚底基线，编排全过程并打包小图集。只进行整帧配准与采样，没有拆分身体、运行时骨骼、双姿态淡化或扭曲补间。

首次原画有站立直接跳到趴下、趴下直接跳到坐姿的缺口，因此补了两段完整中间姿态。实际半速复看还发现 rise 第3格混入相邻卷轴碎片，已剔除；主表漏画卷轴的格子与缺少过渡的尾段不参与最终播放。

工作第一帧、休息及循环连接共用原 v6 中性帧。中途切状态先沿完整帧收束到中性，再进入目标状态；工作退出按24fps收束，最长约3.75秒，画面会显示正在收束。示例流程会完整播放工作段，然后停在等待确认，不自动批准。

## 性能对照

原版 `KodaXDogSpriteMascot.tsx` 使用两张864×672精灵图，按约155–260ms切帧，有间歇调度及后台/减少动画处理，因此本来就是轻量方案。两图合计378,718字节（约370KiB），像素RGBA估算合计约4.43MiB；这些数值由实际文件和尺寸读取。

新版也只裁切图集，不在运行时生成或计算身体形变。运行图格112×112，工作图集约415KiB、RGBA像素约4.59MiB，待机约4.21MiB；上一版待机22MiB的问题已通过独立预览的图集缩小解决。当前和待加载目标分别保留引用，切换后释放旧图集的JS引用；浏览器决定解码缓存及GPU资源实际何时回收。初次直接打开工作预览会短暂预载待机再进入工作，切换峰值像素约8.8MiB。全部状态源图不会一次性加载。

播放计时按当前源帧率调度，工作16fps。相同连续静帧合并到一次定时唤醒，休息段不逐帧绘制；暂停、减少动画、完成收住及document.hidden时无持续播放计时，恢复时重置时钟，避免后台时间导致动作跳过。没有常驻60Hz动画循环。DOM诊断一般最多4次/秒，阶段变化、暂停及结束及时更新。

最终浏览器录取后半段，两个画布单帧绘制提交耗时的滚动均值样本中位数约0.13–0.16ms，95分位约0.15–0.16ms。这只覆盖Canvas代码提交，切换首帧还有解码/纹理准备开销；截图录取也会影响负载。它不是整个应用的CPU/GPU占用、耗电或浏览器总内存基准，不能承诺所有机器与旧版完全相同。结论是图集像素和稳定播放开销仍在轻量级范围，动作更丰富不需要骨骼计算或重型特效。
