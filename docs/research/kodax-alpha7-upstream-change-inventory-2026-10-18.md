## 行为变更及 Space 的适配判断

### 1. 共享 Session 存储的 Host 归属与安全刷新

- profile 是连接名；共享 canonical Session 目录只有一个产品写入 owner。auto-start 会先对 canonical Session 目录持有 `startup.lock` 协调门，再发现 `.product-host/owner.lock` 真正指向的 daemon profile，使用其 token、endpoint 和身份连接；不会因请求了另一个 profile 就启动竞争 Host。目录正在被持有、descriptor 尚未发布时，在原 deadline/signal 内等待。[来源：[state.ts:742](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/runtime-daemon/state.ts#L742)、[sdk-runtime.ts:5811](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/sdk-runtime.ts#L5811)、[6352](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/sdk-runtime.ts#L6352)]
- bootstrap 中 peer 赢得 owner、或 probe/attach 之间 owner 改变时，先关闭临时 lease，再重新发现，最多沿用原有两次启动重试预算及原 deadline；不会重放已被接受的 input 或 tool work。新诊断 `runtime.daemon.storage-owner` 带 requestedProfile、ownerProfile、runtimeId、pid；无法 attach 的共享 owner 错误以 `session_storage_owned` 和 retryable 标识。[来源：[sdk-runtime.ts:6389](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/sdk-runtime.ts#L6389)、[6495](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/sdk-runtime.ts#L6495)、[6655](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/sdk-runtime.ts#L6655)]
- compatible Host 直接复用；自动刷新除了已证明更旧的 Host/同安装 build 改变，只额外允许同版本、同 build 的 `daemonOrphanExit` 策略刷新。仍要 preflight 无活动工作、精确 owner 身份、shared owner fence、一致的 launcher build、真实进程退出验证，受阻发 `runtime.daemon.upgrade-blocked` 结构化诊断。[来源：[sdk-runtime.ts:6152](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/sdk-runtime.ts#L6152)]
- **Space 需要核对**：启动器不要在 SDK 之外建立第二套共享存储 owner 逻辑；不要把实际返回 profile 与 requested profile 不同直接视为错误；重试限制在安全的连接/初始化阶段，保持 input/tool 的一次性语义。这是根据上述上游契约作出的集成要求，不是已完成的 Space 验证。[来源：同上三处启动/归属实现]

### 2. 启动 deadline、取消、可重试错误

- 一个原始 startup deadline 穿过协调门、owner 发现、spawn、readiness、socket connect、authenticated initialize、最终同步 owner/build 校验；过期后不得通过 `Math.max(1,...)` 重新获得启动预算，也不得再开临时 attachment。socket connect 和 Windows supervisor readiness 观察原 AbortSignal，关闭仍走既有 cleanup。[来源：[sdk-runtime.ts:6243](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/sdk-runtime.ts#L6243)、[6276](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/sdk-runtime.ts#L6276)、[6647](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/sdk-runtime.ts#L6647)、[process.ts:502](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/runtime-daemon/process.ts#L502)、[windows-job-supervisor.ts:603](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/runtime-daemon/windows-job-supervisor.ts#L603)]
- `daemon_startup_failed` 增加结构化 `reason`；`timeout`、`unhealthy` 可重试，`cancelled`、`child_exit`、`identity_mismatch` 不由该实现标记可重试。socket 连接超时为 `code='ETIMEDOUT'`，**没有**额外 `retryable` 字段。upgrade error 默认只有 `preflight.canStop===false` 才 retryable；inspection interrupted 子类强制 retryable。协调门超时等部分 upgrade error 仍为 false。[来源：[process.ts:311](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/runtime-daemon/process.ts#L311)、[transport.ts:640](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/runtime-daemon/transport.ts#L640)、[sdk-runtime.ts:482](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/sdk-runtime.ts#L482)、[5828](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/sdk-runtime.ts#L5828)、[6145](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/sdk-runtime.ts#L6145)]
- health 先完成认证和 OS 身份检查，再对同一个精确 owner 刷新 `starting→ready` 状态；不能把 owner/PID generation 变化当作 readiness 提升。[来源：[lifecycle.ts:70](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/runtime-daemon/lifecycle.ts#L70)]
- **Space 需要核对**：IPC 错误转换应保留 code、reason、retryable、ownerProfile、preflight；不能只看 `retryable` 而漏掉 `ETIMEDOUT`，也不能把所有 upgrade error 无限重试。SDK 的 end-to-end deadline/cancel 修复由升级继承，不应在 Space 靠增大 timeout 来覆盖失效路径。[来源：上述错误实现和 deadline 实现；Space 结论为集成推导]

### 3. idle Host 生命周期与显式服务保留

- 普通产品 CLI 使用 `daemonLifecycle:'interactive'`，新 Host 默认 **30 秒持续空闲**退出；无 lifecycle/idle 选项的 SDK 启动仍默认持久。`interactive` 会复用兼容 persistent Host，不主动改掉其策略；显式 `daemonOrphanExitMs` / `requirements.daemonOrphanExit` 则继续要求启用 idle capability。`persistent + daemonOrphanExitMs` 是无效组合。[来源：[sdk-runtime.ts:6335](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/sdk-runtime.ts#L6335)、[kodax_cli.ts:4642](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/kodax_cli.ts#L4642)、[embedder-guide.md:4964](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/public_docs/sdk/embedder-guide.md#L4964)]
- `daemon start` 通过 authenticated logical client 且 `daemon:admin` scope 在原 Host 上保留持久意图，不需要重启；A2A service 的保留来自 Host 的真实 `keepAlive`。initialize 返回 `daemonLifecycle` 和 `daemonRetention:'explicit'|'service'` 元数据；persistent Host 不再宣告 active orphan-exit capability。probe/startup 观察连接不能更改保留意图。[来源：[server.ts:629](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/runtime-daemon/server.ts#L629)、[1009](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/runtime-daemon/server.ts#L1009)、[management.ts:74](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/runtime-daemon/management.ts#L74)、[kodax_cli.ts:757](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/kodax_cli.ts#L757)]
- 显式 retained/A2A service 与强制 idle requirement 冲突时，在 shutdown 前拒绝。旧 Host 无可信 lifetime metadata 时保守持久；rebuild 刷新保留显式 persistent 意图，service 是否仍存在则由新 Host 配置重新判断。[来源：[sdk-runtime.ts:6548](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/sdk-runtime.ts#L6548)、[6628](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/sdk-runtime.ts#L6628)、[embedder-guide.md:4964](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/public_docs/sdk/embedder-guide.md#L4964)]
- idle 必须在无 client、无 active mutation、无 governed work、无 background maintenance 后持续满 grace。连接到来会取消进行中的 idle preflight；startup admission 暂时保留 Host，但首次真实 client 前不会触发 Session 历史扫描。memory review 与 managed-task maintenance 会阻止自动退出，包括 final draining 检查；显式 stop 仍按原取消/结算契约处理这些可选工作。[来源：[management.ts:92](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/runtime-daemon/management.ts#L92)、[229](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/runtime-daemon/management.ts#L229)、[283](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/runtime-daemon/management.ts#L283)、[sdk-runtime.ts:5419](https://github.com/icetomoyo/KodaX/blob/25fa6399ada6dae0493faa221eb82174eebb9ad6/src/sdk-runtime.ts#L5419)]
